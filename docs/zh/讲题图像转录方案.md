# 讲题图像转录

`geo-vision` 是 GeoTeacher 对宿主 `dshVision` 服务的适配层。它负责解析题库题的图片引用、构造不含答案和解析的任务上下文、调用宿主视觉服务，并把通用 `VisionResult` 映射为 `geo_solve` 使用的图像证据。图片读取、附件持久化、OCR、模型路由、缓存、重试与结果校验均由宿主负责。

## 调用链

```text
geo_solve(qid)
  └─ geoVision.extract(qid, { problem })
       ├─ kernel.imageRefs(qid)          解析题库图片引用
       ├─ 构造仅含材料、题干和选项的任务上下文
       ├─ dshVision.inspect({
       │    inputs,
       │    mode: "ocr",
       │    policy: { evidenceOnly: true, allowInference: false }
       │  })
       ├─ 按图片序号映射 observed / uncertain 证据
       └─ 返回 status、images、degraded、visionOk、markdown
```

`mode: "ocr"` 表示一次证据转录，不再触发“整体识别后追加 OCR”的串行调用。模型和 provider 的选择不属于 GeoTeacher 配置。

## 宿主前提

DSH 宿主必须在本预设挂载前发布名为 `dshVision` 的兼容服务：

- 必须提供 `inspect(options)`；
- 可选提供 `health()`；
- 在宿主侧配置模型、provider、凭据、附件、缓存和重试策略；
- 教师直接提供独立图片时，宿主应暴露 `vision_inspect`；纯文字扫描可暴露 `vision_ocr`。

若 `dshVision` 不可用，GeoTeacher 适配层保持禁用并明确返回降级状态，不伪装识别成功。

## 边界与保证

1. `geo_solve` 只向视觉服务发送材料、题干和选项，不发送标准答案或解析。
2. 适配层请求 `evidenceOnly: true` 和 `allowInference: false`，只映射 `observed` 与 `uncertain` 证据。
3. 不确定内容保留原始不确定性和原因，不补猜。
4. `/geo/vision/status` 和 `/geo/vision/toggle` 只控制 GeoTeacher 适配层，不修改宿主视觉配置。
5. 教师直接给出图片路径时，使用 `vision_inspect`；纯文字扫描可使用 `vision_ocr`。禁止用普通文件读取工具绕过视觉服务，也不得把图片直接交给当前主模型。

## 验收

- `/geo/vision/status` 能显示适配层状态和下游服务健康信息；
- 有图题返回非空证据，或返回带原因的明确降级结果；
- 独立图片按宿主视觉工具契约处理；
- 视觉结果不泄露标准答案或解析。
