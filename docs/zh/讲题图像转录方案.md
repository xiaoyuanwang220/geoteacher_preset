## 一、问题与目标

**问题**：本地真题库中大量题目（尤其综合题）内含图片（区域分布图、等压线图、统计图表、示意图、照片等，以 `![说明](相对路径)` 嵌入 md，路径指向 `../../../90_附件/题目图片/<省>/<年>/...png|webp`）。当前 `geo_solve` 只返回文字材料，`extractMaterial` 把图片行**整行丢弃**——DeepSeek（无视觉）解题时完全看不到图，涉图题只能靠题干猜。实测综合题组 30 个中 20+ 涉图，影响面大。

**目标**：在不改变"DeepSeek 是唯一解题推理者"的前提下，让涉图题解题**吃得到图的信息**——用视觉模型（Qwen3.6 Plus）把图的**像素信息结构化**成 `GeoVisionResult`（JSON/对象，含图类型/标签/图例/数值/空间关系/不确定度及图引用），内部按需渲染成 Markdown 注入 `geo_solve` 的材料作为给定事实，由 DeepSeek 独立完成审题→证据→知识→推理链→作答。结构化存储是为了**评测、缓存、多插件复用**的稳定基础。

**约束（用户明确的边界）**：
1. 视觉模型**只做"读图提取信息"，不做解题推理**——不输出答案、不做地理因果判断、不评价。
2. **DeepSeek 保持唯一解题推理者**。

## 三、总体架构（三层职责分离）

核心职责划分（本项目的关键设计决策）：
- **Qwen3.6 Plus**：视觉**模型 Provider**——只负责把图的像素"看见"并转成文本，不含任何解题逻辑。
- **`geoVision` 服务（底层业务 Service）**：真正执行"读图 → 结构化"的**内部业务服务**——读图字节、构造转录 prompt、调模型、缓存、过滤"推理污染"、降级。供**任何内部消费者**复用。
- **`geo_extract_images` 工具**：只把 `geoVision.extract(...)` **包装成 Agent 可调用的工具接口**——它解决"DeepSeek 主 Agent 是否要主动读图"这个决策问题，本身不含转录业务逻辑。
- **`geo_solve`（内部消费者）**：解题模块。若需要图信息，**直接调用底层的 `geoVision.extract(qid)`**（作为给定事实并入 material），**绝不绕经 `geo_extract_images` 这个 Agent 工具**。

```
题目 md（含 ![...](相对路径) 图引用）
        │  core.questionData()/imageRefs(qid) 解析出 imageRefs[]
        ▼
┌───────────────────────────────────────────────────────────┐
│  geoVision 服务（底层业务 Service，供内部复用）                  │
│  · geoVision.extract(qid): Promise<GeoVisionResult[]>        │
│    - core.imageRefs(qid) 拿空 imageRefs → fs.readBytes→base64 │
│    - ctx.llm.stream 调 Qwen3.6 Plus（视觉 Provider）          │
│        prompt：按 §五 schema，只转录 observed 事实             │
│           (observed/uncertain/inferred 显式标注)             │
│        - 只保留 observed+uncertain，丢弃 inferred            │
│        - 服务器端丢弃"推理污染"（inferred），失败降级            │
│    - 结构化缓存 key=imageHash+modelId+promptVersion+schema   │
│      存 GeoVisionResult JSON → outputs\visionCache\<key>.json │
│    - 每次调用写运行记录（provider/model/版本/cacheHit/耗时/状态）│
└───────────────────────────────────────────────────────────┘
      ▲                          ▲
      │ geoVision.extract(qid)   │ geoVision.extract(qid)（工具内调用同一底层）
      │ （内部消费者，直接调）       │
      ▼                          ▼
┌──────────────────────┐   ┌──────────────────────────────────┐
│ geo_solve             │   │ geo_extract_images 工具（薄壳）     │
│ 解题模块（业务消费者）   │   │ → 暴露给 DeepSeek 主 Agent          │
│ GeoVisionResult→渲染    │   │ → 解决"Agent 是否要主动读图"         │
│ → material(Markdown)   │   │ → 内部仅调 geoVision，不含业务逻辑  │
│ → DeepSeek 解题        │   │                                   │
└──────────────────────┘   └──────────────────────────────────┘
```

**关键点**：
1. `geoVision` 是**唯一**执行"读图 → 结构化"的 Service，`geo_extract_images` 与 `geo_solve` 都是它的消费者（一个对外暴露成 Agent 工具，一个内部解题时自动取图）——避免"Agent 工具层"与"内部业务服务层"混淆，调用链清晰、可测、可复用。
2. 若以后出现"某个内部模块也要图信息"，它直接调 `geoVision.extract(qid)`，不碰工具层；工具层只负责把同一能力开放给 Agent 做显式决策。
3. **内部以 `GeoVisionResult`（JSON/对象）为准**；Markdown 是"按需渲染"的产物，供 DeepSeek 阅读，不作为存储/传输主载体。这样评测、缓存、其它插件复用都基于稳定 schema。
4. 图像转录仍是**独立、可选、可缓存**的预处理层，插在 `questionData` 与 `solutionScaffold` 之间。它只拿到图片（不拿设问/答案），从结构上不可能"泄题式推理"。

## 四、功能组成与放置（三层）

| 层 | 位置 | 职责 |
| :-- | :-- | :-- |
| **core** | `plugins/core/index.js` | 新增 `imageRefs(qid)`：解析该题 md 中 `![...](rel)` 为**绝对路径数组**（供 geoVision 使用） |
| **`geoVision` 服务（底层业务 Service）** | 新插件 `plugins/vision/index.js` | `ctx.provide('geoVision', api)`，核心方法 `async extract(qid): Promise<GeoVisionResult[]>`：读图字节 → 调 Qwen3.6 Plus 按 §五 schema 产出结构化对象 → `observed/uncertain` 保留、`inferred` 丢弃 → 结构化缓存 + 运行记录 → 降级。**不含工具外壳、不含解题逻辑；返回 JSON/对象，非文本** |
| **`geo_extract_images`（Agent 工具薄壳）** | 同 `plugins/vision/index.js` | `ctx.tools.register`；`execute` **仅调 `geoVision.extract(qid)`** 并把 `GeoVisionResult[]`（可渲染为 Markdown）回给 Agent。解决"Agent 是否要主动读图"。**不含转录业务逻辑** |
| **`geo_solve`（内部消费者）** | `plugins/analysis/index.js` | 解题时若涉图且 `vision.enabled`，**直接调 `geoVision.extract(qid)`**，把 `GeoVisionResult[]` 渲染成 Markdown 并入 material。**不绕经 `geo_extract_images` 工具** |
| **配置** | vision 插件 config（或 core config） | `vision.enabled`（默认关）、`provider`、`model`（Qwen3.6 Plus）、`promptVersion`、`schemaVersion`、缓存目录 `outputs\visionCache`、日志目录 |

**依赖注入**：`plugins/vision` 插件 `inject: ['fs','llm','tools','geoKernel']`（`fs` 读图、`llm` 调模型、`tools` 注册工具薄壳、`geoKernel` 取 `imageRefs`），`ctx.provide('geoVision', api)`；`plugins/analysis` 的 `geo_solve` 若要自动带图，`inject` 增加可选 `geoVision`（`ctx.get('geoVision')`，处理缺失——若 vision 插件未挂载则跳过，不影响纯文字题）。

> 放独立 `plugins/vision` 而非塞进 analysis：图像转录与解题（P1–P3）解耦，可单独开关、单独演进、不影响 analysis 现有回归。需在 `agent.cordis.yml` 的 geo group 下加一行 `geo-vision`（消费同组 geoKernel；`geoVision` 服务与 `geoKernel` 同置 isolate realm，供同组插件消费）。

## 五、结构化结果 schema（GeoVisionResult）

**内部永远保存 JSON/对象，不直接以 `imageMarkdown` 为存储/传输主载体**。Markdown 只在喂给 DeepSeek 时按需渲染。这样评测、缓存、其它插件复用都基于稳定 schema。

### 5.1 顶层：生产视图 GeoVisionResult（geoVision.extract 的返回）

> 视觉模型**不直接输出它**。`geoVision` 收到的是 Qwen 返回的 JSON（见 §5.8/5.9），经 **schema validation + 边界清洗** 后组装成下列**生产视图**；每个元素 = 一道题的一张图。`inferred` 在此被丢弃（见 §5.3），原始输出另存 raw log（见 §5.6）。

```ts
type GeoVisionResult = {          // 生产视图：geoVision.extract(qid) 返回的数组元素
  imageId: string;                // 稳定的图引用键，如 "fig_1"、"图5"、"shared_01"
  caption: string;                // 图注/说明（md 里的 ![caption](...)）
  sourcePath: string;             // 图片绝对路径
  imageType: 'region' | 'isoline' | 'chart' | 'schematic' | 'photo' | 'unknown';
  contentType: string;            // image/png | image/webp ...
  // —— 观察事实（显式边界，见 §5.3）——
  observed: ObservedItem[];       // 模型"亲眼所见"，保留
  uncertain: UncertainItem[];     // 模型"较不确定"（字迹模糊/遮挡/数值难辨等），保留并降置信
  // inferred 已在此丢弃，不在生产视图（原始已写入 raw log，见 §5.6）
  uncertainties: string[];        // 汇总不确定点（脱敏，供 DeepSeek 知道哪些不可靠）
}
```

### 5.2 元素项（observed / uncertain 共用结构）

```ts
type ObservedItem = {
  field: 'label' | 'legend' | 'numeric' | 'symbol' | 'line' | 'annotation' | 'spatial' | 'other';
  text: string;                   // 转录内容（数值/图例项/注记/描述）
  unit?: string;                  // 单位（hPa/℃/m/° 等），numeric 时有效
  modelConfidence: number;        // 0–1，仅"模型自评"，非真值/校准概率
  valueRaw?: string;              // 数值类保留原始读取串，便于评测核对
};
// labels: ObservedItem[]（全部 label 类）
// legend: ObservedItem[]（图例项）
// numericValues: ObservedItem[]（numeric）
// spatialRelations: ObservedItem[]（spatial，如 "湘潭位于长沙西南"）

// UncertainItem = ObservedItem & { reason: string }   // 附加"不确定原因"
```

> **`modelConfidence` 语义限定**：它只是 Qwen 对"我自己读这条是否可信"的自评分（0–1），**不代表经过验证的正确概率**。系统不得用它当校准置信、不得作为是否采纳的依据阈值来"自动通过/拒绝"；仅用作评测时的参考信号，并由后续评测（§八 V2）核实其与实际正确性的相关性。

即每个 `GeoVisionResult` 内含若干字段便于程序取用：`labels`、`legend`、`numericValues`、`spatialRelations`（从上表 `observed` 按 `field` 分桶）。`uncertain` 单独给低置信项（结构同 `ObservedItem`，另加 `reason`）。

### 5.3 观察/推断显式边界（关键强化）

**不靠"因为/说明/故选"等关键词过滤**（易漏隐性推理），而是要求 Qwen **在每一条转录上显式标注信任类别**，系统按类别决策：

```
每条输出字段：category ∈ { observed, uncertain, inferred }；modelConfidence ∈ 0–1（仅模型自评）
  observed   : 图中明确可见、可核对的（数值/图例/符号/位置/形状）
  uncertain  : 图中可见但难以确读的（模糊/遮挡/压线/字号小/反光），须附 reason
  inferred   : 你对图的理解/推断/结论（如"这是高压中心"→应记为位置观察；因果、优劣、
               "说明…""可能是…""相比…更" 等全部归此）
```

**处理规则**：`observed` + `uncertain` → 保留进**生产 `GeoVisionResult`**；**`inferred` → 不进入生产视图、不渲染给 DeepSeek**。但 Qwen 的**原始完整输出**（含 `inferred` 与全部 `modelConfidence`）会原样写入 **raw log**（见 §5.6），供评测分析（如幻觉率、"模型想推什么"）。`inferred` 的存在是为了让模型有机会"自述哪条它拿不准/推的"，而不是当作可用信息。
> 渲染给 DeepSeek 时，`uncertain` 项前面标 `【不确定】` 并附原因，`observed` 项直接给；两者都不下结论。

### 5.4 图引用（imageId / caption / sourcePath）

- 一道综合题常见**多图、多小问**，必须让 DeepSeek 明确知道引的是哪张图，**不要把多图转录混成一段**。
- `imageId` 规则（V1 简化）：按 md 中出现顺序编号 `fig_1/fig_2/…`；若 md 图文注里已有编号（如"图1/图5"或 `__01/__02` 后缀），优先沿用该号作为 `caption` 与 `imageId` 的别名。
- 渲染 Markdown 时**逐图分段**，每段开头带 `【图 fig_1 · 图注】`，使 DeepSeek 在破题/采分点里能写"据图 fig_1 的 XX 数值"。

### 5.5 结构化缓存 key

**缓存 key 统一为图片内容哈希**（便于按图定位、跨题复用同一张图）：

```
cacheKey = imageHash        // 图片文件内容的 SHA-256（同一张图在所有题/缓存中一个 key）
```

- **按图复用**：同一张图（如"共用材料图"）在多个题组出现时共用同一缓存，避免重复提取。
- **换模型/改 prompt 后的失效，用"关联索引"解决（而非改变 cacheKey）**：每个 `imageHash` 下保存 `cacheIndex.json`，记录生成该结果的 `modelId/promptVersion/schemaVersion/ts`。读取时比对当前配置——若与索引记录不符，视为**过期**、重新提取并覆盖索引；记录同时保留旧 raw log 便于溯源。
- 存 `GeoVisionResult` JSON → `outputs\visionCache\<imageHash>.json`；索引 `outputs\visionCache\<imageHash>.index.json`。

> 这样 cacheKey 精简稳定（就是 imageHash），同时不丢失"换模型/改 prompt 不用旧缓存"的正确性——因为失效判定由索引元数据完成，而非靠 key 字段拼接。

### 5.6 视觉调用运行记录（可复现）

每次对单张图的实际视觉调用（或不命中缓存的提取）写一条结构化日志，存 `outputs\visionCache\runs\*.jsonl`：

```ts
type VisionRun = {
  ts: string;              // 时间
  imageId: string;
  sourcePath: string;
  provider: string;        // 实际 provider 路由名
  model: string;           // 实际模型 id（如 Qwen3.6 Plus）
  promptVersion: string;
  schemaVersion: string;
  cacheHit: boolean;       // 是否命中缓存（命中时无模型调用）
  durationMs: number;      // 模型调用耗时
  status: 'success' | 'failed' | 'degraded';
  error? : string;         // 失败原因（含 schema validation 失败原因）
  schemaOk: boolean;       // Qwen 返回 JSON 是否通过 schema validation
  resultSummary?: string;  // 成功时摘要（如 observed/uncertain/inferred 条数）
  rawOutput?: string;      // Qwen 原始输出（JSON 全文，含 inferred 与全部 modelConfidence），仅日志保留、不进入生产视图
}
```

- **`rawOutput` 是评测与溯源的关键**：Qwen 的原始 JSON（含 `inferred` 项与 `modelConfidence`）随 run 记录完整落盘（`runs\*.jsonl` 或配对的 `runs\raw\*.json`），但**不进生产 `GeoVisionResult`**。这样既满足"生产丢弃 inferred、不渲染给 DeepSeek"，又能事后评测幻觉率、分类准确率、"模型想推什么"。
- **schema validation**：Qwen 返回先按 §5.9 JSON schema 校验；不合格则该条记为 `schemaOk:false`（可触发一次重试或降级），校验通过项才进入生产视图。

用途：一道题识别异常时，能复现"当时用了哪个模型、哪版 prompt、是否缓存、耗时、成败、原始输出"。

### 5.7 图类型 router（V1 留接口，不做复杂）

- `imageType` 是 `GeoVisionResult` 的稳定字段（`region/isoline/chart/schematic/photo/unknown`），但 **V1 先用统一 prompt**，不按类型切换提取模板。
- 预留接口：`typeRouter: (imageId, caption, sourcePath, previewHints) => imageType` ——V1 用文件名/图注启发式粗判，仅做分类标注；后续（V3）再按 `imageType` 选不同提取模板与字段约束。

### 5.8 转录 prompt（V1 统一，要求 Qwen 直接输出 JSON）

要求 Qwen **直接返回符合 §5.9 schema 的 JSON**（数组），不做自由文本。每一条含 `category/field/modelConfidence`，`field`、`category` 均取自枚举：

```
你是一个"图像转录器"。看图后直接返回一个 JSON 数组，不要自由文本、不要 markdown 代码块。
每个元素：{ "category": "...", "field": "...", "text": "...", "unit": "（可选）", "modelConfidence": 0.0~1.0, "reason": "（仅 uncertain 必填）" }
- field ∈ { label, legend, numeric, symbol, line, annotation, spatial, other }
- category ∈ { observed, uncertain, inferred }
    observed   : 明确可见可核对
    uncertain  : 难以确读（模糊/遮挡/压线/字号小），须填 reason
    inferred   : 你的推断/结论（因果、优劣、"说明…""可能…""更…"）
只转录 坐标/数值/图例/符号/线型/图斑/注记/空间关系；不回答任何设问。
inferred 项也要照常给出（以便系统识别并丢弃）。
modelConfidence 只是你对自己这条转录可信度的自评，0–1。
```

> 注：让模型连 `inferred` 也输出，是为了让"边界"显式化——系统据此丢弃，且能看清模型"想推什么"（利于评测幻觉率），而不是靠猜词拦截。

### 5.9 JSON schema（Qwen 输出校验 + 生产视图组装的输入）

`geoVision` 用该 schema（`schemaVersion` 与之绑定）对 Qwen 返回做 **schema validation**：

```
GeoVisionRaw = {                       // Qwen 一次返回的原始 JSON（每图一条）
  imageType?: 'region'|'isoline'|'chart'|'schematic'|'photo'|'unknown';
  items: Array<{
    category: 'observed'|'uncertain'|'inferred';
    field:    'label'|'legend'|'numeric'|'symbol'|'line'|'annotation'|'spatial'|'other';
    text:     string;
    unit?:    string;
    modelConfidence?: number;           // 0–1，仅模型自评
    reason?:  string;                   // uncertain 必填
  }>;
}
```

组装到生产 `GeoVisionResult` 的规则：
1. 先过 schema validation；不合格 → `run.schemaOk=false`，触发一次重试或降级。
2. `category==='observed'` → `observed[]`（`modelConfidence` 原样带上）。
3. `category==='uncertain'` → `uncertain[]`（含 `reason`）。
4. `category==='inferred'` → **不进生产视图**；其内容仅留在 run 的 `rawOutput`（§5.6）供评测。
5. `imageType` 若为空/非法 → 由 §5.7 `typeRouter` 补判为 `unknown`。

## 六、与 DeepSeek 解题流水线的衔接

- `material`（文字题干/材料）与**渲染自 `GeoVisionResult` 的图转录 Markdown** 都只是**给定事实**；推理与结论一律由 DeepSeek 产出。
- **`geo_solve`（内部消费者）**在求返回 material 时，若该题涉图且 `vision.enabled`，**直接调 `geoVision.extract(qid)`**，把 `GeoVisionResult[]` 逐图渲染成 Markdown 并入 `material`（每图带 `【图 fig_x · 图注】` 段头 + observed/uncertain 标注），并注明"下列为图像转录证据，非结论"。**不调 `geo_extract_images` 工具**。
- **`geo_extract_images`（Agent 工具）**独立于 `geo_solve` 存在：当 DeepSeek 主 Agent **主动决定**要读某题的图时调用它（其 `execute` 内部调 `geoVision.extract(qid)`），返回 `GeoVisionResult[]`。该工具与 `geo_solve` 是否自动带图是**两个独立决策**，由调用方分别触发。
- **图引用约定**：多图题中，DeepSeek 破题/采分点时必须以 `fig_x` 指认所依据的图（如"据 fig_1 的数值…"），不引用则视为证据不明。
- `geo-solver.md` 技能补充约束：图转录是"转录证据"，`observed` 可直接引用、`【不确定】` 项不得当成确定事实、`inferred` 已被丢弃；数值/坐标优先引用转录值，但仍独立思考其在地理解题中的作用。

## 七、风险与缓解

| 风险 | 缓解 |
| :-- | :-- |
| Qwen 转录精度方差（等值线数值读错等） | `numericValues` 要求保留 `valueRaw` 原始读取串便于核对；prompt 要求数值逐项、must-read-from-figure；关键数值二次抽样；V2 纳入 P4 评测对读数准确性打分层打分 |
| Qwen"顺手推理"污染 | **结构化边界**：每条按 `observed/uncertain/inferred` 标注，系统只保留前两类、丢弃 `inferred`——不依赖"说明/因为/优于"等关键词漏检；同时保留 `inferred` 便于统计幻觉率 |
| 视觉模型误差被 DeepSeek 误当确定事实 | 渲染时 `uncertain` 标【不确定】并附原因；技能约束 DeepSeek 不得把其当确定事实 |
| 缓存误用（换模型/改 prompt 后旧缓存仍被用） | cacheKey 统一为 `imageHash`；用配套 `index.json` 记录生成时的 `modelId/promptVersion/schemaVersion`，读取时不一致即视为过期、重新提取并覆盖索引 |
| 异常难复现（当时用了哪个模型哪版 prompt） | 每次不命中缓存的调写真 run 记录（provider/model/promptVersion/cacheHit/耗时/成败/原因 + 原始 JSON rawOutput）到 `runs\*.jsonl` |
| Qwen 返回非标 JSON / schema 不合格 | 按 §5.9 schema validation；`schemaOk:false` 时记录 + 一次重试或降级；正常结果才进生产视图 |
| `modelConfidence` 被误当准确率使用 | 语义限定为"仅模型自评、非校准概率"，不得作为自动通过/拒绝的阈值；仅评测参考（见 §5.2） |
| 模型路由/模型 id 不符 | 实现第一步用 `ctx.llm.listProviders()`/`listModels(provider)` 实查 `Qwen3.6 Plus` 的确切 provider 名与是否 vision/支持 image 块 |
| 图损坏/读取失败/超时 | 降级为保留图注文字 + 标注"该题涉图但图像信息未提取"，DeepSeek 据此决定是否仍能解题，不静默 |
| 缓存膨胀 | `outputs\visionCache` 按 `imageHash` 命名（每图一个）；可设清理阈值、对未命中索引（过旧）的缓存优先清除 |
