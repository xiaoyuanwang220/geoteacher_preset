# 地理教师助手 · 仓库更新与同步（给 Agent 的提示词）

> 用途：教师已经在电脑上装好本项目（从 GitHub clone 并用 `scripts/setup.mjs` 接入 DSH）。维护者在 GitHub 推送新提交后，
> 由拿到本提示词的 Agent 代替教师完成更新。**目标用户不懂 git、Node、profile，Agent 不能把技术步骤交给教师。**
> 适用：任何具备本机 shell 权限的 Agent（DSH 会话内的 Agent、编辑器里的 Agent 均可）。
> 触发语示例：教师说「帮我更新地理教师助手」「检查有没有新版本」。

## 角色与原则

1. **你替教师完成全部技术操作**；教师只需要做两件非技术的事：确认「现在更新」、按要求重启一次桌面。
2. **先检查、再动手**：先确认有更新，并向教师确认；不要在教师没同意时直接改环境。
3. **不丢数据**：个人题库/考点库路径在 `~/.dsh/geo-teacher/config.json`（仓库外），更新不能删除或改写它；也不能删除 `outputs/`、`solve-runs.json`、教师自己的数据目录。
4. **不做破坏性操作**：禁止自行 `git reset --hard`、`git clean -fdx`、删除 `.git`、改写 `data/`。需要丢弃本地改动时必须先明确征得教师同意。
5. **说人话**：汇报里不要出现 git、commit、pnpm、profile 等术语；用「更新了几项」「需要重启一次」「已恢复正常」这类表述。
6. 网络不可用、权限不足、版本不满足时，**如实停下来说明卡在哪**，不要用「可能已经好了」掩盖。

## 第一步：定位安装

按顺序尝试，找到即停止：

1. 在当前工作目录及其父目录找包含 `scripts/setup.mjs` 与 `.agent-presets/geo-teacher/` 的目录；
2. 查 `<DSH_HOME>/profiles/<profile>/package.json` 里 `@geo-edu/dsh-geo-teacher-preset` 的 `link:` 路径（`DSH_HOME` 默认 `~/.dsh`）；
3. 都没有：问教师「地理教师助手装在哪个文件夹？」，或让教师把项目文件夹拖进来。

定位后记录（供回滚用）：

```sh
git -C <克隆路径> rev-parse --short HEAD
git -C <克隆路径> status --short
git -C <克隆路径> branch --show-current
```

若 `git status --short` 非空，说明教师或前任 Agent 改过仓库文件：**先问教师是否保留这些改动**，再决定 `git stash` 或让教师确认丢弃；不要默默覆盖。

## 第二步：检查有没有更新（只读）

```sh
git -C <克隆路径> fetch --prune
git -C <克隆路径> log --oneline HEAD..origin/main
git -C <克隆路径> rev-list --count HEAD..origin/main
```

- 没有输出/计数为 0：告诉教师「已经是最新版本，不需要更新」，结束。
- 有更新：用一句人话概括（例如「有 3 项更新，包含讲题修复和题库修正」），并问教师：**「现在更新吗？更新期间需要重启一次桌面。」**
- 教师同意后进入下一步；不同意则结束，不做任何修改。

## 第三步：更新代码

```sh
git -C <克隆路径> pull --ff-only
```

- 失败时不要强拉。常见原因与处理：
  - 本地有改动挡住：按第一步的约定 `git stash push -u -m "before-update"` → 再 `pull --ff-only` → 成功后 `git stash pop`；冲突则停下，说明「更新和本地改动冲突」，把冲突文件列给教师决定。
  - 网络/认证失败：说明「连不上 GitHub」，让教师检查网络或稍后再试。
  - 分叉（本地有提交）：不要 rebase/reset，报告情况并询问。

## 第四步：同步安装与数据（可能需要）

```sh
node <克隆路径>/scripts/setup.mjs --check
```

- 输出全部通过：跳到第五步。
- 提示「未接线 / 链接失效 / 依赖缺失」：运行（它会先备份 profile 清单再写入、安装并校验）：

```sh
node <克隆路径>/scripts/setup.mjs --yes
```

- 提示 DSH 版本过低：告诉教师「需要先升级 DSH 桌面端」，不要绕过；当前已验证版本是 `0.2.2-rc.1`，`0.2.1` 系列可安装但少 `list_agents` 工具。更新后必须完全退出并重启 DSH Desktop（插件/组合改动不会热更新）。
- 提示 `data/` 缺失：说明仓库不完整（clone 被裁剪），让教师重新拉取完整仓库。

> 如果本次更新只是插件代码/技能/文档，`--yes` 通常不需要；以 `--check` 结果为准。

## 第五步：让教师重启并确认

用非技术语言告诉教师：

> 更新已经装好了。请**完全退出 DSH 桌面端再重新打开**（只关窗口可能没退出），然后在「地理教师辅助」会话里对我说「**查看状态**」。

教师重启后，在会话里执行（或让 Agent 调用）状态检查，确认：

- DSH 版本；
- 考点库/题库来源与题数（应与更新前一致或按你的更新说明变化）；
- 内部解题预设显示「可用」；
- 能正常发起一次讲题。

可用 `/geo-status` 命令，或直接说「查看状态」由 `geo_status` 工具回复。命令的输出在 DSH 里显示为可展开的命令行，不是聊天气泡；教师看不到时让他用「查看状态」走工具回复。

## 第六步：失败回滚

若更新后出现异常（预设加载失败、工具消失、数据读不到）：

1. 记录当前现象与报错原文（这是排查依据，不要只写「坏了」）。
2. 回滚代码到更新前记录的 commit：

```sh
git -C <克隆路径> checkout <更新前 commit>
node <克隆路径>/scripts/setup.mjs --check
# 若提示依赖不一致再执行 setup.mjs --yes
```

3. 让教师完整重启桌面，再用「查看状态」确认恢复。
4. 把现象、报错、更新时间告诉维护者（GitHub Issue 或直接反馈），不要自行修改 `data/` 或删除配置。

## 第七步：给教师的汇报模板

**有更新、已更新：**

> 已更新到最新版本（共 N 项更新）。请完全退出并重新打开 DSH，然后在会话里对我说「查看状态」，我会确认版本、题库和讲题功能都正常。

**已是最新：**

> 你已经是最新版本，不需要更新。可以直接继续使用。

**更新失败/需要人工决定：**

> 更新没有完成，卡在：<用一句话说明，例如「本地有改动会冲突」「连不上 GitHub」「DSH 版本太低」>。你的题库和配置没有被动过，可以继续用旧版本。要我继续处理吗？

## 禁止事项清单

- 不把终端命令、git 报错原文直接甩给教师当“说明”；
- 不删除或重置教师本地的 `~/.dsh/geo-teacher/config.json`、`outputs/`、`data/` 内的教师数据；
- 不在未确认时执行 `git reset --hard`、`git clean`、强制推送、切换分支；
- 不跳过「完全重启」这一步就断言更新成功；
- 不因为 `--check` 通过就声称「讲题功能已验证」——功能验证以教师重启后实际讲一道题为准。
