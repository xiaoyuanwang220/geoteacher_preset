本项目**独立设计、独立实现**。检索开源项目是为了**校准思路、避免已知陷阱**，不是复用。

| 允许 | 禁止 |

## 一、问题陈述

插件解决的不是"模型做得更好"，而是**建模过程失去终止条件**。

| 优先级 | 痛点 | 项目证据 |
|---|---|---|
| **P1** | 验证太慢、每次全量重跑 | `水循环/design-qa.md` 迭代 1→5，每轮全量构建截图审查 |
| **P2** | 反复改版、永远不满意 | 冲积扇 Blockout `v01→v06`；`环流2` 与 `环流3` 并行重做 |
| **P3** | 改 A 坏 B | 冲积扇"拼接逆坡已在制作过程中修正"；水循环迭代 3 为修位置把已对齐坐标全部重设；迭代 4 需专门声明"未改变箭头/云朵/标签坐标" |

**新增问题（P0）**：用户看到三维模型后，**无法用文字说清要改哪个组件**。"那个箭头"指代不明，agent 只能猜，猜错就再来一轮——这是 P2 反复改版的直接成因之一。

`16测试/环流2/05_skill改进建议.md` 的结论：**缺的不是"要检查什么"，而是"怎么判断做到了"**。

## 四、组件注册表

### 4.1 为什么必须有它

用户点到的只是三维物体或 SVG 元素。要让 agent 能改，必须建立映射：

```
用户点中的东西 → 组件 ID → 代码位置（file:line）
```

如果模型是随手搭的、对象无稳定命名，点选只能拿到无意义内部 ID，agent 还是得猜——**功能就白做了**。

### 4.2 内容

`.modelcheck/components.json`，每条：

| 字段 | 说明 |
|---|---|
| `id` | 稳定标识，如 `nh-trade-winds` |
| `label` | 中文标签，如"北半球东北信风箭头" |
| `locator` | 源码定位：`file` + 配置键/符号名；`line` 只是当前版本的辅助提示，不作为身份 |
| `route` | `three` / `svg` / `dom` / `image` |
| `pick` | 点选钩子：Three.js 对象名 / CSS 选择器 / SVG id |
| `related` | 关联判据 id 列表 |
| `observables` | 可监测属性及单位，如世界坐标、方向、可见性、文案、材质参数 |
| `sharedDependencies` | 共享材质、父节点、布局规则等影响来源 |

### 4.3 建立方式（已确认：建模时注册）

- 建模时由 agent 按约定登记，并写进**开发文档**。
- 与你现有做法自洽：`AGENTS.md` 本就要求 `config.js` 集中管教学数据、元素用稳定 `id`/`data-role` 定位——**只是把它规范成"可点选的组件表"**。
- 模型需暴露一个**预览钩子**（Three.js 需要 `scene/camera/renderer`；SVG/DOM 走 `data-mc-id` 属性，无需钩子）。
- 点选钩子只解决身份识别；运行时取证另遵守第十七节。组件 ID 必须唯一，删除、重命名须记录迁移或失效；不可静默复用于不同对象。
- 图像路线：矢量叠加层按组件注册；底图内部对象只有在登记可点选区域后才支持定位。未登记区域不得声称能精确映射到独立源码组件。

## 五、契约 Contract

### 5.1 位置与生效边界

- 存于项目内 `.modelcheck/`，随项目走、可纳入 git。
- **没有契约目录时，插件完全不干预**任何会话。

### 5.2 判据字段

| 字段 | 说明 |
|---|---|
| `id` | 稳定标识；用户标注生成的用 `USR-01` 系列 |
| `level` | `P0` / `P1` / `P2` |
| `blocking` | 是否阻塞完成；P0 固定为 true，P1 默认 true，P2 默认 false，最终随契约确认 |
| `claim` | 可判定的陈述句 |
| `method` | `auto` / `visual` / `manual` |
| `rule` | `auto` 判据的规则 |
| `component` | 关联组件 id（可空） |
| `depends` | 依赖文件/产物 |
| `status` | `unverified` / `pass` / `fail` / `inconclusive` / `stale` |
| `evidence` | 实测值、证据哈希、确认人/时间 |
| `source` | 来源文档、章节/条款 ID、内容哈希和辅助行号 |
| `context` | 需要验证的步骤、模式、视角、动画时刻及视口条件 |
| `acceptance` | 自动验收或用户确认；与严重程度分别定义 |

### 5.3 状态三态 + 未验证

| 状态 | 含义 | 处置 |
|---|---|---|
| `pass` | 查完了，且符合 | 计入完成 |
| `fail` | 查完了，确有缺陷 | 必须修 |
| `inconclusive` | **没查完 / 判不出来** | **不是通过**，补查信号 |
| `unverified` | 未跑过 | 不是通过 |
| `stale` | 曾通过，但依赖变了 | 不是通过 |

**fail-closed**：已执行且明确不满足断言才记 `fail`；工具异常、超时、取证缺失记 `inconclusive`，绝不静默跳过。错误须给可定位的补救指令。`stale` 表示任何旧结果的适用条件已变化，不限于曾通过的结果。

## 六、三层判定

| 层 | 定义 | 谁判断 | 处理 |
|---|---|---|---|
| **L1 机械可判** | 哈希、坐标、闭合容差、方向矢量、文案一致 | 插件自动 | 未通过则不予认证；优先自动修复，不逐项请求确认 |
| **L2 明显缺陷** | 环流不成圈、乱飞、遮挡、首屏溢出 | agent 必须先自查并修 | 修复后举证；能力缺失、持续失败或预算耗尽时报告阻塞 |
| **L3 判断性** | 简化口径、构图配色是否达标 | **只有这类问你** | 走确认流程 |

**补充**：
- **证据充分性**：每条判据须声明所需证据类别。配置检查不得替代运行时几何检查，几何检查不得替代视觉检查；缺少要求的证据记 `inconclusive`，P0 不得仅警告后放行。
- **判据自检（元判据）**：每条 `auto` 判据启用前，至少包含一个正确样本应 `pass`、一个已知缺陷样本应 `fail`，并验证阈值边界。规则或阈值变化后重跑；结果不符合预期时不可启用。

## 七、核心机制

### 7.1 增量验证（治 P1）

- `depends` 建立「文件/产物 → 判据」映射；变了只复跑受影响项。
- 改前可查影响面。
- **证据复用绑版本键**：契约版本、依赖内容、规则与阈值、执行器/适配器版本、构建产物和判据所需运行上下文共同形成键；键一致且上次为 `pass` 才复用。纯静态规则可不含无关视口参数，但须显式声明。
- 依赖覆盖共享模块与传递依赖；无法确定影响范围时扩大复验，不猜测“无影响”。源文档相关条款变化时，对应契约需复核；不得继续复用旧确认。
- **可续跑**：中断后从断点继续，已完成且键未变的跳过。

### 7.2 冻结双轨（治 P3）

- **判据级**：`pass` 冻结证据基线；依赖一变自动 `stale`。
- **文件级**：已验收产物记录哈希基线；写前阻止能力须由 M0 验证，只有写后检测时称为“变更检测”，不得宣称文件无法被修改。
- **组件级**：修改前声明允许变化的组件、属性及关联影响；在相同上下文下比较修改前后快照，对越界变化触发回归检查。指纹覆盖范围必须写进报告。
- **实现变更通道**：agent 声明目标判据或已接受的变更请求、允许变化范围后自动放行并记录；重新验证，不逐次请求用户许可。
- **契约变更通道**：删除判据、放宽阈值、降低阻塞级别、减少证据要求或改变验收含义，必须展示差异并重新由用户确认。agent 的解锁声明不能替代确认。其他规则代码变更至少使原证据失效并重跑判据自检；无法证明验收含义未变时亦需确认。

### 7.3 三道刹车（治 P2）

| 闸门 | 管什么 | 阈值 |
|---|---|---|
| **轮次预算** | 每阶段修改轮次 | 初始建议：科学文档 3 / 开发文档 3 / 原型 5 / 制作 8 / 交付 3；项目可配置 |
| **空转判定** | 同一目标持续无进展 | 连续 3 个有效修改轮次，无新增通过、无未知项减少、无约定实测指标改善，且重复同类策略 |
| **硬熔断** | 跑太久 / 死循环 | 迭代上限 + 时间预算 + 紧急停止 |

- **排除合法等待**：`wait` 类动作不参与重复判定；带进度标记且标记变化的不算重复。
- 一个轮次定义为“针对同一目标的一批修改 + 一次有效复验”，不是一次工具调用。指标改善方向、最小改善量在开始修复前确定；无实测依据的进度文字不重置空转计数。等待不计空转，但仍受任务总截止时间约束。
- **恢复是梯子**：① 提醒换策略 → ② 禁止重复刚才那类改动 → ③ 才停下问你。前两级不占用你的时间。

### 7.4 完成门禁

- agent 应调用 `complete` 申请完成认证。能否阻止跳过调用或提前结束会话，取决于第十八节的 DSH 能力验证；未验证前只承诺“不出具通过认证”。
- 校验：存在非空、已确认且覆盖约定范围的契约；所有生效判据均有当前版本的确定结果；所有 `blocking=true` 的判据为 `pass`；L3 及要求人工验收的项目具有对应版本的用户确认；所有已发送标注均已验收或由用户明确撤回。
- 非阻塞判据的 `fail` 可作为已知遗留项列入报告；任何生效判据的 `stale` / `inconclusive` / `unverified` 均不允许认证。P0 不可设为非阻塞。
- 完成认证绑定契约版本与交付产物哈希；后续变化自动使认证失效。检查过程中发生修改时，不签发混合版本报告。
- 不达标 → 返回可执行的补救指令（哪条、差什么、下一步做什么）。
- 输出**一页式报告**：每条结果 + 实测值 + 证据位置 + 严重程度。

### 7.5 能力冻结锁

把已确认的关键判据集合与插件支持的规则类型写进基线；未授权减少应报错。兼容迁移须记录旧新映射，标准削弱遵守契约变更流程。基线与源码同在可写工作区时只能检测意外回退，不能宣称防篡改；可靠授权记录的存储边界在 M0 验证。

## 八、组件标注通道（v3.0 新增）

### 8.1 定位

**用户意图的可视化输入通道。** 它同时解决三件事：

| 作用 | 说明 |
|---|---|
| **意思输入** | 点一下代替"那个箭头"，消除指代歧义 |
| **需求追踪** | 每条标注自动生成判据，有编号、必须关闭，不会聊着聊着就丢 |
| **回归保护** | 记录组件指纹，改完自动核对"只该改的变了" |

### 8.2 交互流程（沿用原流程，验收分流为 v3.2 建议）

```
① 打开「模型预览」面板
② 点「标注模式」→ 模型进入点选态
③ 点中组件 → 高亮 + 就地弹出输入框
④ 输入"这个要改什么" → 保存为一条待发送标注（可编辑 / 可删除）
⑤ 可继续点第 2、3 处……（累积）
⑥ 一次发送 → 保存变更请求 + 生成消息 → 整理可判定的验收条件
⑦ agent 修改 → 面板自动重载 → 变动组件高亮
⑧ 自动验收项展示验证结果；人工验收项集中请你确认，通过后关闭
```

### 8.3 发送内容（解决"agent 还要问哪个"）

一次发送包含：

```text
【组件标注 · 第 N 批】
1. nh-trade-winds（北半球东北信风箭头）
   代码: src/config.js:42
   关联判据: GEO-WIND-03
   截图: <该组件高亮图>
   用户要求: "这个箭头方向反了，应该是从东北吹向西南"

2. ...
```

**要点**：组件 id + 中文标签 + 代码位置 + 截图一并给出，agent 不需要再问"你说的是哪个"。

### 8.4 标注 → 判据

- 每条标注先保存不可覆盖的用户原话、组件、截图、模型版本和批次 ID，再由 agent 整理可判定的 `claim`、验收方式和允许变化范围。一个请求可关联多条判据，全部满足后才关闭请求。
- 请求状态：草稿 → 已发送 → 已整理 → 修改中 → 待验收 → 已关闭；用户可明确撤回并保留原因。自动验证失败回到修改中。
- 默认级别 P1 且阻塞完成；科学正确性升为 P0。审美要求也可阻塞完成，优先级低不意味着可以忽略。
- 明确可测的修改默认自动验收；审美、教学取舍、含糊要求以及用户指定亲自验收的项目使用人工确认。与已确认科学口径冲突时，先请求用户解决冲突，不直接覆盖原契约。
- **进入完成门禁**：所有已发送请求都必须处理；草稿不进入。整理和发送须幂等，重试不得生成重复请求或重复判据。

### 8.5 改后闭环（属性核对与验收分流为 v3.2 建议）

- 面板自动重载改动后的模型。
- 高亮**发生变化的组件**，并给出核对结论：

```text
本次改动：2 个组件
  ✓ 已变：nh-trade-winds、sh-trade-winds
  ✓ 其余 17 个组件的已监测属性未变化（相同视角与步骤下）
```

- 自动验收须满足关联判据；人工验收须展示对应构建的改后证据。你点“通过”才记录该版本的确认；“不通过”保留原因并进入下一轮修改，点击本身不重复计轮次。

### 8.6 交付版剥离

标注层**不得进入教师正常使用的交付物**。沿用你已有的 `__VERIFY__` 编译开关做法（`环流2/05` 已实践）：**验证版有、交付版剥离**。符合 skill 的"自检面板/日志不得进入正常操作流程"。

### 8.7 候选技术落点（原稿标为已核实，本版要求补齐版本及验证证据）

| 能力 | DSH 扩展点 |
|---|---|
| 面板挂载 | 客户端 slot `conversation.view`（对话区视图页签，与聊天/轨迹并列，session 作用域） |
| 提供服务页面与注入桥接脚本 | `webServer.register()` |
| 以用户身份发送 | `sessionController.prompt()` |
| 模型与插件通信 | iframe `postMessage` |

以上名称沿用原稿，当前规格修订未独立核验 SDK。M0 须记录目标 DSH 版本、API 出处、最小调用样例和实际结果；能力不足时明确降级，不推定这些 API 具有拦截、取消或授权能力。

## 九、判据规则形式

- **验证核心不依赖外部进程**。既有 pwsh 故障属于特定 DSH/Windows 环境记录，不推导为永久平台限制。构建与浏览器取证通过经 M0 验证的适配器完成；不可用时返回 `inconclusive`，不得拿旧产物冒充新构建。
- 规则：读哪个文件 → 取哪个值（哈希/数值/正则/表达式）→ 断言什么。
- **几何能力**：点距、环上采样连续性、法线一致性、包围盒重叠、方向矢量叉积、SVG 路径端点偏差。
- 目标：把"环流不成圈""乱飞""穿模"变成可计算判据。
- 一期先实现数值比较、距离/闭合、方向与文案一致性；包围盒重叠只标记候选相交，不直接判定穿模。遮挡、穿模等复杂检查明确所需视角和算法边界，未实现能力不得列为自动可判。
- 规则采用受限、结构化操作，不执行任意表达式或 `eval`；读取路径限制在授权项目内，限制输入大小与执行时间。

## 十六、边界澄清：知识点盘点 ≠ 判据模板

（本条为 v3.1 修正，防止后续又滑回"模板化"）

**你说的"高中地理适合网页建模的内容"是一份知识点盘点**——哪些内容适合用网页路线表达。它的用途是**判断选题与选路线**，属于你自己的教学判断资料。

**它不进入插件**，因为：

| 若把知识点做成判据模板 | 后果 |
|---|---|
| 判据脱离本项目的科学性文档 | 出现"套模板过关"，正是要防的 |
| 换一个主题就用不上 | 维护成本高、易失真 |
| 与 skill 现有分工冲突 | skill 已管"该表达什么"，插件再管一遍就重叠 |

**初始判据的来源**：本项目的《科学性文档》《开发文档》→ 插件扫描指定章节生成待确认草案 → 你确认 → 冻结。每条草案标注来源条款、内容哈希及辅助行号，可追溯。后续用户标注属于明确的需求变更来源，按第八节处理；改变科学口径或原验收标准时必须同步更新相关文档与契约，不能形成互相矛盾的两套要求。

**一句话**：知识点盘点决定"做什么"，科学性文档决定"做成什么样"，插件的判据从这个"什么样"里来。

## 十七、模型取证协议（v3.2 新增）

### 17.1 最小请求与响应

验证器向预览适配器发送取证请求，包含 `requestId`、项目/会话 ID、预期 `buildHash`、目标组件列表、步骤/模式/视角/动画时刻和所需属性。适配器须等待模型加载及状态稳定后回复；不能到达指定状态则返回明确错误，不回退到任意当前画面。

响应至少包含：

| 字段 | 含义 |
|---|---|
| `requestId` / `projectId` / `sessionId` | 将响应关联到正确请求和项目会话 |
| `buildHash` / `sourceHash` / `adapterVersion` | 被测产物、对应源码及取证适配器版本 |
| `context` | 实际步骤、模式、视角、视口、动画时刻；与请求不符即不采信 |
| `components` | 按稳定 ID 导出的实际运行时属性；含坐标系、单位、父节点变换等必要解释 |
| `evidenceKind` | 配置 / 运行时几何 / 视觉 / 用户确认 |
| `capturedAt` / `artifacts` | 取证时间、截图或数据文件及其哈希 |
| `coverage` / `errors` | 成功覆盖和无法覆盖的组件、属性及原因 |

Three.js 方向、端点等应来自实际构建对象的世界变换或实际使用的路径，不能只复述配置值；DOM/SVG 取实际状态与几何。视觉判据必须绑定截图及上下文。模型自己声明“通过”不算插件验证结果。

### 17.2 一致性与失效

- 取证开始、结束及签发报告前检查版本；期间修改、重载或收到旧响应时丢弃不一致结果，标记待复验。
- 动态模型取证时暂停到约定时刻；无法控制随机性或动画状态时不得复用视觉证据。
- 用户确认绑定具体请求、验收条件和证据版本；相关内容变化后确认失效，无关变化须经依赖证明才可保留。
- 配置、运行时、视觉三类检查可互补，但禁止互相替代必需证据。

### 17.3 通信边界

- `postMessage` 校验来源窗口、允许的 origin、会话绑定和消息结构。若运行环境为 opaque origin，须明确受限的握手机制，不能仅信任消息里的组件 ID。
- 模型页面只能返回取证数据和点选事件，不能伪造用户确认或直接改写认证结果。
- 面板发送请求采用持久化批次 ID 和投递状态；失败可重试且不重复创建标注。切换项目或会话不得将标注投递到其他项目。
- 快照有字段白名单、数据量上限与超时；源码路径和产物访问遵守项目权限边界。

## 十八、DSH 宿主能力验证与降级（M0）

以下均为待测能力，不是已验证事实。每项记录 DSH 版本、SDK/API 出处、样例、结果和限制。

| 能力 | 必须验证的行为 | 不具备时的处理 |
|---|---|---|
| 会话面板与服务页面 | 面板能加载目标预览；重载后仍绑定正确项目 | M2 暂不验收，不宣称标注可用 |
| 向会话投递消息 | 批量标注准确投递，失败可恢复，不重复 | 保存待发送请求并报告投递失败 |
| 构建与取证 | 能确定新源码对应的新产物并采集运行时证据 | 对应判据 `inconclusive` |
| 完成拦截 | agent 不调用 `complete` 就结束时能否拦截 | 只提供完成认证与未认证状态 |
| 写入拦截 | 是否覆盖实际使用的全部修改渠道 | 只提供修改后失效与回归检测 |
| 执行取消 | 超时/紧急停止能否取消活动任务和后续排队动作 | 标明只停止插件自有任务，报告宿主任务未确认停止 |
| 授权与确认存储 | 能否区分真实用户确认和模型页面/agent 写入 | 不签发无法验证来源的人工确认；明确认证信任边界 |
| 恢复与隔离 | 重启恢复、多个项目/会话并存时无串线 | 未满足前不开放并行会话使用 |

认证、请求状态、证据索引需要原子写入和版本检查；多个会话并发修改同一契约时应检测冲突，不以最后一次写入静默覆盖。

## 十九、可执行验收清单

原第十三节为历史问题线索，以下为实际实现验收场景。历史原始版本不可获得时，可以建立标明来源的缺陷夹具，不得声称已回放原始版本。

| 场景 | 预期结果 |
|---|---|
| 已确认闭合容差小于 0.03，运行时端点距离为 0.03 | `fail`，报告实测距离、容差、坐标系及证据 |
| 同一闭合夹具修复到容差内，并测试边界值 | 正确样本通过；边界按约定的包含/不包含关系判定 |
| 配置风向正确，但渲染对象被额外旋转成错误方向 | 运行时方向判据失败，不被配置检查掩盖 |
| 修改共享配置或规则后请求复用旧通过结果 | 原证据失效，相关判据复验 |
| P1 阻塞项失败，P0 全通过 | 完成认证失败 |
| 非阻塞项明确失败，其余条件满足 | 可认证，报告必须列出遗留失败 |
| 契约为空、判据被删、取证超时或响应属于旧构建 | 不认证，并说明具体原因 |
| agent 放宽阈值并声明“为修复失败” | 不自动接受标准变更，要求契约重新确认 |
| 点选风带箭头并修改其方向 | 定位稳定 ID 对应源码；新构建取证；按既定验收方式关单 |
| 修改共享材质造成未声明组件属性变化 | 标记越界影响并触发关联复验，不报告“其他组件未变” |
| 重试发送同一标注批次、刷新面板、切换会话 | 不重复生成、不丢失、不投递到错误会话 |
| 闭合误差连续下降但尚未通过 | 不仅因没有 `fail→pass` 就判空转；仍受总预算约束 |
| 用户确认后修改相关模型内容 | 旧确认和完成认证失效 |
| agent 绕过 `complete` 直接结束 | 有宿主拦截能力则阻止；否则保持未认证，不伪称已阻止 |
| 教师交付版检查 | 无标注层和验证入口；教师默认打开方式单独验证通过 |

冲积扇不进入一期 Blender 接入验收；其版本序列只作为轮次记录机制的离线夹具。只有版本号变化不能证明空转，必须有目标、指标或策略记录。

### 一期完成定义

M0 能力矩阵有实测记录，M1/M2 核心闭环通过上述相关案例后，可交付“一期最小版本”。M3–M5 未实现时在能力清单中明确列出，不以最小版本通过代替全规格完成。通用几何计算器属于执行能力，可复用；具体教学判据与阈值仍只来自已确认项目文档及已接受的用户变更请求。
