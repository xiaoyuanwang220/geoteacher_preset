## 四、M1 变更（规范与技能）

### 4.1 重写 `skills\geo-question-explainer.md`

- `description` / `whenToUse` 扩为三对象路由与触发词；description 控制在 500 字符预算内。
- 新增 **对象路由**表：`student`（默认）｜`teacher`｜`setter`，含触发话术与"各对象回答的核心问题"。
- 明确：**仅因为当前用户是教师，不自动选教师对象**；默认只生成一个对象；换对象而题目未变时复用已核验分析，改题面或答案依据须重新核验。
- 保留四段式，**四维（知识/解题/方法/跨学科）融入段内**，并给出"学生对象侧重 / 教师对象侧重"逐段对照表。
- 命题人对象：给出七段结构 + 三层干扰辨析（设问/材料/选项）必检要求、逐条干扰的报告字段、综合题选项层"不适用"规则、负例约束。
- 方法总结与跨学科：按问题结构提炼 + 状态记 `applicable` / `not_applicable` / `pending`；连通器类比须查条件；新推理交回分析与核验阶段。
- 语言规范按对象分流：学生保留讲课口吻，教师/命题人**不套用**学生口吻。
- 前置门禁增加"缺独立答案/核验报告损坏/qid 不一致时如实返回待核验状态"。
- 质量自检清单扩到 13 项，含"去标题后仍能判断服务对象"。
- 把详细内容移入 references，根正文保持在工程预算内。
- **作废旧规定**："教师版只是可照读的学生讲稿""学生版仅指无答案支架"——现明确学生对象**允许自然推出答案**，"无答案练习支架"是另一个可选交付形式。

### 4.2 新增 `skills\references\explainer-audiences.md`

按方案 §6"同目录新增 references/explainer-audiences.md"落地。含：术语口径、四维内容矩阵、四段式对象取舍、学生/教师/命题人交付规范、教师思维培养组织模板与示例、命题人三层干扰辨析完整表与报告字段、方法总结与跨学科细则、设问类型组织逻辑、交付与缓存规则、**去标题辨识**（反面案例 + 同题三对象演示片段）、过程性元话语检测表、proposition-preservation 边界。

> 位置说明：讲题技能保持平铺单文件形态（方案 §2.2"本次不需要为目录美观迁移技能格式"），因此 references 放在技能根 `skills\references\`。若日后迁为目录包，应移动到 `skills\geo-question-explainer\references\`。

### 4.3 更新 `cordis.patch.yml` persona

讲题路由行补 `audience` 参数与默认值、三对象路由判据、复用与核验纪律；流水线顺序与题库纪律保留不变。

### 4.4 更新 `docs\术语表.md`

按"新增术语须先在术语表追加"的约定，新增并登记：**讲解对象（audience）**、**四维内容**、**三层干扰辨析**、**提供材料待核验**；修订**讲题稿**条目（区分四段式与命题人结构），并标注与"学生投影/教师投影"的易混关系。

## 五、M2 变更（工具、核心与显示）

### 5.1 `plugins\analysis\index.js`

- 新增 `EXPLAIN_AUDIENCES`、`AUDIENCE_LABELS`、`normalizeAudience()`、`buildVerification()`（均具名导出，供测试）。
- `geo_explain` 增加 `audience` 参数（JSON Schema `enum`），并更新 `description`。
- **输入校验**：非法 `audience` 返回 `{ status: 'error', code: 'INVALID_AUDIENCE' }`，不回退、不静默；缺省/空串按 `student`（旧调用兼容）。
- **核验状态**：新增 `verification` 字段，状态为 `material_provided_pending_review` / `missing_judge_report` / `missing_solve_and_judge` / `judge_report_invalid` / `judge_qid_mismatch`，并给出待补齐项；`verified` 恒为 `false`、`evidence` 为 `self_reported_material`。
- `judgeReport` 解析改为**显式**记录成败，并抽出 `questionId` 做跨题校验；解析失败不再产生"看似正常"的包装。
- `renderExplain` 按对象渲染：对象标签、文体要求、共同分析要求、对象 audiencePlan、三层干扰辨析层状态、跨学科状态、核验状态、缓存键；命题人不渲染四段式标题。
- 枚举注释说明：插件间不能相对 import（baseUrl 是 profile 目录），故该枚举与 core 各自声明、改动必须同步。

### 5.2 `plugins\core\index.js`

- `buildExplainerReport(q, isChoice, judge, variants, audience)` 接收对象并**具名导出**；`explainerData(questionId, independentAnswer, judge, audience)` 接收并回传对象。
- 报告新增 `schemaVersion`、`audience`、`audienceLabel`、`commonAnalysis`（共同要求 + 四问论证）、`interdisciplinary`（状态恒为 `pending`，工具不做关键词式跨学科关联）、`audiencePlan`、`audienceDeliverable`、`cacheKey`。
- **学生/教师**：保留 `locate` / `examine` / `solve` / `reflect` 四段骨架与原字段（定位卡字段、`choiceNote`、`dimensionScan`、变式、核心考点），逐段增加 `audienceEmphasis`；`languageGuide` 按对象给不同文体；教师附 `audiencePlan`（六节点模板、思维目标、学生思维动作、递进追问、支架、撤除条件、独立迁移检测、指导语）。
- **命题人**：改用七段 `structure.sections`（考查目标／情境材料设问／干扰辨析／预期认知路径／答案成立条件／迁移与跨学科设计／题组和质量评价）+ `audiencePlan`（三层干扰层，含每层 `applicable`；综合题选项层 `applicable: false` 且注明不得虚构选项）+ `perFindingFields` + `constraints`。
- **缓存键**：`questionId#题面指纹#audience#rules<版本>`；题面指纹为 stem/material/options/answer 的 FNV-1a 摘要（题库项无 revision 字段，故用品面指纹代表"题目版本"）。
- 非法 `audience` 在 core 层兜底为 `student`（正常路径由工具层先拦截）。

### 5.3 显示层

`plugins\ui\` 经核实**没有讲题入口与渲染位置**（`page.html` 仅「真题分析」「命题蓝图」两标签）。按方案 §6 允许的降级路径：**先交付会话工具模式并如实标注**，本轮**未改 `page.html`、未新增 HTTP 讲题路由**（路由也不存在可同步的消费者）。对象选择当前经会话中 `geo_explain` 的 `audience` 参数完成。已在 `docs\使用指南.md`、`README.md`、`docs\讲题功能设计.md` §11.6 标注。

### 6.6 核验材料交接缺陷与修复（2026-09-30）

**症状**（验收 §6.4-3 时暴露）。把核验材料交给 `geo_explain` 的两条路径都走不通：

- 原样回传 `geo_judge` 的 Markdown 渲染 → 返回 `judge_report_invalid`，标为待核验；不崩溃，但核验信息丢失；
- 回传合法 JSON 而其中 scaffold 不含 `scorePoints`／`coverageGrid` → 工具边界报 `geo_explain returned invalid output: value is not lossless JSON`，**整个调用失败**。

**根因**：`plugins/core/index.js` 的 `buildExplainerReport` 写 `judgeSummary: { scorePoints: judge.scorePoints, coverageGrid: judge.coverageGrid }`。缺键时两项取值为 `undefined`；`JSON.stringify({a: undefined})` 得 `{}`，键在往返中丢失，DSH 工具边界按「结果必须无损通过 JSON 往返」判定不通过。

**既有测试未能发现的原因**：`test/explainer-audience.test.mjs` 原有 12 例全部直接调用 `buildExplainerReport`／`buildVerification`／`renderExplain`，绕过了工具 `execute()` 与 DSH 的无损 JSON 边界。仓库内那份 `'{"standard":{}}'` 用例正是这种写法，因此照旧通过。

**修复**：

1. `plugins/core/index.js`：`judgeSummary` 改为 `Array.isArray(...) ? ... : []`，两项恒为数组，结果恢复无损；
2. `plugins/analysis/index.js`：新增导出 `toJudgeReportJson()`；`renderJudge` 末尾追加「## 机器可读核验材料（回传 geo_explain 用）」小节与 json 代码块，把核验材料序列化成可**原样回传**的 `judgeReport`（`JSON.stringify` 丢 `undefined` 键、把非有限数字转 `null`，故必定无损）；
3. `test/explainer-audience.test.mjs`：新增 3 条**走真实 `execute()` 并做深度无损检查**的边界回归（缺键 scaffold、缺材料、非法 `audience`、Markdown 误传、三对象与跨题材料），另加 2 条核验材料交接用例（渲染含可解析 JSON 代码块且原样回传得到 `material_provided_pending_review`；`toJudgeReportJson` 在 scaffold 缺失或含 `undefined` 时仍产出合法 JSON）。

**验证**：`node --test test/explainer-audience.test.mjs` → 17/17 通过，退出码 0；`node scripts/geo-verify.mjs --source` → 0 失败 / 4 提示 / 27 通过。对照探针确认旧形状 `{scorePoints: undefined, coverageGrid: undefined}` 序列化为 `{}`（判定 FAIL），新形状无损（PASS）。

**尚未在运行时生效**：插件 JS 改动需**完整重启桌面**才进入运行进程。修复后再次实调同一合法 JSON，仍报 `value is not lossless JSON`——证实运行中的宿主仍是旧代码。**重启前不得声称该修复已在运行时生效。**

**交接形态已定并实现**（2026-09-30）：采用「`geo_judge` 渲染附机器可读核验 JSON」。模型把「## 机器可读核验材料」小节里 json 代码块的内容**原样**作为 `judgeReport` 传入即可，不需自行转写 Markdown。备选方案「`geo_explain` 接受 Markdown 并跳过 scaffold 解析」会丢失采分点与覆盖网格计数，未采用。此改动与上面的无损化同样**需完整重启桌面**才在运行时生效。

执行命令（等价于 npm scripts，用随发行版 Node 运行）：`node --test test/explainer-audience.test.mjs`、`node scripts/geo-verify.mjs --source`。

补充说明：`pwsh` 在 workspace-write 沙箱下必以 `3221225794`（STATUS_DLL_INIT_FAILED）退出，提升到 full access 后才可执行命令——§6.1 此前记录的「shell 不可用」由此而来，不是 pwsh 或仓库本身的问题。
