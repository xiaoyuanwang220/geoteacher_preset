## 一、功能定位与目标

**定位**：对真题库中任一道真题，生成「如何解题」的讲题稿——一步步教学生读材料、拆题目、讲清解题步骤与思路，培养地理思维与应试能力。

**核心原则（v3.0 定稿）**：

1. **题能真正做对，是一切的前提**：solver（独立解题）先行开发并评测达标，explainer（讲题）建立在已被 judge 验证过的解题过程之上；不先做对题，讲得再像老师也是错的。
2. **解题与讲题分离，讲题不依赖答案**：解题只在**隔离解题会话**中完成——bundle 声明的内部 agent preset（`plugins/solver-isolation` 提供 persona，并在 preset 作用域用 `tools.restrict`/`tools.guard` 隐藏并拒绝全部继承工具）spawn 出的全新子会话，不继承主会话历史与工具，只收到题面（材料+题干+选项/小问+**题面图片**）；**解析图**、答案标记与解析派生的考点提示不进入解题输入。独立作答先由插件提交到服务端 run（`submitted`），答案/解析才开放给核验阶段；对照结论归档后 run 为 `verified`，讲稿只读该记录。讲题教的是**思维过程**，不是把答案翻译成话术。
3. **设问先行**：先看问什么（对象/动词/限定词），带着问题定向读材料；但**不是机械规则**——设问拆解落到**设问类型化的组织逻辑**（见 §五），不套"自然原因+人文原因"式模板。
4. **地理思维显性化 + 四问论证**：不只标注思维类型，每个推理都要能回答四个"为什么"（见 §四）。
5. **分题型讲法**：选择题讲"排除链+错因"，综合题讲"采分点组织+术语"。
6. **带评分视角**：讲题落到分值、采分点、表述规范。
7. **可迁移**：讲完提炼"一类题"的思维模板，并给出变式练习。

**与现有功能的关系**：

| 功能 | 视角 | 回答的问题 |
| :--- | :--- | :--- |
| 真题分析（已有） | 命题者/考情 | 这道题**为什么这样考**（题型/情境/素养/难度/考点映射） |
| 命题蓝图（已有） | 命题者 | **下一道**题怎么设计（情境换新/设问设计/选项设计） |
| **讲题（本功能）** | **教师/解题者** | **怎么教学生做这道题**——solver 独立解题 → judge 核验 → explainer 教学化重组 |

## 二、总体架构：三组件流水线（Solver → Judge → Explainer）

```
        ┌─────────────────────────────────────────────────────────┐
        │  题答分离由插件完成；解题在隔离解题会话中执行，          │
        │  主会话不得自己解题，也不得直读题库 md/图片。            │
        └─────────────────────────────────────────────────────────┘

 题库 MD（题面 + 答案/解析 + 题面图片 + 解析图）
        │  prepareSolve：题答分离 + 题面指纹
        ▼
┌───────────────────────────────────────────────────────────────┐
│ 【1】geo_solve 隔离解题（run 进入 question_ready）               │
│   输入：题面（材料/题干/选项/小问/题面图片；无答案、无解析图）    │
│   执行：内部解题预设（工具锁）spawn 子会话（caller delivery）     │
│   流程：审题（设问类型框架）→ 证据提取（定向读材料/读图）          │
│        → 知识激活（为什么用这个知识）→ 推理链（每步有依据）        │
│        → 作答（选择：选哪项+理由；综合：写要点）                  │
│   提交：recordIndependentAnswer → run 状态 submitted            │
│   失败：fail-closed（不回落主会话）                              │
└───────────────────────────────────────────────────────────────┘
        │  独立作答（服务端保存，原文不得改写）
        ▼
┌───────────────────────────────────────────────────────────────┐
│ 【2】geo_judge 两阶段核验（服务端门禁）                          │
│   阶段一：openReferenceAnswer（需 submitted 且指纹一致）         │
│   输入：独立作答 + 标准答案/解析/采分点/覆盖网格                 │
│   阶段二：recordVerification(conclusion) → run 状态 verified    │
│   分析：得分点覆盖 / 推理错误 / 要点遗漏 / 干扰项解释质量         │
│   输出：核验报告（对照结论归档，不担保内容正确）                  │
└───────────────────────────────────────────────────────────────┘
        │  服务端 verified 记录
        ▼
┌───────────────────────────────────────────────────────────────┐
│ 【3】geo_explain 讲题（只读服务端核验记录）                      │
│   输入：verified run（独立作答 + 核验结论）+ 讲解对象            │
│   输出：讲题稿「题目定位—审题—破题—反思迁移」                     │
│        （选择题/综合题分述；四问论证；设问类型化组织；同类题比较） │
└───────────────────────────────────────────────────────────────┘
        │
        ▼
【4】真题评测（20–30 道，教师人工） → 【5】插件整合 → 【6】UI
```

**三组件职责边界**：
- **solver 管"做对"**：隔离解题会话的独立解题质量（答案正确率、证据准确性、推理链完整性、采分点覆盖率、干扰项解释质量）是评测对象；
- **judge 管"对照"**：作答提交后开放答案，两阶段完成客观对照，并把对照结论归档进服务端 run；
- **explainer 管"讲"**：只消费服务端 `verified` 的独立作答与核验结论做教学化重组，**不再重新解题、不接收主会话传来的独立答案或核验报告**。

> 说明：题面（材料/题干/选项/小问/题面图片）由 `prepareSolve` 从题库 MD 分离后交给隔离子会话；答案/解析只经 `openReferenceAnswer` 在作答提交后开放。`## 相关图片` 节与答案标记前的正文图片是**题面图片**，`**答案**`/`**解析**`/`## 教学备注` 之后的图片是**解析图**，永不进入解题输入。边界无法判断时返回明确错误并指出具体题目，请教师确认，不猜测切分。

> **现行编排（2026-11-06 起，服务端持有状态）**：`question_ready`（题面就绪）→ `submitted`（作答已提交）→ `verified`（核验完成）。每个**题组**一个 run，绑定 `questionId + questionFingerprint`（指纹只含题面，不含答案/解析）；题面变化 → 指纹变化 → 旧 run 失效，必须重新解题。run 持久化到 `<outputPath>/solve-runs.json`（最多保留 200 条），重启后仍可核验/讲题。调用答案接口不能绕过作答提交；`核验完成` 表示"答案开放 → 题组内各小问对照结论均已归档"的顺序已完成，不等于内容正确。

## 三、教学模型：讲题稿结构（Explainer 的产物模板）

**设问先行 → 定向读材料**，每一步挂地理思维锚点：

| 步骤 | 内容 | 地理思维锚点（讲给学生听） |
| :--- | :--- | :--- |
| **1 拆设问（先行）** | 先看问什么：对象 + 行为动词 + 限定词 → 判定思维层级与**设问类型**（见 §五，不机械套模板） | 综合思维入口："'分析'要因果链，'评价'要分利弊，'比较'要同口径指标；'原因'要分清直接/根本/触发/加剧" |
| **2 带着问题读材料** | 定向阅读：按设问对象锁定要找的要素证据（位置/地形/气候/水文/人口/产业/交通…），定区域与尺度 | 区域认知 + 目的性阅读："设问指向产业区位→只盯区位要素；先定位区域→激活区域常识，再找材料证据"；点明干扰信息为何是干扰 |
| **3 知识选择** | 明确"**为什么要用这个知识**"：题目哪些线索激活了哪个原理/概念 | 综合思维：知识不是背出来的，是由题目线索+区域特征选出来的 |
| **4 推理链** | 材料证据 × 知识 × 设问 → 地理因果链 / 逐项排除；每步标注"**为什么能推出下一步**" | 综合思维+区域认知：前提→结论的因果显性化 |
| **5 作答与检查** | 地理语言规范、采分点组织（要素维度排查，见 §六）、易错点 | 人地协调观：答案带条件限定与辩证 |
| **6 方法提炼** | 升维成可迁移的地理思维模型 | 把"这道题"变成"这一类题的思维模板" |

> **现行学生版本线（设问先行六步）**：上表六步是学生对象四段式「题目定位—审题—破题—反思与迁移」的**段内**序列，**不另设顶层目录**：审题＝①，破题＝②③④⑤，反思与迁移＝⑥。选择题与综合题**共用**六步，差异只在②（带着问题读材料）与⑤（作答与检查）；读图不独立成步，作为②的内部动作写清（涉图题）。
>
> **同类题比较**以题库检索为依据（按设问任务、推理关系、材料特征检索，而非仅考点相同），落在**破题**（与相关题的方法/步骤对照）与**反思与迁移**（方法总结、适用边界与变式）；比较安排在本题独立作答提交之后，总结须列出所依据题目及具体对应关系，候选不足时明确缺口。详见技能内 `references/explainer-audiences.md` §4.1 与 `docs/术语表.md`「学生版教学流程（设问先行六步）」 §二。
>
> 规范见技能内 `references/explainer-audiences.md` §4.1；术语登记见 `docs/术语表.md`「学生版教学流程（设问先行六步）」；实现见 `plugins/core/index.js` 的 `buildStudentPlan()`（`flow` / `stepPlacement` / `stepTemplate`）与 `plugins/analysis/index.js` 的 `renderExplain()` 学生分支。

## 四、地理思维显性化：四问论证（solver 轨迹 + 讲题稿共用）

**每个关键推理**都必须回答四个"为什么"，缺一即视为不达标（solver 产出、explainer 讲出）：

1. **为什么用这个知识解答**（知识选择依据）：题目里哪个线索（区域名/要素词/数据/设问词）让你调用了这条知识？换一个区域是否还用同一知识？
2. **为什么依靠这条材料**（材料使用依据）：这句材料支撑哪个推断？删掉它结论还成立吗？哪些材料是无关/干扰信息？
3. **这一步为什么能推出下一步**（推理链条因果）：这一步的前提是什么？到下一步的逻辑缝隙在哪（要素A→现象B→结果C，每段都有依据）？有没有跳跃/想当然？
4. **这题为什么不是另一个答案**（排除论证）：选择题：每个干扰项错在哪（绝对化/因果倒置/偷换概念/无中生有/程度失当），正确项为何必须由材料推出；综合题：备选要点为何不取（材料不支持/答非所问/与设问不匹配）。

**技术支撑**：骨架为每个推理输出"证据-知识-结论"三元组与干扰项错因（复用 `detectDistractors`）。

## 五、设问拆解：设问类型化的答案组织框架（去机械化）

**总原则**：每种设问都有它"该按什么逻辑组织答案"的方式，但都**以题目材料为据**——材料支持的层次才写，禁止机械套模板（如"分析原因"就一律写"自然原因＋人文原因"）。

| 设问类型 | 该组织什么逻辑（而非机械模板） | 讲题时要点明 |
| :--- | :--- | :--- |
| 分析原因/成因 | 按因果层次：**直接原因 → 根本条件 → 触发因素 → 加剧因素**；材料没提的层次不硬凑 | 现象与因素之间的因果链；哪些是"底牌"、哪些是"扳机"、哪些是"放大器" |
| 影响/意义/作用 | **分主体**（对自然/对人文，受益/受损）+ **分层次**（直接—间接、短期—长期）+ 经济/社会/生态维度，按材料支持的组织 | 影响的传递链（谁→怎样→导致什么）；"意义"要落到发展与人地关系 |
| 形成过程/演变 | 按**阶段与时间顺序**组织：环节链（如流水地貌：侵蚀→搬运→堆积）、每阶段驱动因素、动态变化 | 过程的先后与因果；不是静态罗列，而是"怎么一步步变成的" |
| 比较/差异 | **可比指标 + 同口径 + 区域限定**；只比较材料与知识支持的方面 | 用什么指标比、口径是否一致、结论是否可迁移 |
| 评价/是否合理/利弊 | **分主体利弊 + 代价与可行性 + 适用条件** | 受益者与受损者、成本与风险、结论有前提 |
| 措施/对策/治理 | **针对性（对应原因/问题）+ 分主体（政府/企业/个人）+ 可行性** | 措施为什么能解决这个问题（对症）；谁来实施、能否落地 |
| 分布/特征描述 | **空间方位/范围/形状/集中或分散 + "随××变化" + 数据支撑** | 描述要有位置/方向/数值依据，不是形容词堆砌 |
| 变化/趋势 | 时间尺度的**动态表述**（方向+幅度+速率），区分现状/过程/预测 | 什么在变、变多快、往哪变 |

- 骨架输出 `questionFramework`（由设问动词+对象+材料线索判定**类型**与**组织提示**），但**具体组织由模型按材料实际支撑来**；
- 设问动词相近但对象不同（如"分析甲的影响"与"分析乙的影响"）→ 组织逻辑相同，内容由对象决定。

## 六、综合题采分点：要素维度排查法（solver 作答与 judge 核验共用）

分值→要点数是表层；**关键是要点怎么找**。方法：**逐维度扫描题目材料，看材料支持哪几个维度**，再按因果逻辑组织成要点：

- **自然维度排查清单**：位置/地形/气候/水源/土壤/生物（+灾害）；
- **人文维度排查清单**：人口/农业/工业/服务业/交通/市场/政策/技术；
- **操作**：对每个维度问"材料里有没有这个维度的证据？"——**有证据的纳入，无证据的排除**，绝不把五个自然维度全写上；
- 纳入的维度再按"直接原因→根本条件→触发→加剧"或设问要求排序，形成采分点（每点：要素 + 证据 + 结论）。

**技术支撑**：骨架的 `dimensionScan` 输出各维度的**材料命中证据**（检测到"气候"→材料含降水/气温线索）；solver 据此组织要点，judge 据此核对覆盖。

## 七、实战讲题稿模型（Explainer 产物：分题型四段式）

**① 题目定位卡**（给教师快速决策）
题型（选择/综合）· 难度（基础/中档/压轴）· 年份省份题号 · 分值 · 是否涉图 · 主导素养与思维类型 · 建议讲解时长 · 建议年级

**② 审题（设问先行 + 设问类型框架）**
- 拆设问：对象 + 行为动词 + 限定词 → 思维层级 + **设问类型**（原因/影响/过程/比较/评价/措施/分布…→ 对应组织逻辑，见 §五）
- 明确"要答什么方向"

**③ 破题（分题型）**
- **选择题**：读图（涉图时独立：图例→坐标→数值→分布→趋势）→ 定向读材料 → 逐项排除链（每项：材料证据 × 知识 × 设问；正确项证据、干扰项错因）→ 四问论证覆盖（尤其"为什么不是别的选项"）
- **综合题**：读图/定向读材料 → 设问分层 → **要素维度排查**（材料支持的维度 → 采分点组织：分值→要点→每点表述→逻辑顺序）→ 术语规范

**④ 反思与迁移**
- 易错警示：基于服务端 run 的对照结论（`matched`／`missed`／`wrong`／`disputed`／`correction`）+ 常见错误（答非所问/漏维度/术语不规范）
- **同类题比较**：以题库检索为依据（按设问任务、推理关系、材料特征，`similarQuestions`），比较共同步骤、条件差异与方法适用边界；总结列出所依据题目及具体对应关系，候选不足时明确缺口；比较在独立作答提交之后，学生练习材料不提前给答案
- 方法提炼：一类题的思维模板（可迁移）；由题库比较得出，不凭单题经验编造
- 变式链接：题库真实候选 1–2 道；自拟变式明确标注

**学生版（旧表述，v4.0 起作废）**：不给答案，给支架——提示性问题、空格、引导性设问，保持认知负荷。

> v4.0 更正：学生对象**允许由推理自然推出答案**（答案呈现克制，即不先亮答案再凑理由）；"不给答案的练习支架"是**另一个可选交付形式**，不等于学生对象本身。教师对象也不是"可照读的学生讲稿"。现行规则见 §十一。

## 八、技术落地（按三组件拆分）

### 8.1 题答分离（core 解析层）

题库 md 版式（已实测 115 份）：`## 来源`、`## 题组材料`、`## 相关图片`、`## 第N题`（综合题为 `### 第17题（1）`）、`## 教学备注`；答案/解析以 `**答案**：`、`**解析**：` 加粗行开头。

- **解题输入**只含：材料、题干、选项、小问、**题面图片**。题面图片 = `## 相关图片` 节内图片 + 各小问 `**答案**` 标记之前的正文图片。
- **解析图**（`**答案**`/`**解析**`/`## 教学备注` 之后的图片）**永不进入解题输入**。
- 不进入解题输入：`**知识点归属**`、`MANAGED-KM` 块、答案、解析、`**点睛**`。
- 边界无法确定时返回明确错误并**指出具体题目**（题组文件、`第N题/第N小问`、命中片段），请教师确认；不得猜测切分后继续解题。判据：小节内没有 `**答案**` 标记但正文出现 `答案`/`解析`/`【答案】` 等痕迹；答案标记数与小问数不一致。错误码 `QUESTION_BOUNDARY_UNCERTAIN`。

### 8.2 隔离解题会话（analysis 执行层）

内部解题预设**在 `cordis.patch.yml` 中声明**（`id: geo-solver-internal`，不新增 profile `package.json` 依赖），唯一插件行是 `plugins/solver-isolation`：

- **persona**：该插件在 `deployment:persona-prefix` 段落写入 `skills/geo-solver.md` 去掉 frontmatter 的正文（读取失败用内置兜底并如实记录），保证解题方法只维护一份；
- **工具锁**：preset 只决定「本 preset 注册哪些工具」，**宿主/全局注册的工具仍会被子 agent 继承**（2026-11-06 实测：子会话 request header 里出现了 `session_search`、`session_event_*`、`external_*`、`working_directory` 等）。因此该插件在 preset 作用域（只作用于挂在 `geo-solver-internal` 下的 agent）内用 `tools.restrict({ deny })` 隐藏全部继承工具，并注册 `tools.guard` 在**执行期**兜底拒绝任何漏网的工具调用；晚于本 bundle 加载的宿主工具由短延时复查补 deny。

该内部预设会出现在预设选择器中（`name: '地理解题隔离会话（内部）'`、`order: 999`，描述已注明内部使用与"日常使用请选择「地理教师辅助」"）：它只供 `geo_solve` 内部调用，**不应被用户手动选择**。

`geo_solve` 执行顺序：

1. `kernel.prepareSolve(qid)`；`reused` 直接返回，不重新解题。
2. 检查隔离能力：`ctx.get('subagents')`、`ctx.get('agentPresets')`、`subagents.getProvider('spawn')`、`exec.agent` 缺任一 → `SOLVER_ISOLATION_UNAVAILABLE`，**不回落主会话**。
3. 题面图片全部保存为附件（顺序与题面一致）；`partial`/`degraded` → `IMAGE_DELIVERY_INCOMPLETE`，不猜。
4. `ctx.subagents.startActivation({ provider: 'spawn', label, request: { parent: exec.agent, agentPreset: '<内部预设 id>' }, delivery: 'caller' })` 创建**全新上下文**（无父会话历史），`await activation.result` 取最终文本。
5. 子会话 prompt 只含材料/题干/选项/小问/图片，不含 qid、文件路径、答案、解析、知识点、骨架、图片路径；说明不得调用工具、最终回复即提交的作答；格式 `## 答案` / `## 关键依据`。
6. `stopReason !== 'completed'` 或文本为空 → `SOLVER_RUN_FAILED`；`finally` 中 `await activation.dispose()`。
7. `kernel.recordIndependentAnswer(runId, { answerText, keyEvidence, childSessionId })`——**只由插件在子会话结束后调用，不接受模型传入的答案**。

### 8.3 服务端 run 状态机与两阶段核验

```
question_ready（题面就绪） → submitted（作答已提交） → verified（核验完成）
```

- 每个**题组**一个 run（题组首题 id 为键），绑定 `questionId + questionFingerprint`（指纹只含题面：material + 各小问 stem + options + 题面图片引用，**不含 answer/analysis**）。题面变化 → 指纹变化 → 旧 run 失效，必须重新解题。
- 同指纹已有 `submitted`／`verified` 作答时默认**复用**（不新建子会话）：`geo_solve` 返回 `reused:true`、`answerOrigin`、`answerSessionId`，渲染与回复必须说明"复用已有隔离作答（提交于…）"，不得表述为本次新建/重解；用户要求重新独立作答时传 `fresh:true`，新建 run 强制重新解题（旧 run 保留在历史，`latest` 指向新 run）。
- 答案（标准答案/解析）只能在 `submitted` 之后开放：`openReferenceAnswer` 需 `state ∈ {submitted, verified}` 且指纹一致，否则 `SOLVE_NOT_SUBMITTED` / `QUESTION_VERSION_CHANGED`；开放即记录 `judgeOpenedAt`。原 `answerData` 无门禁调用路径删除（可留内部别名，同样走门禁）。
- **核验结论按小问分别保存**：`recordVerification(questionId, conclusion)` 需已开放答案，否则 `JUDGE_NOT_OPENED`；`questionId` 必须属于该 run 的题组，否则 `QUESTION_NOT_IN_GROUP`。每个小问的 `verdict`／`matched`／`missed`／`wrong`／`disputed`／`correction` 存在 `conclusions[qid]`；**题组内所有小问都归档后** state 才变 `verified`（`verifiedAt` 取各小问归档时间的最大值），部分归档时仍是 `submitted`，并返回 `pendingQuestionIds`。
- 讲稿 `assembleExplanation(questionId, audience)` 需题组全部小问已核验且指纹一致，否则 `EXPLAIN_NOT_VERIFIED` 并带 `solveStatus` 与未归档小问；返回本小问的 `conclusion` 与题组全部 `conclusions`、`verifiedCount/questionCount`。
- run 持久化到 `<outputPath>/solve-runs.json`（最多保留 200 条），重启后仍可核验/讲题；旧记录（只有单条 `conclusion`）无法判定归属，加载时丢弃旧结论并保留独立作答、回到 `submitted`，要求按小问重新核验；题组扩容同样要求重验。
- `核验完成` 表示"答案开放 → 题组内各小问对照结论均已归档"这一顺序已完成，**不等于内容正确**。

### 8.4 core 新增/调整 API

```js
prepareSolve(questionId, { fresh? })  // 题答分离 + 题面指纹；返回 runId/questionFingerprint/state/
                                     //   group/material/questions/questionImages/reused/answerOrigin/answerSessionId，
                                     //   boundaryIssues 成功路径为空数组 []；有边界问题时走错误分支
                                     //   QUESTION_BOUNDARY_UNCERTAIN（不返回半成品 run）
                                     //   fresh=true 强制新建 run（重新独立作答），默认复用同指纹作答
recordIndependentAnswer(runId, x)     // 插件专用；保存独立作答原文 → state 'submitted'
solveStatus(questionId)               // { state, runId, fingerprintMatches, submittedAt, judgedAt,
                                      //   questionIds, conclusions, pendingQuestionIds, verifiedCount, canJudge, canExplain }
openReferenceAnswer(questionId)       // 作答提交后才开放答案（整组一次）；记录 judgeOpenedAt
recordVerification(questionId, c)     // 按小问归档对照结论到 conclusions[qid]；全部小问归档后才 verified
assembleExplanation(questionId, aud)  // 需题组全部小问已核验；返回 report + verification（本小问 conclusion + 全部 conclusions）
similarQuestions(questionId, limit)   // 题库检索同类题（设问任务/推理关系/材料特征）；不足返回 insufficient + gap
```

- 保留：`questionData`、`imageRefs`、`analyzeQuestion`、`exportAnalysis`、`styleProfile`、`searchQuestions`、`getTaxonomy*`、`health`。
- 调整：`solutionScaffold` 保留但**只供讲稿骨架内部使用，不再进入解题输入**；删除 `languageGuide` 与对象细则长文本（移入技能 references）；`buildExplainerReport` 的 `schemaVersion` 升为 3，学生/教师四段式新增 `locate.knowledgeRole`、`solve.comparison`、`reflect.transfer`，`audiencePlan` 只留短标签/一句话要求并引用 references；`cacheKey` 继续区分题目指纹、audience、规则版本（规则版本 3）。

### 8.5 工具契约（注册到 geo-teacher 预设层，直接对象注册、无 import）

工具描述只写用途、参数与前置条件（**每条 ≤ 350 字符**），教学话术与细则一律移入技能。

| 工具 | 阶段 | 输入 | 输出 |
| :--- | :--- | :--- | :--- |
| `geo_solve` | Solver | `qid`；可选 `fresh:true` | 隔离会话独立作答 + `runId` + `state:'submitted'` + 关键依据；`reused` 时不重新解题，并返回 `answerOrigin` 与 `answerSessionId` 说明作答来自哪个隔离会话；渲染标题「独立作答（隔离会话）」并区分“本次新建/复用已有隔离作答” |
| `geo_judge` | Judge | `qid`；归档时 `qid, conclusion` | 无 `conclusion`：门禁开答案，返回独立作答 + 标准答案/解析/采分点/覆盖网格/干扰项目标，并提示再次调用归档；有 `conclusion`：按小问归档到 `conclusions[qid]`，题组全部归档后才 `state:'verified'`，否则仍 `submitted` 并返回 `pendingQuestionIds` |
| `geo_explain` | Explainer | `qid, audience`（`student` 默认／`teacher`／`setter`） | 只读题组内全部小问已核验的 run：讲稿 report + `verification:{status:'verified', evidence:'server_run_record', questionId, conclusion, conclusions, verifiedCount, questionCount, …}` + comparison + variants；**不再接收** `independentAnswer`／`judgeReport` |

> 技能分工：`skills/geo-solver.md` 是隔离解题会话的 persona 正文来源（独立读题/读图/推导/作答方法）；`skills/geo-question-explainer.md` 是流程编排与交付要求；学生/教师/命题人的具体写法、语言文体与同类题比较规范只写在 `skills/references/explainer-audiences.md`。

- **core**：题答分离、题面指纹、run 持久化、两阶段核验门禁、`similarQuestions`、`buildExplainerReport` 规则版本 3（删 `languageGuide` 与重复细则）；`solutionScaffold` 不再进入解题输入。插件修改后完整重启桌面并验收。

### 8.7 风险与边界

- 模型"主会话自解 / 提前看答案"倾向 → 隔离子会话工具锁（`tools.restrict` 隐藏 + `tools.guard` 拒绝） + 服务端门禁（作答提交后才开答案）+ 技能强约束；隔离能力缺失即报错，不静默回落。
- 采分点/设问类型判定/维度扫描为启发式（题库格式不统一），失败时降级（提示按材料组织），不阻断。
- 涉图题只交付题面图片；解析图永不进入解题输入；`complete` 不证明模型读图正确。
- 讲题稿必须教学化重组，不得照抄解析原文。
- 同类题比较依赖题库检索，候选不足时明确缺口，不编造通用套路。
- 内部解题预设注册、子会话隔离、图片交付、run 持久化与两阶段核验均**只有源码实现**，运行时要等完整重启 DSH 后验收。

**P4 · 真题评测（20–30 道，教师人工）**

- 评测指标（优先验证）：
  1. **答案正确率**（选择判对错；综合要点与标准答案匹配度）
  2. **证据准确性**（解题依据的材料线索是否真实、有无编造）
  3. **推理链完整性**（每步推导是否有关联依据、有无跳跃）
  4. **采分点覆盖率**（综合题要点覆盖标准采分点的比例）
  5. **干扰项解释质量**（选择题每个干扰项错因是否讲清）
- 门槛：正确率与覆盖率达标（具体阈值由评测样本确定）后才进入 P5；不达标则迭代 P1–P3（solver 方法论/骨架规则）。
- **🟡 脚手架已就位（2026-08-15）**：题库实盘扫描（95 题组：选择 65 / 综合 30，省份 安徽/山东/广东/浙江/海南/湖南/福建，年份 2024–2025）产出**分层抽样清单**（7 省 × 选择+综合，14 题组 ≈ 30+ 小题）+ **单题五项指标打分表**，见 `docs\讲题评测方案.md`。**待教师人工评测**：按方案逐题打分并汇总，达标（平均≥0.8、正确率≥0.85）后进 P5。

**P5 · 插件整合**
- 接入现有 analysis 插件（solve/judge/explain 路由 + 工具）、真题库检索、变式推荐；
- 挂载验证 + HTTP 冒烟 + 回归（现有真题分析/蓝图不受影响）。

**P6 · UI 与展示层**
- 面板「讲题」标签（四段式渲染 + 定位卡 + 变式跳转 + 对象选择 + 无答案练习支架）、年级适配、使用指南更新。

**总体顺序**：**Solver → Judge → Explainer → 真题评测 → 插件整合 → UI**——先保证"题能真正做对"，再解决"怎么讲得像老师"。

## 十、验收标准

**P1 门（题答分离与隔离解题）**：解题输入只含材料/题干/选项/小问/题面图片，不含答案、解析、解析图、知识点提示；隔离解题会话为全新上下文、不开放任何工具（`tools.restrict` 隐藏 + `tools.guard` 拒绝，子会话 request header 的工具目录为空）、不继承主会话历史，隔离能力缺失返回 `SOLVER_ISOLATION_UNAVAILABLE` 且不回落主会话；边界不明返回 `QUESTION_BOUNDARY_UNCERTAIN` 并指出具体题目。
**P2 门（作答提交与两阶段核验）**：未提交不能取答案（`SOLVE_NOT_SUBMITTED`）；题面变化旧 run 失效（`QUESTION_VERSION_CHANGED`）；未开放答案不能归档（`JUDGE_NOT_OPENED`）；独立作答原文由服务端保存、模型不能改写；run 持久化到 `solve-runs.json`，重启后仍可核验。
**P3 门（讲稿只读 verified）**：未核验不能生成讲稿（`EXPLAIN_NOT_VERIFIED` 并带 `solveStatus`）；`geo_explain` 不再接收独立答案/核验报告；讲题稿为「题目定位—审题—破题—反思迁移」四段式（学生/教师对象），命题人按独立结构交付，含四问论证、设问类型化组织与**以题库检索为依据的同类题比较**。
**P4 门（核心门槛）**：20–30 道真题教师人工评测，五项指标（答案正确率、证据准确性、推理链完整性、采分点覆盖率、干扰项解释质量）达到约定阈值；独立性指标只基于隔离会话输出；答案提前访问、题答图片分离、作答绑定三项检查全部通过；未达标则回炉 P1–P3。
**P5 门**：analysis 插件整合后 solve/judge/explain 路由与工具可用，现有真题分析/蓝图回归通过。
**P6 门**：面板「讲题」标签渲染四段式（定位卡/审题/破题/反思迁移）+ 对象选择 + 无答案练习支架 + 年级适配；README 与使用指南更新。
**运行时验收门**：本轮（2026-11-06）改动只有源码实现，**必须完整重启 DSH 后**逐项实测：内部解题预设注册与子会话隔离、题面图片/解析图分离、run 持久化、两阶段核验门禁、四题三对象内容评审。源码检查通过不算运行时验收。

## 十一、讲题三对象（v4.0 现行）

三对象改造的完整内容规范见 `.agent-presets/geo-teacher/skills/references/explainer-audiences.md`；执行方案见 `docs\讲题功能三对象改造方案-DSH-0.1.7-rc.2.md`（历史文件，见 Git 历史）；本轮实施记录见 `docs\讲题三对象改造-实施记录.md`（历史文件，见 Git 历史）。

### 11.1 参数与默认行为

- `geo_explain` 增加 `audience`：`student`｜`teacher`｜`setter`，中文显示"学生／教师／命题人"；**省略即 student**，非法枚举返回输入错误（不静默回退）。
- 路由判据按用户实际诉求，而非用户身份：仅因为使用者是教师，**不自动**选 teacher。
- 默认只生成一个对象；用户要求多版本才并列输出。
- 切换对象而题目未变时复用服务端 `verified` run，只重新组织讲稿；**题面指纹变化（旧 run 失效）或答案依据变化后必须重新解题并重新核验**。
- 缓存键区分题目指纹、audience 与讲稿规则版本，防止切换对象返回旧稿。

### 11.2 四维内容融入四段式

学生与教师共用「题目定位—审题—破题—反思与迁移」，四维（知识、解题过程、方法总结、跨学科）融入段内，**不另设替代四段式的顶层目录**。四段式相同不等于正文相同：去掉对象标题仍应能识别服务对象。

| 维度 | 学生 | 教师 | 命题人 |
| :-- | :-- | :-- | :-- |
| 知识 | 学什么、何时想到、怎样使用、适用条件 | 教什么、重点与难点及原因、知识联系、突破方式 | 考什么、实际任务是否有效承载目标 |
| 解题过程 | 如何起步、选择角度、连接证据和原理、检查判断 | 怎样启发学生自主提出问题、选择角度、寻找证据、解释机制和检验判断，逐步撤去支架 | 材料和设问如何引发认知操作、是否可绕开考点；设问、材料、选项中的干扰及其认知作用 |
| 方法总结 | 下一次如何独立组织思考及调整 | 怎样从个例引导概括、纠正过度概括、检测迁移 | 是否测到迁移、是否仅靠记忆套路即可完成 |
| 跨学科 | 换一个视角帮助理解与求解 | 何时引入、怎样搭桥、前置知识和误解防范 | 是否服务目标、材料是否交代必要知识、有无暗中超纲 |

### 11.3 学生对象与教师对象

- **学生对象**：保留当前引导式讲课口吻、无寒暄、思维显性化、答案由推理自然引出、以方法收束；重点写"下一步可以做什么以及为什么"。知识点、解题过程、方法总结、跨学科融入四段，不强制第五个顶层章节。
- **教师对象**：沿用四段式，但"审题—破题"重点转为学生思维的启发与培养，"反思与迁移"重点转为总结方法的引导和独立迁移检测。正确解题逻辑必须清楚，**主体篇幅用于如何让学生产生、检验和修正想法**。关键节点按「思维培养目标→问题/活动→学生思维动作→关注的回答及依据→分支追问与必要支架→撤去支架后的独立表现」组织，但不要求每步都出长表；避免连续使用只需回答"是/否"的诱导问题；没有真实学情时只提出待验证障碍，"粗心"不得替代具体错误环节分析。

### 11.4 命题人对象

结构：**考查目标 → 情境/材料/设问 → 设问、材料与选项的干扰辨析 → 预期认知路径 → 答案成立条件及错误路径 → 迁移与跨学科设计 → 题组和质量评价。**

- 选择题检查唯一性及干扰项机制；综合题检查合理答案范围、评分依据和开放性。
- 无原作者说明时标注"依据题面推断"；**无试测数据时不生成正确率、区分度数值或实际测量效果断言**。
- **三层干扰辨析（必检）**：设问层、材料（含图表）层、选项层。错误选项称"干扰项"；设问、材料中的相关内容称"干扰信息/干扰机制"。每个确认存在的干扰给出：位置及原文/图表证据 → 可能诱发的错误思路 → 辨别所需的知识或证据 → 对考查的作用 → 质量判断（有效认知辨析／无效噪声／歧义风险）。
- 综合题将选项层标为不适用，可分析典型偏离思路，但不得虚构选项；某层未发现干扰时如实说明，不强凑三层。
- 负例约束：不把必要限定误判为文字陷阱，不把必要背景、其他小问所需信息或未用于最终答案的内容一律判作干扰。

### 11.5 核验状态

`geo_explain` 返回的核验状态来自**服务端 run 记录**，不再由调用方传入材料推断：返回 `verification: { status: 'verified', evidence: 'server_run_record', questionId, judgedAt, questionCount, verifiedCount, conclusion, conclusions, message: '核验状态来自服务端运行记录：答案在作答提交后开放，题组按小问分别归档核验结论；不证明内容正确。' }`。只有题组内**全部小问**已归档且题面指纹一致才生成讲稿，否则返回 `EXPLAIN_NOT_VERIFIED` 并带 `solveStatus`（含 `state`、`pendingQuestionIds`、`fingerprintMatches`、`canJudge`、`canExplain`），不静默吞错。讲稿读取的是**请求小问自己的** `conclusion`；`conclusions` 含题组全部小问结论。**核验完成不等于内容正确**；参考解析有疑点时保留 `disputed`。原「提供材料待核验」（`verified: false`、`evidence: self_reported_material`）已废弃。

### 11.6 交付形态

- 面板暂无讲题入口与对象选择控件；对象选择经会话工具模式的 `audience` 参数完成。
- 无答案练习支架是学生对象的**可选附加交付**，不与会话对象混为同一模式。
