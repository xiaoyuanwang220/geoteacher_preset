# 讲题功能设计文档（geo-explain）

> 版本：v3.0（设计稿）　日期：2026-08-15　状态：待评审后实施
> 修订沿革：
> - v1.0：初稿（设问先行、地理思维锚点、分题型四段式讲题稿）。
> - v2.0：① 解题与讲题分离（agent 独立解题，不依赖答案）；② 思维显性化深入为"四问论证"；④ 综合题采分点改为"要素维度排查法"。
> - v2.1：③ 设问拆解去机械化扩展为**按设问类型系统化**（原因/影响/过程/比较/评价/措施/分布等）。
> - **v3.0：开发实施顺序重构**——**Solver → Judge → Explainer → 真题评测 → 插件整合 → UI**。先保证"题能真正做对"，再解决"怎么讲得像老师"；解题能力（solver）作为独立可评测的组件优先开发，讲题与展示层最后接入。
> 面向对象：高中地理一线教师与师范生；以「应试地理教学」为核心视角。
> 配套：`geo-teacher-agent-plan.md`（插件化方案）、`使用指南.md`。

## 一、功能定位与目标

**定位**：对真题库中任一道真题，生成「如何解题」的讲题稿——一步步教学生读材料、拆题目、讲清解题步骤与思路，培养地理思维与应试能力。

**核心原则（v3.0 定稿）**：

1. **题能真正做对，是一切的前提**：solver（独立解题）先行开发并评测达标，explainer（讲题）建立在已被 judge 验证过的解题过程之上；不先做对题，讲得再像老师也是错的。
2. **解题与讲题分离，讲题不依赖答案**：solver 只给题目（材料+题干+选项/小问），不给答案/解析，独立完成审题、证据提取、知识激活、推理链构建、作答；答案/解析由 judge 环节开放，仅用于核验（得分点覆盖、推理错误、遗漏分析）。讲题教的是**思维过程**，不是把答案翻译成话术。
3. **设问先行**：先看问什么（对象/动词/限定词），带着问题定向读材料；但**不是机械规则**——设问拆解落到**设问类型化的组织逻辑**（见 §五），不套"自然原因+人文原因"式模板。
4. **地理思维显性化 + 四问论证**：不只标注思维类型，每个推理都要能回答四个"为什么"（见 §四）。
5. **分题型讲法**：选择题讲"排除链+错因"，综合题讲"采分点组织+术语"。
6. **带评分视角**：讲题落到分值、采分点、表述规范。
7. **可迁移**：讲完提炼"一类题"的思维模板，并给出变式练习。

**与现有功能的关系**：

| 功能 | 视角 | 回答的问题 |
| :--- | :--- | :--- |
| 真题分析（已有） | 命题者/考情 | 这道题**为什么这样考**（题型/情境/素养/难度/考点映射） |
| 命题蓝图（已有） | 命题者 | **下一道**题怎么设计（情境换新/设问设计/选项设计） |
| **讲题（本功能）** | **教师/解题者** | **怎么教学生做这道题**——solver 独立解题 → judge 核验 → explainer 教学化重组 |

## 二、总体架构：三组件流水线（Solver → Judge → Explainer）

```
        ┌─────────────────────────────────────────────────────────┐
        │  组件独立性：三个阶段先作为「独立工具 + 技能」开发评测，  │
        │  核心解题能力稳定后，再整合进 plugins/analysis 插件。    │
        └─────────────────────────────────────────────────────────┘

 题目（材料+题干+选项/小问，无答案）
        │
        ▼
┌───────────────────────────────────────────────────────────────┐
│ 【1】geo-solver 独立解题（最小可用，最先开发）                    │
│   输入：题目（geo_solve 工具，不含答案/解析）                     │
│   流程：审题（设问类型框架）→ 证据提取（定向读材料/读图）          │
│        → 知识激活（为什么用这个知识）→ 推理链（每步有依据）        │
│        → 作答（选择：选哪项+理由；综合：写要点）                  │
│   输出：解题思维轨迹（证据-知识-结论 三元组 + 逐项排除/要点组织）   │
└───────────────────────────────────────────────────────────────┘
        │  独立答案（未被答案污染）
        ▼
┌───────────────────────────────────────────────────────────────┐
│ 【2】geo-judge 核验（第二步开发）                                │
│   输入：独立答案 + 标准答案/解析（geo_judge 工具，&answer=1）     │
│   分析：得分点覆盖 / 推理错误 / 要点遗漏 / 干扰项解释质量         │
│   输出：核验报告（对在哪、错在哪、漏在哪、为什么）                │
└───────────────────────────────────────────────────────────────┘
        │  已验证的解题过程
        ▼
┌───────────────────────────────────────────────────────────────┐
│ 【3】geo-explainer 讲题（第三步开发）                            │
│   输入：已验证解题过程（solver 轨迹 + judge 核验）               │
│   输出：讲题稿「题目定位—审题—破题—反思迁移」                     │
│        （选择题/综合题分述；四问论证；设问类型化组织；易错/变式）  │
└───────────────────────────────────────────────────────────────┘
        │
        ▼
【4】真题评测（20–30 道，教师人工） → 【5】插件整合 → 【6】UI
```

**三组件职责边界**：
- **solver 管"做对"**：独立解题质量（答案正确率、证据准确性、推理链完整性、采分点覆盖率、干扰项解释质量）是评测对象；
- **judge 管"对照"**：开放答案后客观核验，产出可复核的偏差分析；
- **explainer 管"讲"**：只消费 solver+judge 的已验证结果做教学化重组，**不再重新解题、不直接接触原始答案推导讲法**。

> 说明：现有 `geo_question_detail` 返回的材料+题干+选项**不含答案/解析**，天然适配 solver 阶段；答案/解析由 judge 的 `geo_judge?answer=1` 独立暴露。

## 三、教学模型：讲题稿结构（Explainer 的产物模板）

**设问先行 → 定向读材料**，每一步挂地理思维锚点：

| 步骤 | 内容 | 地理思维锚点（讲给学生听） |
| :--- | :--- | :--- |
| **1 拆设问（先行）** | 先看问什么：对象 + 行为动词 + 限定词 → 判定思维层级与**设问类型**（见 §五，不机械套模板） | 综合思维入口："'分析'要因果链，'评价'要分利弊，'比较'要同口径指标；'原因'要分清直接/根本/触发/加剧" |
| **2 带着问题读材料** | 定向阅读：按设问对象锁定要找的要素证据（位置/地形/气候/水文/人口/产业/交通…），定区域与尺度 | 区域认知 + 目的性阅读："设问指向产业区位→只盯区位要素；先定位区域→激活区域常识，再找材料证据"；点明干扰信息为何是干扰 |
| **3 知识选择** | 明确"**为什么要用这个知识**"：题目哪些线索激活了哪个原理/概念 | 综合思维：知识不是背出来的，是由题目线索+区域特征选出来的 |
| **4 推理链** | 材料证据 × 知识 × 设问 → 地理因果链 / 逐项排除；每步标注"**为什么能推出下一步**" | 综合思维+区域认知：前提→结论的因果显性化 |
| **5 作答与检查** | 地理语言规范、采分点组织（要素维度排查，见 §六）、易错点 | 人地协调观：答案带条件限定与辩证 |
| **6 方法提炼** | 升维成可迁移的地理思维模型 | 把"这道题"变成"这一类题的思维模板" |

## 四、地理思维显性化：四问论证（solver 轨迹 + 讲题稿共用）

**每个关键推理**都必须回答四个"为什么"，缺一即视为不达标（solver 产出、explainer 讲出）：

1. **为什么用这个知识解答**（知识选择依据）：题目里哪个线索（区域名/要素词/数据/设问词）让你调用了这条知识？换一个区域是否还用同一知识？
2. **为什么依靠这条材料**（材料使用依据）：这句材料支撑哪个推断？删掉它结论还成立吗？哪些材料是无关/干扰信息？
3. **这一步为什么能推出下一步**（推理链条因果）：这一步的前提是什么？到下一步的逻辑缝隙在哪（要素A→现象B→结果C，每段都有依据）？有没有跳跃/想当然？
4. **这题为什么不是另一个答案**（排除论证）：选择题：每个干扰项错在哪（绝对化/因果倒置/偷换概念/无中生有/程度失当），正确项为何必须由材料推出；综合题：备选要点为何不取（材料不支持/答非所问/与设问不匹配）。

**技术支撑**：骨架为每个推理输出"证据-知识-结论"三元组与干扰项错因（复用 `detectDistractors`）。

## 五、设问拆解：设问类型化的答案组织框架（去机械化）

**总原则**：每种设问都有它"该按什么逻辑组织答案"的方式，但都**以题目材料为据**——材料支持的层次才写，禁止机械套模板（如"分析原因"就一律写"自然原因＋人文原因"）。

| 设问类型 | 该组织什么逻辑（而非机械模板） | 讲题时要点明 |
| :--- | :--- | :--- |
| 分析原因/成因 | 按因果层次：**直接原因 → 根本条件 → 触发因素 → 加剧因素**；材料没提的层次不硬凑 | 现象与因素之间的因果链；哪些是"底牌"、哪些是"扳机"、哪些是"放大器" |
| 影响/意义/作用 | **分主体**（对自然/对人文，受益/受损）+ **分层次**（直接—间接、短期—长期）+ 经济/社会/生态维度，按材料支持的组织 | 影响的传递链（谁→怎样→导致什么）；"意义"要落到发展与人地关系 |
| 形成过程/演变 | 按**阶段与时间顺序**组织：环节链（如流水地貌：侵蚀→搬运→堆积）、每阶段驱动因素、动态变化 | 过程的先后与因果；不是静态罗列，而是"怎么一步步变成的" |
| 比较/差异 | **可比指标 + 同口径 + 区域限定**；只比较材料与知识支持的方面 | 用什么指标比、口径是否一致、结论是否可迁移 |
| 评价/是否合理/利弊 | **分主体利弊 + 代价与可行性 + 适用条件** | 受益者与受损者、成本与风险、结论有前提 |
| 措施/对策/治理 | **针对性（对应原因/问题）+ 分主体（政府/企业/个人）+ 可行性** | 措施为什么能解决这个问题（对症）；谁来实施、能否落地 |
| 分布/特征描述 | **空间方位/范围/形状/集中或分散 + "随××变化" + 数据支撑** | 描述要有位置/方向/数值依据，不是形容词堆砌 |
| 变化/趋势 | 时间尺度的**动态表述**（方向+幅度+速率），区分现状/过程/预测 | 什么在变、变多快、往哪变 |

- 骨架输出 `questionFramework`（由设问动词+对象+材料线索判定**类型**与**组织提示**），但**具体组织由模型按材料实际支撑来**；
- 设问动词相近但对象不同（如"分析甲的影响"与"分析乙的影响"）→ 组织逻辑相同，内容由对象决定。

## 六、综合题采分点：要素维度排查法（solver 作答与 judge 核验共用）

分值→要点数是表层；**关键是要点怎么找**。方法：**逐维度扫描题目材料，看材料支持哪几个维度**，再按因果逻辑组织成要点：

- **自然维度排查清单**：位置/地形/气候/水源/土壤/生物（+灾害）；
- **人文维度排查清单**：人口/农业/工业/服务业/交通/市场/政策/技术；
- **操作**：对每个维度问"材料里有没有这个维度的证据？"——**有证据的纳入，无证据的排除**，绝不把五个自然维度全写上；
- 纳入的维度再按"直接原因→根本条件→触发→加剧"或设问要求排序，形成采分点（每点：要素 + 证据 + 结论）。

**技术支撑**：骨架的 `dimensionScan` 输出各维度的**材料命中证据**（检测到"气候"→材料含降水/气温线索）；solver 据此组织要点，judge 据此核对覆盖。

## 七、实战讲题稿模型（Explainer 产物：分题型四段式）

**① 题目定位卡**（给教师快速决策）
题型（选择/综合）· 难度（基础/中档/压轴）· 年份省份题号 · 分值 · 是否涉图 · 主导素养与思维类型 · 建议讲解时长 · 建议年级

**② 审题（设问先行 + 设问类型框架）**
- 拆设问：对象 + 行为动词 + 限定词 → 思维层级 + **设问类型**（原因/影响/过程/比较/评价/措施/分布…→ 对应组织逻辑，见 §五）
- 明确"要答什么方向"

**③ 破题（分题型）**
- **选择题**：读图（涉图时独立：图例→坐标→数值→分布→趋势）→ 定向读材料 → 逐项排除链（每项：材料证据 × 知识 × 设问；正确项证据、干扰项错因）→ 四问论证覆盖（尤其"为什么不是别的选项"）
- **综合题**：读图/定向读材料 → 设问分层 → **要素维度排查**（材料支持的维度 → 采分点组织：分值→要点→每点表述→逻辑顺序）→ 术语规范

**④ 反思与迁移**
- 易错警示：基于"独立解题 vs 答案核验"的偏差（judge 产出）+ 常见错误（答非所问/漏维度/术语不规范）
- 方法提炼：一类题的思维模板（可迁移）
- 变式链接：同考点/同设问真题 1–2 道

**学生版（可选）**：不给答案，给支架——提示性问题、空格、引导性设问，保持认知负荷。

## 八、技术落地（按三组件拆分）

### core 新增方法（三个组件共用的确定性支撑，均不产生教学话术）

```js
questionData(qid)        // 题目数据（材料/题干/选项/小问），绝不含答案/解析 —— solver 用
solutionScaffold(qid)    // 审题骨架：questionFramework（设问类型+组织提示）、thinkingModes、
                         //   focusElements、dimensionScan（各维度材料命中证据）、
                         //   干扰项错因（复用 detectDistractors）—— solver 用
answerData(qid)          // 标准答案/解析 + 倒推采分点 scorePoints —— 仅 judge 用，需显式授权
variants(qid)            // 同考点变式候选（复用 collectSamePointContexts）—— explainer 用
```

### 工具（注册到 geo-teacher 预设层，直接对象注册、无 import）

| 工具 | 阶段 | 输入 | 输出 |
| :--- | :--- | :--- | :--- |
| `geo_solve` | Solver | qid | 题目 + 审题骨架（**无答案/解析**）→ 模型独立解题并产出解题轨迹 |
| `geo_judge` | Judge | qid, 独立答案 | 标准答案/解析 + 核验分析（得分点覆盖/推理错误/遗漏/干扰项解释质量） |
| `geo_explain` | Explainer | qid | 讲题稿（消费 solver 轨迹 + judge 核验；**内部不再看答案推导**） |

> 技能侧配套 `skills/geo-solver.md`（独立解题方法论）与 `skills/geo-question-explainer.md`（讲题方法论），frontmatter 齐全；solver 技能先开发，explainer 技能在其稳定后开发。

### 关键机制：答案不参与解题
- `geo_solve` **不含答案/解析**——模型独立解题；
- `geo_judge` 才开放答案——仅用于核验；
- 流水线顺序由技能与工具契约强制：**solve → judge → explain**；solver 阶段读取答案视为失败。

### 各层改动
- **core**：`questionData/solutionScaffold/answerData/variants` + 要素词表/动词表/设问类型判定规则/维度扫描；改后同步双副本；
- **analysis**（P5 整合）：`/geo/analysis/solve|judge|explain` 路由 + 三工具；
- **ui**（P6）：详情页「讲题」标签（四段式 + 定位卡 + 变式跳转；标注"解题轨迹/核验"区分）、学生版支架、年级适配；
- **复用点**：分析引擎全部 + collectSamePointContexts + groupInfo + loadBank——零重复开发。

### 风险与边界
- 模型"solve 阶段偷看答案"倾向 → 工具默认不含答案（机制隔离）+ 技能强约束；
- 采分点/设问类型判定/维度扫描为启发式（题库格式不统一），失败时降级（提示按材料组织），不阻断；
- 涉图题素材只描述图类型与读图步骤，不渲染图形；
- 讲题稿必须教学化重组，不得照抄解析原文。

## 九、实施步骤（v3.0 定稿：Solver → Judge → Explainer → 评测 → 整合 → UI）

**P1 · Solver（最小可用，最先开发）**
- core：`questionData` + `solutionScaffold`；`geo_solve` 工具；
- 技能 `skills/geo-solver.md`：审题（设问类型框架）→ 证据提取 → 知识激活 → 推理链 → 作答的独立解题方法论（含四问自检）；
- 验证：模型**不读答案**能对单题完成审题/证据提取/知识激活/推理链/作答，解题轨迹含证据-知识-结论三元组。

## 十、验收标准

**P1 门**：`geo_solve` 返回题目+骨架**不含答案/解析**；模型独立完成审题→证据提取→知识激活→推理链→作答，轨迹含证据-知识-结论三元组。
**P2 门**：`geo_judge` 开放答案并产出可复核的得分点覆盖/推理错误/遗漏/干扰项解释分析。
**P3 门**：讲题稿为「题目定位—审题—破题—反思迁移」四段式，选择题/综合题分述，含四问论证与设问类型化组织，源自已验证解题过程。
**P4 门（核心门槛）**：20–30 道真题教师人工评测，五项指标（答案正确率、证据准确性、推理链完整性、采分点覆盖率、干扰项解释质量）达到约定阈值；未达标则回炉 P1–P3。
**P5 门**：analysis 插件整合后 solve/judge/explain 路由与工具可用，现有真题分析/蓝图回归通过。
**P6 门**：面板「讲题」标签渲染四段式（定位卡/审题/破题/反思迁移）+ 学生版支架 + 年级适配；README 与使用指南更新。
