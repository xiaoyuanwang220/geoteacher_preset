## 1. 目标与本期边界

目标：别人 `git clone` 后能按 README 三步直接用起来，不必懂 profile、bundle、数据路径。

```
git clone → node scripts/setup.mjs → 重启 DSH → 选择「地理教师辅助」
→ 在原生输入区选「讲题／出题／课程方案」，发题号或需求
```

工作台沿用现有输入区 UI 插件（`packages/dsh-geo-teacher-ui`，用户已确认界面符合需求），**本期不改它的界面**。

本期交付四项：

| # | 交付 | 说明 |
| :-- | :-- | :-- |
| 1 | 安装器 `scripts/setup.mjs` | 校验、备份、写 profile 清单、安装依赖并建立链接、静态校验、卸载 |
| 2 | 示例数据 | 包内自编示例题库 + 演示考点库；core 单一解析逻辑；health 标注来源 |

| 4 | README 快速开始 | 首屏三步；修正“题库必填”等与演示模式冲突的表述 |

## 3. 安装：真实步骤（不能只改 package.json）

### 3.1 先明确三个事实

1. Desktop profile 由 Electron 应用独占：外部 `dsh plugin --profile desktop …` 会被 CLI 明确拒绝，安装器必须**直接操作 profile 目录**（与桌面「插件管理器」的底层行为一致）。
2. 插件解析从 profile 的 `node_modules` 出发：`dsh-app-boot` 把 profile `node_modules` 里的 pnpm 托管条目接给 Node 解析器。因此**只写清单不安装 = 不会加载**，必须跑一次 pnpm install 生成链接。
3. DSH 启动**不会自动安装**依赖；启动时只会补齐 `pnpm-workspace.yaml` 等脚手架。安装动作必须由安装器显式完成。

### 3.2 步骤（`scripts/setup.mjs`）

| 步骤 | 行为 | 失败处理 |
| :-- | :-- | :-- |
| 0 前置 | 读 `DSH_HOME`（缺省 `~/.dsh`）、确认 profile 目录存在、读 `runtime.json` 得 DSH 版本；取运行时自带 Node/pnpm（`<DSH_HOME>/dsh-runtimes/dsh-primary-runtime/dependencies/{node,pnpm}`） | 缺 DSH 安装或版本 `< 0.2.1` 时停止并给出升级指引 |
| 1 `--check` | 只读：版本、profile、两个包目录与 `cordis.patch.yml` 是否存在、当前清单与 bundles 状态、`node_modules` 链接状态；打印将要做的修改 | 不写任何文件 |
| 2 备份 | 复制 `profile/package.json` 与 `profile/pnpm-lock.yaml`（存在时）到 `profile/.geo-teacher-setup/<时间戳>/` | 备份失败则停止 |
| 3 写清单 | `dependencies` 增加 `@geo-edu/dsh-geo-teacher-preset`、`@geo-edu/dsh-geo-teacher-ui`（`link:<仓库绝对路径>`，Windows 用正斜杠）；`dsh.profile.bundles` 追加这两项（保持既有顺序，已存在则跳过） | 写入前展示 diff；`--yes` 才落盘（可 `--dry-run` 只打印） |
| 4 安装依赖/建链接 | 在 profile 目录执行：`node <pnpm> install --prefer-offline --no-frozen-lockfile`；随后确认 `node_modules/@geo-edu/…` 为指向仓库的符号链接 | 安装失败时从第 2 步备份恢复清单与 lockfile，并重跑 `pnpm install`（有 lockfile 用 `--frozen-lockfile`，无 lockfile 用 `--config.lockfile=false`）；**不承诺“完全恢复原状”** |
| 5 数据 | 不写死数据路径：生成/补齐 `~/.dsh/geo-teacher/config.json` 时**只补缺失键**；数据路径留空即演示模式（§4） | 已有配置不覆盖 |
| 6 静态校验 | ① 清单 JSON 可解析且 bundles 含两项；② 从 profile 目录 `createRequire(...).resolve('@geo-edu/dsh-geo-teacher-preset/package.json')` 与 UI 包均成功；③ 两包 `cordis.patch.yml` 可达 | 任一项失败：打印具体项并返回非 0 |
| 7 重启与验活 | 打印“完全退出 DSH 再启动（关窗可能只是隐藏）”；重启后选「地理教师辅助」会话，输入 `/geo-status`：命令存在即证明 preset/UI 已加载 | 人工步骤；`/geo-status` 输出可用于排障 |

补充：
- `--uninstall`：按 §3.3 精确移除。
- `--with-modelcheck` **不提供**（见 §7）。
- 可加 `--profile <name>`（默认 `desktop`），但 Desktop 以外的 profile 仍走同一套 pnpm 流程。

### 3.3 卸载（明确删什么、留什么）

| 删除 | 保留 |
| :-- | :-- |
| profile `dependencies` 中两个 `@geo-edu/…` 键 | `~/.dsh/geo-teacher/config.json`（用户数据路径） |
| profile `dsh.profile.bundles` 中两个包名 | `outputs/`、`solve-runs.json`、题库/考点库、会话记录 |
| 执行一次 pnpm install 同步 `node_modules` 链接 | pnpm store、pnpm-lock.yaml 的历史内容（不手工重写） |
| `profile/.geo-teacher-setup/` 内的备份可由用户自行删除 | 仓库本身（不删除） |

**不承诺**“恢复原状”：lockfile 的解析结果、pnpm store、桌面启动时的脚手架文件都可能与安装前不同；只承诺“移除本项目的依赖与 bundle 项，且不影响其他已装插件”。
**不自动卸载 ModelCheck**（即使当前机器装过）：它不是本期安装器安装的组件。

### 3.4 安装器不采用的方式

- 不使用 `dsh plugin --profile desktop`（CLI 拒绝外部管理 desktop）；
- 不发布 npm 包（既有决策：只发 GitHub，安装以 `link:` 为准）；
- 不修改 DSH 安装目录或系统环境变量；
- 不写死机器路径（仓库路径由脚本运行位置计算）。

## 4. 示例数据：统一位置与单一解析逻辑

### 4.1 位置（唯一）

全部放在 **preset 包内**，不往仓库根另放一份：

```
.agent-presets/geo-teacher/
  data/
    question-bank-demo/        # 自编示例题库（4 题组，标注“演示数据，非真题”）
      安徽/2026/…选择题组.md
      安徽/2026/…综合题.md
      安徽/2026/…读图题.md
      安徽/2026/…解析图题.md
      附件/…
    knowledge-demo/            # 精简演示考点库（2 个主题文件，覆盖示例题用到的节点）
```

`package.json` 的 `files` 增加 `data/`；`.gitignore` 不排除它。

### 4.2 解析（core 内只有一套逻辑）

新增/收敛为单一 `resolveDataPath(kind)`（`kind = knowledgeBase | questionBank`）：

```
用户配置路径（存在且可用） > 包内 data/<demo 目录> > 视为未配置（health 报 missing）
```

- `/geo/core/health` 增字段：`knowledgeSource`、`questionBankSource`：`user | packaged-demo | missing`；`dataMode: 'demo' | 'user' | 'missing'`。
- 不再保留两处“包内目录自动查找”的分支（现有 `PACKAGED_KNOWLEDGE_DIR` 与实际目录不一致的问题一并修正：要么目录存在，要么删掉该分支）。
- 题库/考点库都是 `packaged-demo` 时，`status` 仍为 `success`，但 `dataMode: 'demo'`；教师配置任一真实路径后即为 `user`。

### 4.3 演示与正式使用（同一套逻辑，不维护两套）

| 模式 | 触发 | 行为 |
| :-- | :-- | :-- |
| 演示 | `config.json` 未提供对应路径（或安装器只补了空白键） | 使用包内示例题库/演示考点库；`/geo-status` 与 `geo_solve` 成功返回都提示“当前为演示数据” |
| 正式 | 教师在 `config.json` 填写 `questionBankPath` / `knowledgeBasePath` | 以教师路径为准；演示数据不再参与 |

README 需要同步修正的表述：
- 删除“`questionBankPath` 必填、否则工具报错”的绝对表述，改为“未配置时使用自编演示题库；正式使用请配置自己的题库”；
- 更新“三个 bundle”为“两个 bundle”（preset + UI），ModelCheck 标为“开发中、不随本期发布”；
- 快速开始只保留三步 + 换题库一行。

## 5. `/geo-status`（本期统一状态入口）

| 项 | 设计 |
| :-- | :-- |
| 形态 | DSH 宿主**命令**（`ctx.commands.register`，名称 `geo-status`，用户输入 `/geo-status`），**不调用模型** |
| 注册位置 | geo-teacher preset 的一个插件行（优先复用 `plugins/analysis` 或 `plugins/panel`，不新增 bundle） |
| 输出 | DSH 版本；profile 名；`knowledgeSource`/`questionBankSource`/`dataMode`；题库题数；索引构建状态；最近一条讲题 run（题号/状态/提交时间）；内部预设是否存在（只作诊断，不引导使用） |
| 用途 | 安装后验活（命令存在 = preset 已加载）、排障、演示模式提示 |
| 边界 | 只读，不写文件、不触发解题；输出控制在十余行内 |

实现前需核对 rc.5 `commands` 契约（definition 字段、handler 返回值 `{kind:'success', text}`、命令名格式）；如发现命令注册受 profile 作用域限制，退化为 `geo_status` 工具并在 README 说明（不另造第二入口）。

## 7. 预设收口：移出本期

- 本期**保留**现有稳定的隔离解题机制：bundle 声明 `geo-solver-internal` + `plugins/solver-isolation`（`tools.restrict` 隐藏 + `tools.guard` 拒绝）。
- **不做**“隐藏内部预设”的重写：不引入插件自建子会话（路线 A），也不做临时注册/注销（C′）。原因：两者都要重写子会话生命周期或依赖未取证的模块解析，收益只是菜单里少一项，风险不成比例。
- README/使用指南继续保留“内部预设可见但勿选”的一句说明；等安装与数据链路稳定后，再单独评估是否值得收口。

## 8. 实施批次与验收

| 批次 | 内容 | 验收（必须可执行） |
| :-- | :-- | :-- |
| 1 | `scripts/setup.mjs`（`--check`/`--dry-run`/安装/`--uninstall`）、README 安装段 | 在**临时 profile 演练目录**（复制 `desktop/package.json`、`pnpm-workspace.yaml`、lockfile 到临时 `DSH_HOME`）上：`--check` 零写入；安装后 manifest/bundles/链接正确；连跑两次幂等；`--uninstall` 精确移除两项且其他依赖不变；失败恢复路径可复现 |
| 2 | 包内 `data/` 示例题库 + 演示考点库、core 单一解析 + health 字段 | 清空配置后重启：`/geo/core/health` 显示 `packaged-demo` 与题数；用示例题跑完整讲题（solve→judge×2→explain），解析图零交付；改 config 为真实路径后显示 `user`；`node --test`、`geo-verify --source` 全绿 |
| 3 | `/geo-status` 命令 + README 快速开始与文档收口 | 重启后在 geo-teacher 会话输入 `/geo-status`，输出 6 类字段且不触发模型；新用户按 README 三步完成安装并讲通一道示例题；docs/README 索引与基线口径一致 |

**更正一处旧表述**：批 1–2 并非“不影响模型行为”。安装器改变 profile 加载与数据来源，批 2 改变 core 的数据解析与 health 输出，都必须按“改代码”验收（完整重启 + 真实会话），不能只跑静态检查。

## 9. 风险与边界

| 风险 | 处置 |
| :-- | :-- |
| `pnpm install` 改写 profile lockfile | 先备份并展示 diff；失败按备份恢复并重装；README 说明这是正常结果 |
| 用户 profile 已有其他插件/配置 | 只增删本项目两项；不重排 bundles；不覆盖 config 已有键 |
| 离线/无网络 | 依赖全是 `link:`，`--prefer-offline` 通常足够；仍失败时打印可复制的离线命令 |
| 跨平台路径 | 用 `fileURLToPath`/绝对路径计算；Windows 转正斜杠；macOS/Linux 同一脚本 |
| 演示数据被误当真实题库 | 目录与题组标题标注“自编演示，非真题”；`/geo-status`、`geo_solve` 返回提示；README 说明替换 |
| 演示考点库覆盖不全 | 只覆盖示例题节点，`/geo-status` 显示来源；正式使用请配置自己的考点库 |
| rc.5 之后版本行为变化 | 安装器只对 `< 0.2.1` 硬拒绝，其余给“未完整验证”提示；待接口清单确认后再考虑 `engines.dsh` |
