# 工作台聚合与一键安装方案

> 状态：**方案（未实施）**　日期：2026-11-06　运行基线：**DSH Desktop `0.2.1-rc.5`**（`runtime.json` 实测；本机 link 部署可用）
> 目标读者：项目维护者（决定发布形态）＋ 首次 clone 的使用者（README 首屏体验）
> 相关：[讲题优化计划](讲题优化计划.md)、[功能插件与技能归属方案](geo-teacher-功能插件与技能归属方案.md)、[使用指南](使用指南.md)、[DSH 基线（待更新）](DSH-0.2.1-rc.2-基线.md)

## 一、要解决的问题

目标不是再加功能，而是把现有能力**收成一个可交付产品**：

```
git clone → 一条安装命令 → 重启 DSH → 打开会话，在原生输入区用「讲题／出题／课程方案」
```

当前离这个目标有四个落差（按影响排序）：

| # | 落差 | 现状 | 对 clone 即用的影响 |
| :-- | :-- | :-- | :-- |
| 1 | 装不上 | 需手工编辑 `~/.dsh/profiles/desktop/package.json` 的 `dependencies` 与 `dsh.profile.bundles`（README「快速开始」） | 最大阻碍；步骤多、路径因机器而异、易漏配 |
| 2 | 没题可讲 | `questionBankPath` 必填且指向外部目录；仓库内无题库 | 装好也跑不了讲题，`geo_solve` 直接报未配置 |
| 3 | 预设列表多一条 | 讲题隔离需要一个独立 agent preset，在选择器里与「地理教师辅助」并列 | 观感凌乱，用户可能误选 |
| 4 | 文档入口散 | README / 使用指南 / 基线 / 多个方案文档各自为政 | 新用户不知道从哪读三步 |

另外有一个**事实需要先纠正**：现行文档基线仍写 `0.2.1-rc.2`，实际运行是 **`0.2.1-rc.5`**（本机实测可用）。本轮源码核对（`app.asar`）读取的也是 rc.5 打包代码，先前的 DSH 接口结论对 rc.5 仍然成立；但**基线文档本身需要换代**，否则后续排障会拿错版本口径。

## 二、目标形态（本项目对「工作台」的定义）

工作台**不新建网页**，沿用现有原生输入区 UI 插件（`packages/dsh-geo-teacher-ui`，用户已确认其界面符合需求）。目标形态：

| 层 | 目标 |
| :-- | :-- |
| 仓库 | 一个仓库、一个 preset bundle、一个 UI bundle（可选保留 ModelCheck），不新增部署单元 |
| 可见预设 | **只有「地理教师辅助」**；隔离解题会话对用户不可见 |
| 安装 | 一条命令完成 profile 接线与数据路径默认值，可重复执行、可卸载 |
| 数据 | 考点库随包；题库缺省指向仓库内**自编示例题库**（4 道题，覆盖选择/综合/读图/解析图场景），教师随时替换为真实题库 |
| 入口 | 原生输入区的功能选择器（现有 UI）；另加一条只读状态命令作为安装自检 |
| 文档 | README 首屏 30 秒三步；其余文档各守一处，不重复 |

用户可见的「三步」：`node scripts/setup.mjs` → 重启桌面 → 选「地理教师辅助」，在输入区选功能、发需求。

## 三、方案

### 3.1 一键安装（`scripts/setup.mjs`）

新增 Node 脚本（Windows/macOS 通用，零依赖），默认操作 `desktop` profile：

| 能力 | 行为 |
| :-- | :-- |
| `--check`（默认先跑） | 只读检查：`DSH_HOME`、profile 是否存在、DSH 版本是否 ≥ **0.2.1-rc.5**（低于则拒绝并提示升级）、仓库路径、三个包的 `cordis.patch.yml` 是否存在 |
| 安装 | 把 `@geo-edu/dsh-geo-teacher-preset`、`@geo-edu/dsh-geo-teacher-ui`（可选 `@geo-edu/dsh-modelcheck`）以 `link:<仓库绝对路径>` 幂等写入目标 profile 的 `dependencies`，并把 bundle 名补进 `dsh.profile.bundles`（已存在则跳过，不重排既有顺序） |
| 数据 | 生成 `~/.dsh/geo-teacher/config.json`：考点库=包内 `knowledge/`；题库=仓库内 `question-bank-demo/`；写前若已有配置则**只补缺失键**，不覆盖用户已有路径 |
| 自检 | 打印 profile 路径、写入结果、桌面重启提示、`/geo-teacher` 入口与示例题号；可选 `--verify` 在桌面已启动时请求 `/geo/core/health` |
| 安全 | 默认打印 diff 并在 `--yes` 时落盘（首次可交互确认）；另提供 `--uninstall` 移除本项目的依赖与 bundle 项（只动这三项） |

配套：两个包补 `engines.dsh`（`>=0.2.1-rc.5`）；`package.json` 增 `"setup": "node scripts/setup.mjs"`。

**不采用**：把仓库发布到 npm（既有决策是只发 GitHub）；安装脚本不写系统级环境变量、不改 DSH 安装目录。

### 3.2 示例题库与数据默认值

- 新增 `question-bank-demo/`：**自编** 4 个题组（避免真题版权问题），覆盖：
  1. 材料型选择题组（2 小题，含共享图）；
  2. 材料型综合题（3 小问）；
  3. 读图/坐标图题（题面图 + 数据读取）；
  4. **含解析图**的题（验证“解析图不进入解题输入”）；
  图片放 `question-bank-demo/附件/`，目录结构沿用现有题库格式（`省份/年份/题组.md`）。
- core 配置解析增加缺省：`questionBankPath` 未配置且包内 `question-bank-demo/` 存在时，使用示例题库并在 `health` 里标记 `questionBankSource: 'packaged-demo'`；教师配置真实路径后以配置为准（`questionBankSource: 'user'`）。
- `/geo/core/health` 与安装自检都显示数据来源；`geo_solve` 在题库不可用时的报错附上 `scripts/setup.mjs` 提示。
- 示例题库标注“演示数据，非真题”，避免与题库真实性混淆。

### 3.3 预设收口（只留一个可见预设）

现状：讲题隔离依赖一个独立 agent preset（`geo-solver-internal`），原因是 DSH 契约——`subagents.startActivation` 创建的子会话，其 persona 与工具**只由它自己的 preset 决定**，且启动参数里没有 per-child 工具过滤。三个候选：

| 路线 | 做法 | 收益 | 代价/风险 | 结论 |
| :-- | :-- | :-- | :-- | :-- |
| **A. 插件自建子会话** | 插件自己 `agents.create({ setup })`，在 `setup(childCtx)` 内 `tools.restrict`/`guard` + 注入解题 persona，再 `followup` + `whenIdle` 取结果 | 只留一个预设；子会话工具目录真正为空；不依赖 `subagents` 服务 | 需复刻投递/生命周期（消息构造、wake 时序、取消、dispose、lineage），约 200–300 行；使用较低层 API，升级兼容风险较高 | **先做技术验证**，通过则采用 |
| **C′. 临时注册** | 解题时 `agentPresets.register` 内部预设，子会话启动后立即注销 | 选择器平时看不到；改动小 | 注册时插件模块需能从 registry baseUrl 解析（`@geo-edu/...` 未取证，可能要 `file://` 绝对路径） | A 不通过时的退路 |
| C. 现状 | bundle 声明内部预设 | 走官方子代理缝，代码最少、最稳 | 多一条可见预设 | 保底 |

**执行顺序**：先写一次性验证脚本（不改业务）验证 A 的三个关键点——① 手工构造的 user message 能被 `followup` 正常处理；② `whenIdle` 在 followup 之后可靠等待整轮；③ dispose 后 session/agent 清理干净、父会话 lineage 正确。通过则按 A 收口并删除内部预设；不通过则 C′。

无论 A 还是 C′，验收口径不变：**预设选择器只有「地理教师辅助」；隔离解题子会话 `request/header.tools` 为空**；隔离能力缺失时 `SOVLER_ISOLATION_UNAVAILABLE` 类错误 fail-closed（现有错误码 `SOLVER_ISOLATION_UNAVAILABLE` 不变）。

### 3.4 工作台（沿用现有 UI，只补自检入口）

现有输入区 UI 插件已满足界面需求，**不重建、不新增网页**。本期只补三处低成本能力：

1. **状态命令**：新增只读命令 `/geo-status`（DSH 命令，不调模型），输出：DSH 版本、考点库/题库来源（user/packaged-demo）、题库题数、索引状态、最近一次讲题 run 的状态。安装自检与排障共用。
2. **首次使用引导**：示例题库生效时，`geo_solve` 成功返回里带一句“当前使用示例题库，可在 `~/.dsh/geo-teacher/config.json` 换成自己的题库”；`geo_status` 同样提示。
3. **UI 插件小改（可选，默认不做）**：当 `/geo/core/health` 失败时，在功能选择器旁显示一行“数据未配置”提示；该改动涉及 client 行为，待第 1–3 批稳定后单独评估。

**明确不做（本期）**：讲稿/结果卡片的内嵌渲染、会话结果页、面板重写、把三功能拆成三个页面。这些属于“工作台 v2”，依赖 client 插件与槽位能力，等安装与数据链路稳定后再立项。

## 四、实施顺序与验收

| 批次 | 工作 | 完成标准（可验证） |
| :-- | :-- | :-- |
| 1 | `scripts/setup.mjs`（`--check`/安装/`--uninstall`）、`engines.dsh`、README 快速开始 | 在**临时 profile**（`DSH_HOME` 指向临时目录+复制一份 profile 骨架）上：`--check` 只读、安装幂等（连跑两次 diff 为空）、`--uninstall` 恢复原状；不改动既有依赖顺序 |
| 2 | `question-bank-demo/` + 配置缺省 + health 来源标记 + `geo_status` 提示 | 清空 config 后：`/geo/core/health` 显示 `packaged-demo` 与题数；用示例题跑完整讲题（solve→judge×2→explain），解析图零交付；换成真实路径后显示 `user` |
| 3 | 预设收口（先 A 验证，再决定 A/C′） | 预设选择器仅一个预设；`geo_solve` 子会话 `request/header.tools` 为空；答案仍在提交后开放；隔离失败 fail-closed |
| 4 | 文档收口 + 基线换代 | 新用户按 README 三步可完成安装并成功讲一道示例题；docs/README 索引与基线口径一致 |

每批独立提交，均可回滚；批 1–2 不改模型侧行为，风险最低。

## 五、风险与边界

| 风险 | 处置 |
| :-- | :-- |
| 安装脚本改动用户 profile（可能已有其它配置） | 只增/删本项目的三项，默认打印 diff + `--yes`；提供 `--uninstall`；不重排既有 bundle 顺序 |
| rc.5 与文档基线不一致 | 第 4 批新建 rc.5 基线；在此之前所有新文档以本方案头部声明为准 |
| 路线 A 的真实时序问题（`whenIdle`、消息构造） | 先写一次性验证脚本；不通过退 C′；两条路都不通过则保留 C，并在 README 注明“内部预设勿选” |
| 示例题库被误当真实题库/涉版权 | 全部**自编**，标题与说明标注“演示数据，非真题”；README 说明替换方式 |
| UI 插件就地改写宿主 DOM 的既有风险 | 本方案不改 UI 主体；仅新增只读命令与文案提示 |
| ModelCheck/其它 bundle 让安装变重 | 安装脚本默认只装 preset + UI；ModelCheck 以 `--with-modelcheck` 可选 |
