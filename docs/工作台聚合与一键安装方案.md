## 1. 目标与本期边界

目标：别人 `git clone` 后能按 README 三步直接用起来，不必懂 profile、bundle、数据路径。


## 3. 安装：真实步骤（不能只改 package.json）

### 3.1 三个前提事实

1. Desktop profile 由 Electron 应用独占：外部 `dsh plugin --profile desktop …` 会被 CLI 明确拒绝。安装器必须直接操作 profile 目录（与桌面「插件管理器」底层行为一致）。
2. 插件从 profile 的 `node_modules` 解析：`dsh-app-boot` 把 profile `node_modules` 里的 pnpm 托管条目接给 Node 解析器。**只写清单不安装 = 不会加载**，必须跑一次 pnpm install 生成链接。
3. DSH 启动**不会自动安装**依赖；启动只补 `pnpm-workspace.yaml` 等脚手架。安装动作由安装器显式完成。

### 3.2 步骤（`scripts/setup.mjs`）

| 步骤 | 行为 | 失败处理 |
| :-- | :-- | :-- |
| 0 前置 | 读 `DSH_HOME`（缺省 `~/.dsh`）、确认 profile、读 `runtime.json` 得版本；用运行时自带 Node/pnpm（`<DSH_HOME>/dsh-runtimes/dsh-primary-runtime/dependencies/{node,pnpm}`，实测 pnpm 11.28.5） | 版本 `< 0.2.1` 或缺 DSH 时停止并给升级指引 |
| 1 `--check` | 只读：版本、profile、两个包目录与 `cordis.patch.yml`、当前清单/bundles/链接状态、将执行的修改 | 零写入 |
| 2 备份 | 复制 `profile/package.json`、`profile/pnpm-lock.yaml`（存在时）到 `profile/.geo-teacher-setup/<时间戳>/` | 备份失败即停止 |
| 3 写清单 | `dependencies` 增 `@geo-edu/dsh-geo-teacher-preset`、`@geo-edu/dsh-geo-teacher-ui`（`link:<仓库绝对路径>`，Windows 正斜杠）；`dsh.profile.bundles` 追加两项（保持既有顺序，已存在跳过） | 先展示 diff，`--yes` 落盘；支持 `--dry-run` |
| 4 安装依赖/建链接 | profile 目录执行：`node <pnpm> install --prefer-offline --no-frozen-lockfile`；确认 `node_modules/@geo-edu/*` 为指向仓库的符号链接 | 失败时从备份恢复清单与 lockfile，再重跑 `pnpm install`（有 lockfile 用 `--frozen-lockfile`，无则 `--config.lockfile=false`）；**不承诺“完全恢复原状”** |
| 5 数据 | **不写数据路径**：数据随仓库提供（§4），config 只补缺失的其它键 | 已有配置不覆盖 |
| 6 静态校验 | ① 清单可解析且 bundles 含两项；② 从 profile 目录 `require.resolve('@geo-edu/dsh-geo-teacher-preset/package.json')` 与 UI 包成功；③ 两包 `cordis.patch.yml` 可达；④ `data/` 目录与题库文件数 > 0 | 任一项失败：打印具体项并返回非 0 |
| 7 重启与验活 | 提示“完全退出 DSH 再启动”（关窗可能只是隐藏）；重启后选「地理教师辅助」会话，输入 `/geo-status`：命令存在即证明 preset/UI 已加载 | 人工步骤；`/geo-status` 输出可用于排障 |

补充：`--uninstall` 按 §3.3；不提供 `--with-modelcheck`（§6）；可选 `--profile <name>`（默认 `desktop`）。

### 3.3 卸载（明确删什么、留什么）

| 删除 | 保留 |
| :-- | :-- |
| profile `dependencies` 中两个 `@geo-edu/…` 键 | `~/.dsh/geo-teacher/config.json`（教师自定义路径） |
| profile `dsh.profile.bundles` 中两个包名 | `outputs/`、`solve-runs.json`、教师自己的题库/考点库、会话记录 |
| 执行一次 pnpm install 同步 `node_modules` 链接 | pnpm store、`pnpm-lock.yaml` 的历史内容（不手工重写） |
| `profile/.geo-teacher-setup/` 备份可由用户自行删除 | 仓库本身（不删除） |

**不承诺**“恢复原状”：lockfile 解析结果、pnpm store、桌面启动脚手架都可能与安装前不同；只承诺“移除本项目的依赖与 bundle 项，且不影响其他已装插件”。**不自动卸载 ModelCheck**（非本期安装器安装的组件）。

### 3.4 安装器不采用的方式

不用 `dsh plugin --profile desktop`（CLI 拒绝）；不发 npm 包（只发 GitHub，安装以 `link:` 为准）；不改 DSH 安装目录/系统环境变量；不写死机器路径。

## 4. 随仓库数据：统一位置与单一解析逻辑

### 4.1 位置（仓库根 `data/`，镜像 `E:\知识图谱` 现有数据）

原则：**DSH 与 Obsidian 读同一份数据**，不改题库文件、不改图片相对链接，保证现有 Obsidian 中的效果在 DSH 中一致。

```
data/
  config/                       # 考点库：与教师当前 E:\知识图谱\config 完全一致，4 个 YAML 全量随仓库（约 160 KB）
    knowledge_taxonomy_natural_geography.yaml
    knowledge_taxonomy_human_geography.yaml
    knowledge_taxonomy_regional_development.yaml
    knowledge_taxonomy_resources_environment_national_security.yaml
  obsidian_vault/               # 题库与导航：与 E:\知识图谱\obsidian_vault 目录结构一致（约 16 MB / 449 文件）
    00_首页与导航/              # 保留，Obsidian 导航效果一致
    01_知识主题/                # 保留（166 份知识图谱笔记）
    03_考点统计/                # 保留（42 份统计笔记）
    04_题目/…                   # 真实题库全量：115 份 md，约 0.8 MB
    90_附件/题目图片/…           # 真实题图：120 张（116 png + 4 webp），约 15 MB
```

- **考点库不裁剪**：4 个主题文件全量随仓库，与教师当前 `knowledgeBasePath` 指向的内容一致（4 领域 / 26 主题 / 121 知识单元）。不再用“选 2 个主题”的子集方案。
- **题库与图保留原始相对结构**：`04_题目/省/年/x.md → ../../../90_附件/…` 的链接**无需改写**，因此在 `data/obsidian_vault/` 下必须保持 `04_题目` 与 `90_附件` 同级。
- **保留 `00/01/03` 三个目录**：它们不参与 DSH 的解题流程，但保证“Obsidian 里看到的图谱/统计/导航”在仓库中同样是同一份；不做二次生成。
- **排除 `.obsidian/`**（编辑器主题、插件与工作区配置，与内容无关）；如需完全镜像可加进 `.gitignore` 之外单独讨论。
- 仓库体积增加约 **16.3 MB**（单文件均 < 100 MB，直接提交；不启用 Git LFS）。
- `data/` 不加入 `.gitignore`；预设包 `files` 不变（数据不随 bundle 发布，避免把 bundle 变成数据包）。

### 4.2 解析（core 内只有一套逻辑）

新增/收敛为单一 `resolveDataPath(kind)`（`kind = knowledgeBase | questionBank`）：

```
用户 config 显式路径（存在且可用） > 仓库 data/ 默认路径 > missing
```

- 默认路径由 core 从插件位置向上定位仓库根（`plugins/core` → 预设包 → `.agent-presets` → 仓库根）：
  - `knowledgeBase` → `<repo>/data/config`
  - `questionBank` → `<repo>/data/obsidian_vault/04_题目`
- 仓库根不可判定或 `data/` 缺失时按 `missing` 处理，不回落到作者机器路径。
- `/geo/core/health` 增 `knowledgeSource` / `questionBankSource`：`user | packaged | missing`；`/geo-status` 同步显示。
- 修掉现状里 `PACKAGED_KNOWLEDGE_DIR` 指向不存在目录的问题；不再保留第二套“包内目录自动查找”分支。

### 4.3 默认数据与教师自定义

| 场景 | 触发 | 行为 |
| :-- | :-- | :-- |
| 默认（随仓库） | `config.json` 未提供对应路径 | 使用 `data/config` 与 `data/obsidian_vault/04_题目`；`/geo-status` 显示 `packaged` |
| 教师自定义 | 在 `config.json` 填 `questionBankPath` / `knowledgeBasePath` | 以教师路径为准；`/geo-status` 显示 `user` |

- 两份数据都是教师现有真实数据，**不做“演示/非真题”标注**；README 不写相关提示。
- 教师可整体替换 `data/`，也可只改 config 指向自己的目录；两种方式共用同一解析逻辑。

## 5. `/geo-status`（本期统一状态入口）

| 项 | 设计 |
| :-- | :-- |
| 形态 | DSH 宿主**命令**（`ctx.commands.register`，名称 `geo-status`，用户输入 `/geo-status`），**不调用模型** |
| 注册位置 | geo-teacher preset 的一个插件行（优先复用 `plugins/analysis` 或 `plugins/panel`，不新增 bundle） |
| 输出 | DSH 版本；`knowledgeSource` / `questionBankSource`；题库题数；索引构建状态；最近一条讲题 run（题号/状态/提交时间）；内部预设是否存在（仅诊断） |
| 用途 | 安装后验活（命令存在 = preset 已加载）、排障、确认数据来源 |
| 边界 | 只读；不写文件、不触发解题；输出十余行以内 |

实现前核对 rc.5 `commands` 契约（definition 字段、handler 返回 `{kind:'success', text}`、命令名格式）；若命令注册受作用域限制，退化为 `geo_status` 工具并只保留这一个入口。

## 7. 预设收口：移出本期

- 保留现有稳定的隔离机制：bundle 声明 `geo-solver-internal` + `plugins/solver-isolation`（`tools.restrict` 隐藏 + `tools.guard` 拒绝）。
- **不做**插件自建子会话（路线 A）或临时注册/注销（C′）：两者都要重写子会话生命周期或依赖未取证的模块解析，收益只是菜单少一项，风险不成比例。
- README/使用指南保留“内部预设可见但勿选”一句；等安装与数据链路稳定后单独评估。

## 9. 风险与边界

| 风险 | 处置 |
| :-- | :-- |
| `pnpm install` 改写 profile lockfile | 先备份并展示 diff；失败按备份恢复并重装；README 说明这是正常结果 |
| 用户 profile 已有其他插件/配置 | 只增删本项目两项；不重排 bundles；不覆盖 config 已有键 |
| 仓库体积 +16 MB（题库与图） | 单文件均 < 100 MB，直接提交；不启用 LFS；README 不额外说明 |
| 题库/考点的版权与出处 | 按项目决定随仓库发布；本方案只负责位置与解析，不新增标注 |
| Obsidian 相对结构被破坏 | `data/obsidian_vault/` 保持 `00/01/03/04_题目/90_附件` 同级；批 2 校验全部图片链接可解析（`geo_solve` 原生交付与 Obsidian 预览一致） |
| 跨平台路径 | 用 `fileURLToPath`/绝对路径计算，Windows 转正斜杠；macOS/Linux 同脚本 |
| rc.5 之后版本行为变化 | 安装器只对 `< 0.2.1` 硬拒绝，其余给“未完整验证”提示；接口清单确认后再考虑 `engines.dsh` |
