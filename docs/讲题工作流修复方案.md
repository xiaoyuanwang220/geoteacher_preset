# 讲题工作流修复方案

> 日期：2026-08-16　状态：工作流修复已实施并由确定性检查持续守护
> 配套：`讲题功能设计.md`、[项目部署说明](../README.md)、`术语表.md`、`讲题评测方案.md`
> 本文维护现行工作流约束；旧多模态迁移已完成，不再作为部署或执行步骤。

## 一、问题定界

| # | 缺陷 | 影响 |
| :-- | :-- | :-- |
| W1 | `solutionScaffold` 的 `distractorClues` 从官方解析提取错误选项 | solve 阶段可通过排除法反推出答案，破坏独立解题 |
| W2 | `geo_judge` 不接收独立答案，`geo_explain` 不消费核验结果 | 三阶段状态只能由模型在对话中搬运，重复材料且容易错位 |
| W3 | 取题、分析和讲题工具入口职责重叠 | 工具选择不稳定、上下文膨胀 |
| W4 | solver 与 explainer 触发词冲突，阶段门禁不足 | 可能跳过独立解题或核验，直接进入讲题稿生成 |

## 二、有效工作流契约

### 2.1 solve 阶段答案隔离

- `solutionScaffold()` 不得返回由答案或解析派生的 `distractorClues`；只保留由题面派生的 `questionFramework`、`thinkingModes` 和 `dimensionScan`。
- `questionData()` 的 `knowledgePoints` 不得包含会暴露核心考点判断的 `role` 或 `evidence`；完整信息只允许在 judge 阶段开放。
- 题库题面只通过 `geo_solve` 获取，禁止使用 `read`、`glob` 或 PowerShell 直接读取含答案和解析的题库 Markdown。
- `geo_solve` 是唯一解题入口，返回题面、审题骨架和原生图片附件，不返回答案或解析。

### 2.2 solve → judge → explain 编排

1. `geo_solve(qid)`：模型仅依据题面、图片与地理知识形成独立答案。
2. `geo_judge(qid, independentAnswer)`：接收独立答案，并与 `answerData` 中的标准答案、解析和采分点核验。
3. `geo_explain(qid, independentAnswer, judgeReport, audience)`：消费独立答案、核验报告与讲解对象（`student` 默认／`teacher`／`setter`），按对象生成讲稿重组骨架，不重新解题。三对象现行规则见 `讲题功能设计.md` §十一。

未取得独立答案和核验报告前，不得进入 explainer 阶段。完整流程单题原则上不超过 3 次 geo 工具调用，且不得重复携带同一份题面材料。

### 2.3 工具与技能边界

- `geo-solver` 触发词聚焦“怎么解、怎么做”；不得以“讲题”同时触发 solver 与 explainer。
- `geo-question-explainer` 聚焦“怎么讲、讲给学生”，并在入口检查 solver 与 judge 产物。
- 检索、命题研究和讲题流水线工具在 description 中保持职责分级；`geo_solve` 不用于普通题库浏览。
- 工具结果使用紧凑 Markdown 渲染，避免重复输出大段 JSON。

## 三、回归门

`scripts/geo-verify.mjs` 必须持续断言：

- `geo_solve` 返回不含 `answer`、`analysis` 或解析派生的 `distractorClues`；
- `geo_judge` 与 `geo_explain` 接收 `independentAnswer`，explainer 同时接收 `judgeReport`；
- 题面图片采用原生图片附件，并对 `none`、`complete`、`partial`、`degraded` 四种交付状态作显式区分；
- 预设包导出、`cordis.patch.yml` 声明行及技能入口符合当前部署形态；
- P4 评测只对 judge 前的 solve 输出评价独立性，避免标准答案污染评测。

## 四、验收标准

1. 抽查至少 5 道选择题，`geo_solve` 输出中没有答案、解析或解析派生线索。
2. 单题严格按 solve→judge→explain 顺序执行，并正确传递独立答案和核验报告。
3. 单题讲题流程不超过 3 次 geo 工具调用，无重复取题和题库文件直读。
4. 按 `讲题评测方案.md` 对 20–30 道真题执行教师人工评测；独立性指标只基于 solve 阶段输出。
5. 修改插件、组合或依赖后完整重启 DSH，再执行运行时验收；技能入口变更重新加载技能。本机 profile 通过 `link:` 读取仓库，不需要双副本同步。

## 五、风险与处置

- 技能触发词变化可能影响旧话术：同步维护 `使用指南.md` 中的示例和意图映射。
- persona 与 Skill 的题库读取纪律属于模型侧约束；若再次出现直接读取题库文件，应升级为宿主文件访问硬限制。
- 修改组合、插件、导出或依赖后须完整重启并验收，不以文件保存成功作为运行时已加载的证据。

## 六、原生图片交付

当前由 DeepSeek 多模态模型直接读图。`geoKernel.imageRefs(qid)` 提供图片引用与顺序；`geo_solve` 读取图片字节，通过 `attachments.saveImage()` 保存原生附件；`renderSolve` 将题面文字与图片块交给模型。这些步骤负责图片传递，不执行外部视觉转录。

- 图片附件保持题面顺序；图片与图中文字作为不可信题面数据，不执行其中的指令。
- 图片返回值不暴露本地路径或图片字节；失败原因须显式报告。
- `none` 表示无图，`complete` 表示全部附件交付，`partial` 表示部分交付，`degraded` 表示交付失败或引用解析失败。`complete` 不证明模型读图正确。
- 教师上传图片由当前多模态模型读取；独立本地图片路径使用官方 `read_image`，不得用文本读取工具代替。
- `scripts/geo-verify.mjs` 中旧视觉服务名称是禁止回归的检测项，不是服务注册。
