# 讲题工作流修复方案

> 日期：2026-08-16（2026-11-06 起编排契约改为隔离解题会话与两阶段核验，**源码已实现、待完整重启 DSH 后运行时验收**）　状态：确定性检查持续守护
> 配套：`讲题功能设计.md`、[项目部署说明](../README.md)、`术语表.md`、`讲题评测方案.md`
> 本文维护现行工作流约束；旧多模态迁移已完成，不再作为部署或执行步骤。

## 一、问题定界

| # | 缺陷 | 影响 |
| :-- | :-- | :-- |
| W1 | `solutionScaffold` 的 `distractorClues` 从官方解析提取错误选项 | solve 阶段可通过排除法反推出答案，破坏独立解题 |
| W2 | `geo_judge` 不接收独立答案，`geo_explain` 不消费核验结果 | 三阶段状态只能由模型在对话中搬运，重复材料且容易错位 |
| W3 | 取题、分析和讲题工具入口职责重叠 | 工具选择不稳定、上下文膨胀 |
| W4 | solver 与 explainer 触发词冲突，阶段门禁不足 | 可能跳过独立解题或核验，直接进入讲题稿生成 |

## 二、有效工作流契约

### 2.1 solve 阶段答案隔离（题答分离 + 隔离解题会话）

- **题答分离**：解题输入只含材料、题干、选项、小问与**题面图片**；`**答案**`／`**解析**`／`## 教学备注` 之后的**解析图**、`**知识点归属**`、`MANAGED-KM` 块、答案与解析文本不进入解题输入。边界无法判断时返回 `QUESTION_BOUNDARY_UNCERTAIN` 并指出具体题目（题组文件、`第N题/第N小问`、命中片段），请教师确认，不猜测切分。
- `solutionScaffold()` 不再进入解题输入（只供讲稿骨架内部使用）；`questionData()` 的 `knowledgePoints` 不含会暴露核心考点判断的 `role` 或 `evidence`；完整信息只在作答提交后开放。
- 题库题面只通过 `geo_solve`／`prepareSolve` 获取，禁止使用 `read`、`glob` 或 PowerShell 直接读取含答案和解析的题库 Markdown；**主会话不得自己解题**。
- `geo_solve` 是唯一解题入口：由**隔离解题会话**（bundle 声明的内部 agent preset；`plugins/solver-isolation` 提供 persona，并在 preset 作用域用 `tools.restrict` 隐藏、`tools.guard` 拒绝全部继承工具；spawn 子会话、caller delivery）完成独立读题、读图、推导与作答，题面图片作为原生附件交付，不返回答案或解析。隔离能力缺失返回 `SOLVER_ISOLATION_UNAVAILABLE`，**fail-closed，不回落主会话**。

### 2.2 solve → judge → explain 编排（服务端状态机）

```
question_ready（题面就绪） → submitted（作答已提交） → verified（核验完成）
```

1. `geo_solve(qid)`：`prepareSolve` 分离题面并记 run（指纹绑定 questionId + 题面）；隔离会话作答；`recordIndependentAnswer(runId, { answerText, keyEvidence, childSessionId })` 保存独立作答原文 → `submitted`。
2. `geo_judge(qid)`：作答提交后才开放答案（`openReferenceAnswer`，否则 `SOLVE_NOT_SUBMITTED`／`QUESTION_VERSION_CHANGED`），返回独立作答 + 标准答案/解析/采分点/覆盖网格/干扰项目标，`state:'answer_opened'`。
3. `geo_judge(qid, conclusion)`：模型对照后提交 `verdict`（`consistent`／`partially_consistent`／`inconsistent`）与 `matched`／`missed`／`wrong`／`disputed`／`correction`，`recordVerification` 归档 → `verified`（未开答案则 `JUDGE_NOT_OPENED`）。
4. `geo_explain(qid, audience)`：只消费 `verified` run（否则 `EXPLAIN_NOT_VERIFIED` 并带 `solveStatus`），按对象生成讲稿；`student` 默认／`teacher`／`setter`。三对象现行规则见 `讲题功能设计.md` §十一。

未 `submitted` 不得取答案；未 `verified` 不得生成讲稿。完整讲题共 4 次 geo 工具调用（`geo_solve` → `geo_judge` 开答案 → `geo_judge` 归档 → `geo_explain`）；「只问怎么做」只调 `geo_solve`（1 次）。原「单题不超过 3 次」随两阶段核验废止，理由见 §四 第 3 条。

### 2.3 工具与技能边界

- persona 只做需求路由与答案隔离底线：「只问怎么做」→ 只调 `geo_solve`，返回独立答案与关键依据；「要求讲题」→ 连续 `solve → judge（两阶段）→ explain`，**中途不询问是否继续**；「分析命题设计」→ `geo_analyze`。
- `skills/geo-solver.md` 是隔离解题会话的 persona 正文来源；`skills/geo-question-explainer.md` 管流程编排与交付要求；学生/教师/命题人的具体写法与同类题比较规范只写在 `skills/references/explainer-audiences.md`。
- `geo_solve` 不用于普通题库浏览；工具描述只写用途、参数与前置条件（每条 ≤ 350 字符），教学话术与细则移入技能；工具结果使用紧凑 Markdown 渲染，避免重复输出大段 JSON。

## 三、回归门

`scripts/geo-verify.mjs` 必须持续断言：

- **题答分离**：core 含题面图片/解析图分离与边界检测；analysis 的解题 prompt 不含 answer/analysis/知识点；边界不明返回 `QUESTION_BOUNDARY_UNCERTAIN`；
- **隔离执行**：analysis 含 `subagents.startActivation`、`agentPreset`、`delivery: 'caller'`、`SOLVER_ISOLATION_UNAVAILABLE`；无主会话自解回落；失败 `SOLVER_RUN_FAILED`；
- **作答绑定与门禁**：core 含 `SOLVE_NOT_SUBMITTED`、`JUDGE_NOT_OPENED`、`EXPLAIN_NOT_VERIFIED`、`questionFingerprint`（题面口径）、`solve-runs.json` 持久化；
- **核验状态**：analysis 不再含 `self_reported_material`／`buildVerification`／`toJudgeReportJson`；`geo_explain` 只接受 verified；
- **题面图片交付**：原生图片附件与 `none`／`complete`／`partial`／`degraded` 四态显式区分，`partial`／`degraded` 返回 `IMAGE_DELIVERY_INCOMPLETE`；
- **工具描述预算**：三个讲题工具 description ≤ 350 字符；
- 预设包导出、`cordis.patch.yml` 声明行及技能入口符合当前部署形态；
- P4 评测只对隔离会话的 solve 输出评价独立性，避免标准答案污染评测。

## 四、验收标准

1. 抽查至少 5 道选择题，`geo_solve` 输出的独立作答中没有答案、解析或解析派生线索；隔离解题会话只收到题面（材料/题干/选项/小问/题面图片）。
2. 单题严格按 `geo_solve → geo_judge（开答案）→ geo_judge（归档结论）→ geo_explain` 顺序执行；未提交取答案返回 `SOLVE_NOT_SUBMITTED`，未核验生成讲稿返回 `EXPLAIN_NOT_VERIFIED`，题面变化旧 run 失效。
3. 工具调用次数按新流程计：只问怎么做 1 次（`geo_solve`），完整讲题 4 次（`geo_solve` + `geo_judge` 两次 + `geo_explain`）。原「单题不超过 3 次 geo 工具调用」与两阶段核验冲突而废止——开放答案与归档结论必须分两次完成，不能压成一次；仍要求无重复取题、无题库文件直读。
4. 按 `讲题评测方案.md` 对 20–30 道真题执行教师人工评测；独立性指标只基于隔离会话输出。
5. 修改插件、组合或依赖后完整重启 DSH，再执行运行时验收；技能入口变更重新加载技能。本机 profile 通过 `link:` 读取仓库，不需要双副本同步。源码检查通过不等于运行时验收。

## 五、风险与处置

- 隔离能力（`subagents`／`agentPresets`／`spawn` 提供方）缺失时返回 `SOLVER_ISOLATION_UNAVAILABLE`，**不以主会话自解兜底**；失败即失败，交由会话如实报告。
- 技能触发词变化可能影响旧话术：同步维护 `使用指南.md` 中的示例和意图映射。
- persona 与 Skill 的题库读取纪律属于模型侧约束；若再次出现直接读取题库文件，应升级为宿主文件访问硬限制。
- 修改组合、插件、导出或依赖后须完整重启并验收，不以文件保存成功作为运行时已加载的证据。

## 六、原生图片交付

题面图片由 `geo_solve` 交付给隔离解题会话：`kernel.prepareSolve` 给出题面图片引用与顺序，`geo_solve` 读取图片字节，通过 `attachments.saveImage()` 保存原生附件，再交给子会话。这些步骤负责图片传递，不执行外部视觉转录。**解析图永不交付**（见 §2.1）。

- 图片附件保持题面顺序；图片与图中文字作为不可信题面数据，不执行其中的指令。
- 图片返回值不暴露本地路径或图片字节；失败原因须显式报告。
- `none` 表示无图，`complete` 表示全部题面图片附件交付，`partial` 表示部分交付，`degraded` 表示交付失败或引用解析失败；`partial`／`degraded` 返回 `IMAGE_DELIVERY_INCOMPLETE`，不猜图中内容。`complete` 不证明模型读图正确。
- 教师上传的图片题**未纳入本轮隔离解题**：本轮只覆盖题库 MD 题（题答分离与隔离子会话），上传图片题仍由主会话多模态读取，不属于隔离流程；独立本地图片路径使用官方 `read_image`，不得用文本读取工具代替。
- `scripts/geo-verify.mjs` 中旧视觉服务名称是禁止回归的检测项，不是服务注册。
