## 二、数据/解析层根因（3 个真 bug）

### 2.1 qid 双引号污染（最关键的根因）

- **机制**（已用真实源码 + 逐行 trace 证实）：题目文件格式不一致——正文用反引号 `` question_id: `2025-安徽-...` ``，而 **MANAGED-KM 块**内是双引号：

  ```
  <!-- MANAGED-KM-START Q17-1        ← 综合G17_Q1-3.md 第 46 行
  ```yaml
  question_id: "2025-安徽-地理-2025年安徽高考地理真题-Q17-1"   ← 第 47 行，双引号
  ```

  `plugins/core/index.js` 的 `parseOneQuestion` 主循环**只跳过 `<!--` 开头行，KM 块内全部 YAML 行仍按正文处理**；双引号行命中通用正则 `/^question_id:\s*`?([^`]+)`?\s*$/`（`[^`]+` 允许双引号），把 questionId **覆盖为带引号的值**。trace 证据：正文行第一次匹配干净（`2025-安徽-...`），KM 块第二次匹配带引号（`"2025-安徽-..."`），最终取后者。

- **后果链**：所有 questionId 带引号 → `geo_solve` 传干净 id → 「未找到题目」×2 → 模型陷入 12+ 次文件系统调试调用（glob/pwsh/read/grep，甚至读插件源码 `bank/index.js`/`core/index.js`）→ 间接引发答案污染（见 §四）。

- **涉及文件**：`plugins/core/index.js:247`（正则）、题目文件 MANAGED-KM 块格式。

### 2.2 stem 恒为"题干"（隐蔽破坏）

- **机制**：`parseOneQuestion` 第 255 行 `const inline = stemMark[1].trim();` —— **取的是捕获组 1（marker「题干/小问」），而非捕获组 2（真实题干内容）**。真实解析证实：所有小题 `stem` 都是字面"题干"，题干文字被丢弃。

- **后果**：
  - `geo_solve` 返回的题面**看不到任何真实小问文字**（渲染显示 `### "2025-..."` + 题干）；
  - 模型读不到题干 → 只能直接 `read` 题库原文件补齐（**把官方答案读进上下文**）；
  - `classifyQuestion`/`detectStemMode` 全部失真（所有题被判「综合/开放」）；题干全文检索失效。

- **涉及文件**：`plugins/core/index.js:252-256`。

### 2.3 磁盘索引陈旧 + 新鲜度检查过弱

- **现状**：`outputs/question-index.json`（95 文件 / 229 小题，builtAt 2026-08-16 23:42）由上述 buggy parser 生成（引号 id + "题干" stem）；`loadBank` 只比对 `fileCount` 相同即信任（`plugins/core/index.js` 的 `loadBank`）。
- **风险**：即使修复 parser，若只删内存缓存/直接重启，**磁盘索引仍会被信任、继续供旧数据**（fileCount 不变即命中）。必须：删除/重建旧索引 + 增加 mtime 新鲜度检查（任一文件 mtime 晚于 `builtAt` 即重建）。

## 四、流程/行为层

### 4.1 调试螺旋 + 答案污染点（qid bug 的连锁反应）

- 顺序：`geo_solve`（干净 qid）失败 ×2 → 全局 glob/pwsh 找文件 → read 插件源码排查 → **直接 read 题库 md（官方答案/解析进入上下文）** → `ask_user_question` 确认（用户选择「以题面为依据重新推演，再正常核验讲题」）→ 继续读图（`read_image` 直接看原图）→ 最终 `geo_judge` + `geo_explain` 完成。
- 模型对污染保持了透明（最终讲题稿主动注明「非未读答案的独立作答」），但污染点本身应消除。
