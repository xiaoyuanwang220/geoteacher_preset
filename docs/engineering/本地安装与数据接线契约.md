> 状态：**已实施（现行本地仓库模式契约）**；面向公网分发的 npm 一键安装与数据包拆分升级见 [npm 一键安装与数据包拆分方案](../proposals/npm一键安装与数据包拆分方案.md)。
> 说明：本文合并原《工作台聚合与一键安装方案》与《geo-teacher-仓库更新-给agent的提示词》中当前生效的工程契约。

## 1. 安装器契约（`scripts/setup.mjs`）

### 1.1 宿主前提事实
1. **Desktop profile 独占**：运行期外部执行 `dsh plugin --profile desktop …` 会被 CLI 拒绝，安装器直接操作 `<DSH_HOME>/profiles/<profile>` 目录（默认 `desktop`，与桌面内置插件管理器底层行为一致）。
2. **必须执行 `pnpm install`**：`dsh-app-boot` 从 profile 的 `node_modules` 解析插件，只改 `package.json` 不安装不会生效；且 DSH 启动时不会自动安装依赖。
3. **运行时自带工具链**：安装器优先从 DSH Desktop 安装目录（Windows 经卸载注册项定位 `resources/runtime/primary-runtime`）读取现行宿主版本与内置 Node/pnpm，`$DSH_HOME/dsh-runtimes` 仅作回落。

### 1.2 执行步骤与安全边界
- `--check`：零写入只读检查（DSH 版本门 `< 0.2.1` 拒绝、profile 清单、两个 bundle 接线、`node_modules` 解析与数据目录完整性）。
- `--dry-run`：展示 `package.json` 差异，不落盘。
- `--yes`：先备份 `package.json` 与 `pnpm-lock.yaml` 到 `profile/.geo-teacher-setup/<timestamp>/`，再将两个业务 bundle（`@geo-edu/dsh-geo-teacher-preset`、`@geo-edu/dsh-geo-teacher-ui`）写入 `dependencies` 与 `dsh.profile.bundles`，并将独立真题数据包 `@geo-edu/dsh-geo-teacher-data` 仅写入 `dependencies`（遵循 DSH 非 bundle 依赖规范，不列入 `bundles`），调用内置 pnpm 安装并做静态校验；失败时自动从备份恢复清单重装。
- `--uninstall --yes`：仅移除本项目的三个依赖、两个 bundle 项及对应符号链接，**保留** `~/.dsh/geo-teacher/config.json`、`outputs/`、`solve-runs.json` 与用户自有题库数据。

## 2. 数据目录与单一解析优先级（`geo-core`）

### 2.1 默认数据结构（考点库 + 独立真题数据包）
```text
data/
└── config/                                  # 考点库（4 份 knowledge_taxonomy_*.yaml，4 领域 / 26 主题 / 132 知识单元）

packages/dsh-geo-teacher-data/               # @geo-edu/dsh-geo-teacher-data（独立非 bundle 数据包）
└── obsidian_vault/                          # 与 Obsidian 同源结构，保持相对图片链接无需改写
    ├── 00_首页与导航/                       # 保留在仓库，npm 发布时不打包
    ├── 01_知识主题/                         # 保留在仓库，npm 发布时不打包
    ├── 03_考点统计/                         # 保留在仓库，npm 发布时不打包
    ├── 04_题目/                             # 真题 Markdown（115 份题组 / 279 小问）
    └── 90_附件/题目图片/                     # 真实题图（120 张）
```

### 2.2 解析优先级（`resolveDataDir`）
`knowledgeBasePath`（考点库）与 `questionBankPath`（真题库）共用唯一解析顺序：

```text
插件显式 config ＞ 用户配置文件 <DSH_HOME>/geo-teacher/config.json ＞ 已安装数据包（DSH runtime resolution / profile node_modules / 仓库 packages/） ＞ missing（显式报错，绝不回落作者机器路径）
```

- `/geo/core/health` 与 `/geo-status` 如实回显 `knowledgeSource` / `questionBankSource`（取值为 `user` | `packaged` | `missing`）及实际生效路径。
- `outputPath` 缺省为 `<DSH_HOME>/geo-teacher/outputs`，`workspaceRoot` 缺省为 `<DSH_HOME>/geo-teacher`。

## 3. 状态自检双入口（`/geo-status` 与 `geo_status`）

由预设 `plugins/analysis` 注册，同源调用 `geoKernel.statusSummary()`，只读不写盘、不触发解题：

1. **宿主命令 `/geo-status`**：不调模型，DSH 客户端渲染为可展开命令行，用于快速确认预设已成功挂载。
2. **模型工具 `geo_status`**：教师在会话中说「查看状态」时由模型调用并以正常聊天气泡回复。
3. **输出六要素**：DSH 版本、考点库与真题库来源、题库文件与小问数、磁盘索引状态、最近讲题 run 摘要、内部隔离预设可用性诊断。

## 4. 现行仓库克隆用户的 Agent 辅助同步规程（过渡期）

在 npm 一键更新正式上线前，已通过 `git clone` 安装的教师若需同步更新，可让本地具备终端权限的 Agent 按以下安全规程代办（全程不向教师暴露 git/pnpm 术语，不触碰个人数据）：

1. **定位安装目录**：从 `<DSH_HOME>/profiles/desktop/package.json` 读取 `@geo-edu/dsh-geo-teacher-preset` 的 `link:` 路径；检查 `git status --short`，若有本地改动先询问教师是否保留，严禁擅自 `git reset --hard` 或 `git clean`。
2. **只读检查远端更新**：`git fetch --prune` 后比对 `HEAD..origin/main`，无更新即告知已是最新；有更新则用通俗语言概括并征得教师同意。
3. **拉取与校验**：执行 `git pull --ff-only`，随后运行 `node scripts/setup.mjs --check`；若提示依赖或链接需同步，执行 `node scripts/setup.mjs --yes`。
4. **重启确认与回滚**：提示教师完全退出并重开 DSH Desktop，在会话中发送「查看状态」核验；若异常则 `git checkout <原 commit>` 回滚并保留现场报错反馈维护者。
