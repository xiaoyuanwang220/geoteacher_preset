# 地理教师辅助 Agent — 使用指南

> 状态：2026-08-21（内容部分）／2026-09-27（部署与验证部分按 DSH `0.1.7-rc.2` 桌面端更新）／2026-09-28（讲题三对象）／2026-10-03（工作台重做，旧仪表盘下线）／2026-10-04（出题范围与数据格式定案：**综合题纳入 V1**，命题包升 `schemaVersion: 2`）／**2026-10-08（状态变更：讲题开发完成、转入用户反馈迭代；出题转入开发；工作台已完成；数据路径改为用户配置，见项目 README「配置数据路径」）**
> GeoTeacher 使用 DSH 官方多模态模型；题库图片由 `geo_solve` 作为原生附件交付，不再经过视觉转录插件。

## 一、三个使用入口（**可用：讲题 / 工作台 / 对话工具**；出题开发中、课程方案未接入）

### 1. Web 工作台（任务受理台）

桌面端打开 `http://127.0.0.1:19387/geo-teacher`（可用 `DSH_WEB_URL` 覆盖实际地址）——「地理教师助手」工作台，
把需求整理成一段可直接粘贴到对话的提示词。**它不连模型、不写盘**，最终仍由会话里的预设来执行。

| 功能 | 当前状态 | 参数 | 需求怎么写 |
| :--- | :--- | :--- | :--- |
| 讲题 | ✅ **可用（开发完成，反馈迭代中）** | 讲题对象：学生（默认）／教师／命题人 | 试题的年份、省份及题号，例如「2025年广东卷第10题」 |
| 出题 | 🔨 **开发中** | 题型：选择题／综合题（2026-10-04 纳入 V1，两者**二选一**）；难度：简单／中等／困难 | 学生学情、要考查的知识点及题目数量 |
| 课程方案 | ⏸️ 技能待重构（旧技能已删除） | 年级：高一／高二／高三；时间：45分钟／10分钟 | 课本、课标等 Markdown 文档信息与具体学情 |

操作：选功能 → 填需求（`Ctrl`/`Cmd`+`Enter` 也可提交）→ 选参数 → 点「开始讲题／开始出题／生成课程方案」
→ 弹出「需求已整理」→「复制需求」→ 粘贴到对话发送。

> ⚠️ **工作台已完成（2026-10-08），但三个入口背后接的东西不一样**：讲题入口可直接用；出题入口会把需求整理成提示词交给会话，技能已支持两种题型，但**产出的题组目前无法自动校验**（命题包校验器还没做）；课程方案入口在预设内没有对应技能，**提交后不会有结果**。工作台本身零构建、不写盘、不连模型，只把需求整理成提示词。

> 旧 `/geo-teacher` 仪表盘（考点树浏览、题库检索、真题分析与导出、风格档案）已于 2026-10-03 下线：
> 这些能力改由对话中的 `geo_*` 工具提供（见下一节），分析报告导出后仍写入 `E:\geo_edu_agent\outputs\`。

### 2. 对话使用（模型自动调用 geo 工具链）

在选择了「地理教师辅助」预设的会话里，直接用自然语言提需求，模型会自动调用对应工具：

| 你说 | 模型会做 |
| :--- | :--- |
| 「查一下『人口分布』这个考点有哪些真题」 | `geo_taxonomy`（定位考点）+ `geo_search_questions`（检索题组） |
| 「2025年湖南卷 Q4 这道题为什么这样考」 | `geo_question_detail`（取题组）+ `geo_analyze`（分析+命题蓝图） |
| 「把这个分析导出成 markdown 文件」 | `geo_export_analysis`（写入 outputs） |
| 「广东卷真题大概是什么风格」 | `geo_style_profile`（七维度风格档案） |
| 「这道题怎么做/怎么解」（讲题 Solver） | `geo_solve`（题面+审题骨架+原生图片附件，不含答案/解析；模型独立解题，需按顺序先执行此步） |
| 「我的解题对了吗/帮我核验」（讲题 Judge） | `geo_judge`（传入独立答案，开放答案/解析/采分点，核验覆盖/错误/遗漏/干扰项解释） |
| 「把这题讲成讲题稿/怎么讲给学生」（讲题 Explainer · 学生对象，默认） | `geo_explain`（传入独立答案+judge 结果，产出「题目定位—审题—破题—反思与迁移」四段式讲题稿骨架+变式；需先完成 solve→judge） |
| 「这道题如何讲授/怎么引导学生自己总结」（讲题 Explainer · 教师对象） | `geo_explain` 带 `audience: "teacher"`（同一四段式，段内侧重学生思维的启发、追问与支架撤除；附教师 audiencePlan） |
| 「从命题角度分析这道题/干扰项怎么设计的」（讲题 Explainer · 命题人对象） | `geo_explain` 带 `audience: "setter"`（考查目标→情境材料设问→三层干扰辨析→认知路径→答案成立条件→迁移与跨学科设计→题组和质量评价） |

> 讲题对象由 `geo_explain` 的 `audience` 参数决定：`student` 学生（可省略，缺省即学生）／`teacher` 教师／`setter` 命题人。默认只生成一个对象，需要多版本才说明。仅因为使用者是教师，不会自动切到教师对象。切换对象而题目未变时复用已核验分析；改题面或答案依据须重新核验。缺 solve/judge 产物时 `geo_explain` 返回「待核验」状态，不冒充核验完成。

### 3. 出题技能（专门命题流程）— 🔨 开发中

> **已在开发中**（2026-10-08 起；2026-10-04 之前的暂缓令已解除）。范围与数据格式已于 2026-10-04 定案：
> ① **综合题已纳入 V1**——**一个题包只用一种题型**（材料型选择题组 `single_choice` 或材料型综合题 `comprehensive`），由题包顶层 `questionType` 声明，不支持混排；
> ② **命题包数据格式已升 `schemaVersion: 2`**——综合题以「1 道大题 + 2—4 个小问」承载分值／采分点／评分标准／开放答案边界。
>
> **开发进度如实四分**：技能目录包、schema v2、双样例与术语表口径**已落地**；命题包校验器、学生与教师投影、Markdown 渲染器**未实现**（`plugins/question` 下只有 schema，全仓没有程序读取它），因此**产出的题包目前无法自动校验**；M1 桌面验收与 references 语义评审**未验收**；M2 端到端闭环**未跑通**。详见 [决策记录](决策记录.md)、[样例说明](examples/README.md)（含 v1→v2 迁移说明）与[执行方案](geography-question-generation-execution-plan.md)。

对话中说「出几道题」「按广东卷风格出 3 道选择题」「出一道综合题，考区域发展」等，模型会加载 **geo-question-generator** 技能：

1. 明确年级、主题、学情、用途和**题型**（选择题组或综合题，只能选一种），核对本地考点库、课标与教材依据；真题风格通过现有工具取得。
2. 提出三个构思，等待教师选择后生成 Markdown 初稿；图表提案须另行确认。
3. 命题稿采用六大章节：学生用试题／答案与解析／命题设计说明／典型学生模拟作答／来源与证据／风险与待确认事项。
   - **选择题组**：2—3 道小题，含 A/B/C/D 选项、唯一答案，每个干扰项对应一种认知错误；
   - **综合题**：1 道大题、2—4 个小问，各问带分值、采分点与证据链、评分标准与开放答案边界。
4. 命题包以 `outputs/出题/<taskId>/package.json` 为唯一编辑源（当前格式为 `schemaVersion: 2`）；学生投影只含题面，教师投影包含答案或采分点、解析与设计说明，并绑定同一 revision。
5. 按构思待选择、初稿完成、可使用、待补充四种完成度如实交付；必要图表或证据缺失时不得宣称可使用。综合题另需「采分点与分值自洽」和「答案边界可判定」两条语义条件通过，才能到「可使用」。

> 当前目录包技能、命题包 schema v2 与选择题／综合题双样例均已落地；**校验器、学生与教师投影、端到端交付尚未实现**，M1 桌面验证和 M2 完整题组验收也尚未闭环。以上是当前技能要求，不代表交付链路已验证。详见 [样例说明](examples/README.md)、[M1 实施记录](geography-question-generation-m1-record.md) 和 [执行方案](geography-question-generation-execution-plan.md)。

### 图片解题

当前直接使用 DeepSeek 多模态模型读取图片。题库题由 `geo_solve` 返回题面与原生图片附件；教师上传的图片由当前模型读取；独立本地图片路径通过官方 `read_image` 读取。**图片识别已可用**：题库题的原生图片附件经 2026-09-30 桌面验收实测（涉图题返回 2 张原生图，见[实施记录](讲题三对象改造-实施记录.md) §6.5）；教师上传图片与本地图片路径经用户确认（2026-10-08）可识别。图片无法读取时说明证据缺失，不补猜图中内容。图片交付实现与状态含义见 [讲题工作流](讲题工作流修复方案.md)。

## 三、数据与产物

首次使用前，请向负责安装配置的 Agent 提供 **4 个绝对目录路径：考点库目录、真题库目录、产物目录、工作区根目录**。Agent 按用户给出的值写入本机配置；缺少信息时询问，不自动搜索、识别或推断路径。产物目录必须位于工作区根目录内或与其相同，考点库和题库可以继续放在外部目录。可直接复制的请求与操作步骤见 [README「配置数据路径」](../README.md#配置数据路径clone-后必做)。

| 项目 | 位置 | 说明 |
| :--- | :--- | :--- |
| 考点库（KPS） | 用户提供目录，绑定到 `knowledgeBasePath` | 4 份；三级考点，动态读取最新版；当前 `meta.version: v0.2-draft`、`status: draft` |
| 真题库 | 由 `questionBankPath` 指定 | 新题单页直接丢进去即被检索（数量以实际扫描为准）。当前位于外部目录，计划与考点库同步开源 |
| 分析报告输出 | `<outputPath>\` | 真题分析/命题蓝图 Markdown、讲题稿 |
| 出题任务包（🔨 出题开发中） | `<outputPath>\出题\<taskId>\` | 唯一编辑源为 `package.json`（当前格式 `schemaVersion: 2`）；见执行方案 §6。已有一份真实的 v1 产物 `2026-0927-water-cycle-01`，其迁移方式见[样例说明](examples/README.md) |

> 上表用的是配置键名：实际生效路径由 `/geo/core/health` 的 `config` 字段回显（含目录是否存在），不要凭记忆推断。配置方式见项目 README「配置数据路径」。

## 五、故障排查

- **工具没出现**：确认会话用的是「地理教师辅助」预设；**插件**改动需完整重启桌面（关闭主窗口可能只是隐藏，需确认进程已退出）；技能文档改动由技能发现器监听，不需要重启。
- **工具报「未配置真题库/考点库路径」**：把四个实际目录路径告诉安装配置 Agent，按项目 README「配置数据路径」填写 `<DSH_HOME>\geo-teacher\config.json`。完整重启后用 `/geo/core/health` 逐项核对；路径不可用时由用户重新指定，Agent 不自动寻找替代目录。
- **面板打不开/路由 404**：重启桌面后 geo 插件应自动挂载；若仍异常，确认 `desktop` profile 的依赖指向你克隆的 `.agent-presets/geo-teacher` 且该目录含 `cordis.patch.yml` 与 `skills\`；跑 `node scripts\geo-verify.mjs --source` 看接线检查。工作台页由 `plugins/panel` 独占注册 `/geo-teacher`——同一路径只能有一个插件注册，重复注册会让整个 preset 挂载失败。
- **导出失败**：需重启使写盘沙箱策略生效（写入 `<outputPath>`，其根由 `workspaceRoot` 决定）。
