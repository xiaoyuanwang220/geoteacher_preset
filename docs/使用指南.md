## 一、三个使用入口（**讲题、工作台、对话工具可用**；出题开发中；课程方案技能已入预设、端到端未验收）

### 1. Web 工作台（任务受理台）

桌面端打开浏览器访问 `$DSH_WEB_URL/geo-teacher`（0.2.1 起端口由系统分配，读取运行时环境变量，不要写死端口）——「地理教师助手」工作台，
把需求整理成一段可直接粘贴到对话的提示词。**它不连模型、不写盘**，最终仍由会话里的预设来执行。

| 功能 | 当前状态 | 参数 | 需求怎么写 |
| :--- | :--- | :--- | :--- |
| 讲题 | ✅ **可用（开发完成，反馈迭代中）**；2026-11-06 讲题优化（隔离解题 + 两阶段核验）**源码已实现，待完整重启 DSH 后运行时验收** | 路径：只问怎么做／要求讲题；讲题对象：学生（默认）／教师／命题人 | 试题的年份、省份及题号，例如「2025年广东卷第10题」 |
| 出题 | 🔨 **开发中** | 题型：选择题／综合题（2026-10-04 纳入 V1，两者**二选一**）；难度：简单／中等／困难 | 学生学情、要考查的知识点及题目数量 |
| 课程方案 | 🔨 **技能已入预设，端到端未验收** | 年级：高一／高二／高三；时间：45分钟／10分钟 | 课本、课标等 Markdown 文档信息与具体学情 |

操作：选功能 → 填需求（`Ctrl`/`Cmd`+`Enter` 也可提交）→ 选参数 → 点「开始讲题／开始出题／生成课程方案」
→ 弹出「需求已整理」→「复制需求」→ 粘贴到对话发送。

### 2. 对话使用（模型自动调用 geo 工具链）

在选择了「地理教师辅助」预设的会话里，直接用自然语言提需求，模型会自动调用对应工具：

| 你说 | 模型会做 |
| :--- | :--- |
| 「查一下『人口分布』这个考点有哪些真题」 | `geo_taxonomy`（定位考点）+ `geo_search_questions`（检索题组） |
| 「2025年湖南卷 Q4 这道题为什么这样考」 | `geo_question_detail`（取题组）+ `geo_analyze`（分析+命题蓝图） |
| 「把这个分析导出成 markdown 文件」 | `geo_export_analysis`（写入 outputs） |
| 「广东卷真题大概是什么风格」 | `geo_style_profile`（七维度风格档案） |
| 「这道题怎么做/怎么解」（只问怎么做） | `geo_solve`：在**隔离解题会话**中独立作答，返回独立答案与关键依据（题面图片作为原生附件），不含答案/解析；到此为止，不自动核验与成稿 |
| 「把这题讲成讲题稿/怎么讲给学生听」（要求讲题） | 连续完成 `geo_solve → geo_judge（开放答案）→ geo_judge（归档核验结论）→ geo_explain`，**中途不询问是否继续**；学生对象默认 |
| 「我的解题对了吗/帮我核验」 | 走同一流程：`geo_judge` 在作答提交后开放标准答案/解析/采分点/覆盖网格/干扰项目标，对照后提交结论归档 |
| 「这道题如何讲授/怎么引导学生自己总结」（讲题 Explainer · 教师对象） | `geo_explain` 带 `audience: "teacher"`（同一四段式，段内侧重学生思维的启发、追问与支架撤除；附教师 audiencePlan） |
| 「从命题角度分析这道题/干扰项怎么设计的」（讲题 Explainer · 命题人对象） | `geo_explain` 带 `audience: "setter"`（考查目标→情境材料设问→三层干扰辨析→认知路径→答案成立条件→迁移与跨学科设计→题组和质量评价） |

> 讲题对象由 `geo_explain` 的 `audience` 参数决定：`student` 学生（可省略，缺省即学生）／`teacher` 教师／`setter` 命题人。默认只生成一个对象，需要多版本才说明。仅因为使用者是教师，不会自动切到教师对象。切换对象而题目未变时复用服务端已核验记录；题面变化须重新解题。
>
> **核验状态含义**：服务端每道题记一个 run，状态 `question_ready`（题面就绪）→ `submitted`（作答已提交）→ `verified`（核验完成）。答案只在作答提交后开放；`geo_explain` 只读 `verified` 记录，未核验时返回 `EXPLAIN_NOT_VERIFIED` 并带状态。`核验完成` 表示"答案开放 → 对照结论归档"的顺序已完成，**不等于内容正确**。run 记录持久化在产物目录的 `solve-runs.json`，重启后仍可核验/讲题。
>
> **内核预设可见但不可选**：预设选择器里会出现内部解题预设「地理解题隔离会话（内部）」（`order: 999`，描述已注明讲题流水线内部使用、「日常使用请选择地理教师辅助」）。它是不开放任何工具的隔离子会话（preset 作用域内 `tools.restrict` 隐藏 + `tools.guard` 拒绝继承工具），**请不要手动选择**——隔离解题只由 `geo_solve` 自动调用。
>
> **本轮不可用面**：本轮只覆盖**题库 MD 题**；**教师上传图片题未纳入隔离解题**，仍由主会话多模态读取，不走隔离与两阶段核验流程。题库题若题答边界无法判断，工具会指出具体题目请你确认（`QUESTION_BOUNDARY_UNCERTAIN`），不会猜测切分后继续。

### 3. 出题技能（专门命题流程）— 🔨 开发中

> **已在开发中**（2026-10-08 起；2026-10-04 之前的暂缓令已解除）。范围与数据格式已于 2026-10-04 定案：
> ① **综合题已纳入 V1**——**一个题包只用一种题型**（材料型选择题组 `single_choice` 或材料型综合题 `comprehensive`），由题包顶层 `questionType` 声明，不支持混排；
> ② **命题包数据格式已升 `schemaVersion: 2`**——综合题以「1 道大题 + 2—4 个小问」承载分值／采分点／评分标准／开放答案边界。
>
> **开发进度如实四分**：技能目录包、schema v2、双样例、术语表口径与 **M3 校验/投影/渲染**（`plugins/question/package.js`、工具 `geo_question_validate`、CLI `check-package.mjs`、行为测试 55 项含逐条反例）**已落地**；**未实现**无；**已验收** M1 桌面验收（2026-10-20）、M3 工具运行时复跑与 M2 首个完整题组（2026-10-21，同一会话内 `geo_question_validate` 调用 7 次全部返回 ok，两阶段流程 + 校验修复闭环）；**未做**语义内容评审（四翼、难度、答案唯一性）、`contentHash` 回填与 M4 跨主题/恢复验证。详见 [决策记录](决策记录.md)、[样例说明](examples/README.md)（含 v1→v2 迁移说明）与[执行方案](geography-question-generation-execution-plan.md)。

对话中说「出几道题」「按广东卷风格出 3 道选择题」「出一道综合题，考区域发展」等，模型会加载 **geo-question-generator** 技能：

1. 明确年级、主题、学情、用途和**题型**（选择题组或综合题，只能选一种），核对本地考点库、课标与教材依据；真题风格通过现有工具取得。
2. 提出三个构思，等待教师选择后生成 Markdown 初稿；图表提案须另行确认。
3. 命题稿采用六大章节：学生用试题／答案与解析／命题设计说明／典型学生模拟作答／来源与证据／风险与待确认事项。
   - **选择题组**：2—3 道小题，含 A/B/C/D 选项、唯一答案，每个干扰项对应一种认知错误；
   - **综合题**：1 道大题、2—4 个小问，各问带分值、采分点与证据链、评分标准与开放答案边界。
4. 命题包以 `outputs/出题/<taskId>/package.json` 为唯一编辑源（当前格式为 `schemaVersion: 2`）；学生投影只含题面，教师投影包含答案或采分点、解析与设计说明，并绑定同一 revision。
5. 按构思待选择、初稿完成、可使用、待补充四种完成度如实交付；必要图表或证据缺失时不得宣称可使用。综合题另需「采分点与分值自洽」和「答案边界可判定」两条语义条件通过，才能到「可使用」。

6. **成稿后做结构校验**（会话里用工具 `geo_question_validate`，或命令行）：
   ```
   node .agent-presets\geo-teacher\skills\geo-question-generator\scripts\check-package.mjs --task <taskId>
   ```
   默认**只读校验、不写盘**；加 `--render` 才生成 `draft.md`／`student.json`／`teacher.json`／`validation.json`。校验器只给**结构结论**（分值三级求和、ID 引用、投影是否夹带答案、确认与评审的版本绑定、v1 是否需迁移），**语义质量仍须人工或独立核验**——报告里语义项恒为 `pending`，「结构通过」不等于「质量通过」。

> 目录包技能、命题包 schema v2、选择题／综合题双样例与 **M3 校验/投影/渲染实现**均已落地；**M1 桌面验收、M3 工具运行时复跑与 M2 首个完整题组已于 2026-10-21 通过**。仍缺语义内容评审、`contentHash` 回填与 M4。详见 [样例说明](examples/README.md) 和 [执行方案](geography-question-generation-execution-plan.md)。

### 图片解题

当前直接使用 DeepSeek 多模态模型读取图片。题库题由 `geo_solve` 把**题面图片**（`## 相关图片` 节与答案标记前的正文图片）作为原生附件交给隔离解题会话，**解析图不交付**；**教师上传的图片题本轮未纳入隔离解题**，仍由当前模型在主会话读取，不走隔离与两阶段核验流程；独立本地图片路径通过官方 `read_image` 读取。**图片识别已可用**：题库题的原生图片附件经 2026-09-30 桌面验收实测（涉图题返回 2 张原生图，历史验收见 Git 记录）；教师上传图片与本地图片路径经用户确认（2026-10-08）可识别。题面图片交付不完整时返回 `IMAGE_DELIVERY_INCOMPLETE`；图片无法读取时说明证据缺失，不补猜图中内容。图片交付实现与状态含义见 [讲题工作流](讲题工作流修复方案.md)。

## 五、故障排查

- **工具没出现**：确认会话用的是「地理教师辅助」预设；**插件**改动需完整重启桌面（关闭主窗口可能只是隐藏，需确认进程已退出）；技能文档改动由技能发现器监听，不需要重启。
- **新建会话失败：`agent-preset/invalid: <插件行> (<包名>): never started`**：预设里有一行插件在升级后的 DSH 中已不存在（子路径被移除或并入主入口），该行 import 失败会让**整条预设**挂载失败。处理：先从仓库更新（`git pull --ff-only` → `node scripts/setup.mjs --yes`）并完整重启，不要手工改运行时目录；仍失败时跑 `node scripts/geo-verify.mjs --source`，并把完整报错与 DSH 版本（桌面「关于」或 `app.asar` 包版本）一并反馈。本仓库已适配 `0.2.2-rc.1`：`list_agents` 已并入 `@deepseek-ai/dsh-tool-subagent-control` 主入口，预设不再单独声明 `/list-agents` 行。
- **版本读数看起来没升级（`/geo-status` 或 `setup.mjs --check` 显示旧版本）**：两处都读 `<DSH_HOME>/dsh-runtimes/.../runtime.json`，桌面**就地自动更新**后该文件可能不刷新（本机实测：安装包已 `0.2.2-rc.1`，读数仍是 `0.2.1-rc.5`）。以安装包版本为准：Windows 看 `<安装目录>\DeepSeek Harness.exe` 的「属性 → 详细信息 → 文件版本」，或 `resources\app.asar` 内 `package.json` 的 `version`；不要用旧读数判断是否需要适配。
- **讲题报 `SOLVER_ISOLATION_UNAVAILABLE`**：当前会话缺少隔离所需服务或提供方（`subagents`、`agentPresets`、spawn 提供方或调用方 Agent）。这是 fail-closed：工具不会退回主会话解题。确认预设与插件为最新代码并完整重启后再试。
- **讲题报 `QUESTION_BOUNDARY_UNCERTAIN`**：题库 md 的题面/答案边界无法可靠切分，工具会指出具体题目（题组文件、第N题/第N小问、命中片段），请教师确认后修正题库格式；不要期待模型猜测切分。
- **图片报 `IMAGE_DELIVERY_INCOMPLETE`**：题面图片只完成部分交付或引用解析失败；不要据此编造图中内容，先修复题库图片引用与路径。
- **工具报「数据不可用」**：先确认 `data/` 是否完整（`node scripts/setup.mjs --check`）；使用自有数据时检查 `<DSH_HOME>\geo-teacher\config.json` 的 `knowledgeBasePath` / `questionBankPath` 是否存在。完整重启后用 `/geo-status` 或 `/geo/core/health` 核对来源；路径不可用时由用户重新指定，Agent 不自动寻找替代目录。
- **面板打不开/路由 404**：重启桌面后 geo 插件应自动挂载；若仍异常，确认 `desktop` profile 的依赖指向你克隆的 `.agent-presets/geo-teacher` 且该目录含 `cordis.patch.yml` 与 `skills\`；跑 `node scripts\geo-verify.mjs --source` 看接线检查。工作台页由 `plugins/panel` 独占注册 `/geo-teacher`——同一路径只能有一个插件注册，重复注册会让整个 preset 挂载失败。
- **导出失败**：需重启使写盘沙箱策略生效（写入 `<outputPath>`，其根由 `workspaceRoot` 决定）。
