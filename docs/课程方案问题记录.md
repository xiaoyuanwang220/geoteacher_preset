## 2. 课标解读

### P-01 课标分析参考篇幅偏低（L1）

**状态：已实施（2026-11-14）**——`subject-notes.md`「从分析到成文」篇幅条改为 200—400 字，并补"落到 200 字以下通常说明至少有一项要素没有展开"；`docs/课程方案治理记录.md` 规则 18 同步备注。

- **现象**：`subject-notes.md` 规定完整方案的课标分析约 100—200 多字。按此写成时，ABCD 各要素只能压成一句，读起来像要素清单，缺"学生需要形成什么认识"的展开。
- **证据**：[subject-notes.md:108](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/references/subject-notes.md)「完整教学方案中的课标分析通常约 **100—200 多字**」；[课程方案治理记录.md:66](课程方案治理记录.md) 规则 18 抄录同一数字。
- **实际情况**：本课最终成文约 350 字（含段首标签），落在 200—400 区间，四要素与总结均有展开空间。
- **建议**：参考值改为 **200—400 字**，并保留"教师有语言风格配置或明确要求时以其为准"；治理记录规则 18 同步。
- **注意**：仍作参考值，不设为硬门槛；不宜写成"低于 200 字即不合格"。

### P-02 从条文推出条文没有的限制（L1）

**状态：已实施（2026-11-14）**——`subject-notes.md`「解读立场」新增一段：条文只规定对象、动作与程度，不据此推出未限定的数量、范围、课型或组织形式；并说明教师采用多案例、讲授或复习不需要以条文为依据作说明。

- **现象**：把「以某资源枯竭型城市为例」读成"限定只用一座城市"，并据此论证单案例组织的正当性。实际该表述只指明分析对象与证据来源，不限定案例个数；教材本身并用阜新、大庆、焦作、北九州。
- **证据**：[subject-notes.md:9](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/references/subject-notes.md)「解读立场」要求"区分条文明确要求与教师的教学选择"，但未写明不得从条文推出它没有限定的数量、范围或课型。
- **影响**：解读错误会顺着教材分析与方法段扩散；本课返工两轮。
- **建议**：在「解读立场」补一句明确禁令：条文只规定对象、动作与程度，不据此推出条文未限定的数量、范围、课型或组织形式要求。

### P-03 在成品里解释自己的解读与取舍（L1）

**状态：已实施（2026-11-14）**——`lesson-format.md`「表达纪律」的「不得进入成品」扩为"对设计过程或解读过程的自我辩护"，并新增一条"解读或设计有误时只改内容"。

- **现象**：被指出误读后，修法是把"这是教学取舍，不是课标的要求——条文只规定……由教师按学情与课时决定"写进教案正文，等于在交付物里自我辩护。
- **证据**：[lesson-format.md:52](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/references/lesson-format.md) 已禁止"对设计过程的自我辩护"，但只覆盖"设计过程"，未覆盖"解读过程"与"为自己曾经的误读正名"。
- **建议**：把该条扩为"不得解释自己的设计过程或解读过程"；并写明**解读错误只改内容，不解释错在哪**。
- **关联**：P-01 的字数压缩会自然抑制这类句子，但两者不互相替代。

### P-04 跳过 A 要素时不必留占位或说明（L1）

**状态：已实施（2026-11-14）**——`subject-notes.md`「四要素拆解」补"跳过时不设空段、不写占位、也不解释为什么跳过"。

- **现象**：本条原文省略主语，按规范跳过 A 行为主体。本次跳过是正确的，但规范没有写明"跳过时正文不留占位、也不必解释为什么跳过"，下一次容易补出"因原文省略主语，故不解读 A"这类元话语。
- **证据**：[subject-notes.md:54](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/references/subject-notes.md)「原文没有的要素（常见是 A）跳过即可」。
- **建议**：在该句后补"跳过时不设空段、不写说明"。
- **注意**：不得反向要求"四要素必须齐全"——本次 A 缺失不是缺陷。

## 3. 成品文字语域

### P-05 检查口径词进入成品表头（L1）

**状态：已实施（2026-11-14）**——`lesson-format.md`「表达纪律」新增内部口径词对照表（看什么→材料、学生做什么→学生活动、交出什么→学生成果、怎么算过关→达标表现、预期回答边界→学生可能答成、阶梯提示→答不出时提示、纠偏路径→答偏了引回、承重问题→关键问题、落点收口→本课要建立的认识、设计理由本课取舍→为什么这样安排），并说明表左栏是判准用语、不写进成品正文与表头；块类型表里的误用示例「设计理由：…」改为「为什么这样安排：…」。

- **现象**：教学设计与观察表中，检查口径词被直接用作表格列名与教师话术标签：

| 词 | 作为表头 | 作为教师话术 | 位置 |
| :-- | :-- | :-- | :-- |
| 看什么 | 6 处 | 4 处 | 表头见 `documents[0].sections[0].blocks[1]`、`sections[8].blocks[1/8/15/22/39]`；话术见 `shared.phase1_q/phase3_q/phase4_q/phase5_q` 的 `teacher` 面 |
| 怎么算过关 | 7 处 | 0 | 同上表头与 `documents[0].sections[5].blocks[0].headers[2]` |
| 交出什么 | 6 处 | 0 | 同上表头 |
| 学生做什么 | 6 处 | 0 | 同上表头 |

- **词源**：[delivery-checklist.md:38](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/references/delivery-checklist.md)（第 13 条）使用"预期回答边界、阶梯提示、纠偏路径"。模型读自查清单后把这套语汇带进成品，属可预期的泄漏路径。
- **注意**：教师话术里出现"看什么"虽是教师版内部内容，但它同样不是课堂用语；一并按成品文字处理。
- **建议**：[lesson-format.md:48](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/references/lesson-format.md)「表达纪律」加一份**默认禁用词表**，明确检查口径词、评审腔词、内部工作术语（承重、收口、落点、达成标志、纠偏、阶梯提示、预期回答边界）不得进入成品正文与表头。

### P-06 教师未配置语言风格时缺少默认语域（L1）

**状态：已实施（2026-11-14）**——同节开篇补"教师未配置时按课堂口语默认：写成一个熟悉这课的高中地理教师会说的话，不写成评审报告、设计说明或自查记录"。

- **现象**：「表达偏好由教师个人知识中的语言风格配置决定」在教师未配置时是空转的，等于没有默认值，模型自行选择语域时容易选成报告体。
- **证据**：[lesson-format.md:48](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/references/lesson-format.md)。
- **建议**：补一句"教师未配置时按课堂口语默认"，与 P-05 的禁用词表配套。

### P-07 "不是 A 而是 B" 句式反复（L1）

**状态：已实施（2026-11-14）**——同节新增"句子不靠对偶推进"一条：一份文档用一两处尚可，连续出现像讲稿或答辩，后半句直接写正面陈述。

- **现象**：成品 16 处「不是」、3 处「而是」，其中 5 处构成对偶对比句（如"最后一步不是再记一遍焦作做了什么，而是提炼一条能带走的东西"）。单句可读，成片出现即成腔。

- **建议**：并入 P-05 的禁用词表条目，写"同一份文档内不得反复用对偶对比句式推进"，避免给成"禁止使用"这类绝对规则。

### P-08 向评审交代来源的句子（L1）

**状态：已实施（2026-11-14）**——同节新增"来源核验过程不写进成品"一条：已逐份核验、均登记在依据文件属依据文件职责，成品只写来源机构、年份与链接。

- **证据**：`documents[0].sections[3].blocks[3].text`（label「补足的证据」）。
- **建议**：并入 P-05 禁用词表；来源核验属依据文件职责，成品只需来源标识与链接。

## 5. 渲染与工具链

### P-28 HTML 被定义为 DOCX 的预览，不是并列的成品（L1，横跨多条的根因）

- **现象**：规范把 HTML 定位为 DOCX 的前置预览，DOCX 才是交付物。这一句话决定了其余多条的处理方式——凡是"HTML 能做得更好、DOCX 成本高"的能力，一律被砍掉或降级。
- **证据**：
  - [render_documents.py:89](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/scripts/render_documents.py) 注释原文：`docx is the teacher deliverable, html is its always-available preview`；该注释自 `ccb2ffe`（引入 V3.2）起存在，不是后来写偏的。
  - [SKILL.md:32](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/SKILL.md)「首次只渲染 HTML」、[:39](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/SKILL.md) 铁规则 4「DOCX 等教师确认后再渲染」、[:76](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/SKILL.md)「首次交付只渲染 HTML」。
  - [README.md:3](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/README.md)「首次交付为 HTML，教师确认后可出 DOCX」、[:17](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/README.md) 同义。
- **它造成了哪些下游问题**：

| 下游 | 因果 |
| :-- | :-- |
| P-19 无图片通道 | 预览阶段不需要图，反正最终交付是 DOCX |
| P-20 无图表块、只有一维 `number_line` | 同上；图形原语被判断为"对预览没必要" |
| P-21 无 `print-color-adjust` | 从未计划让 HTML 承担打印 |
| P-10 条块靠手数 `█` | 块表里没有图形原语，模型只能用字符凑，且无脚本复算 |
| P-22 机械复核只查"文件存在且非空" | 预览不值得写结构校验；第 27 条却按交付物标准承诺 |
| P-14 真题配图缺失 | 无图片通道，含图题只能以文字呈现 |

- **更实质的代价不在缺功能，在词汇表**：21 种块类型（`paragraph / labeled / h2 / h3 / instructions / list / checklist / callout / cards / fill_in / phase_header / group / workspace / labeled_box / page_break / table / columns / source_card / fill_table / number_line`）每一种都能在一张 A4 纸上印出来。`workspace`（作答留白）、`labeled_box`（带标签横线）、`number_line`（一维刻度线）的设计对象尤其明显是纸。**模型想画数据图时，词汇表里没有那个词**，只能退回表格里塞字符。
- **还有一层**：HTML 与 DOCX 是两条独立 if 链（`render_lesson_html.py:89` 起 21 个分支 vs `render_lesson_docx.py:590` 的 `_EMITTERS`），没有任何测试保证等价（P-26）。当 HTML 只是预览时，每加一个能力都要问"DOCX 那边怎么实现"，付不起的那一遍就变成缺口。
- **已决（2026-11-15）**：HTML 与 DOCX **地位并列，都是最终产物**，用哪种由教师选择；不再把 HTML 称作预览或 DOCX 的前置。规范文本已同步修改，见 §9。
- **仍需处理**：定位改了以后，P-19、P-20、P-21、P-22 的处理方式都要重算——它们不再是"给预览补功能"，而是"并列产物各自要达到可用标准"。具体见 §9。

## 5.1 图形与打印

### P-19 无图片通道（L4）

- **现象**：三个渲染器全文 `add_picture`、`<img`、`svg`、`base64`、`matplotlib` 命中均为 0，没有任何位图或 SVG 通道。`theme.css` 亦无 `img` 规则。
- **证据**：[render_lesson_html.py:89](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/scripts/render_lesson_html.py) 起的 if 链与 [render_lesson_docx.py:590](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/scripts/render_lesson_docx.py) 的 `_EMITTERS` 各 21 种块类型，均无图形块。
- **影响**：P-14 无法在现有契约内解决；教材图 2.23—2.32 也只能以图号文字出现。
- **待定**：图片随包方式（base64 内联 vs 相对路径 `assets/`）。P-28 定位改为并列成品后，HTML 与 DOCX 都要能显示同一张图，不再是"给预览配图、正式稿另有方案"，见 §9。

### P-20 无图表块，只有一维 `number_line`（L4）

- **现象**：唯一图形能力是 `number_line`，参数仅 `min/max/ticks/marks`，只画一根带刻度的水平线与两端两个标签；无纵轴、无图例、无双序列、无来源注、单位只能写在别处。HTML 刻度上限 100，DOCX 上限 24（`render_lesson_html.py:244` vs `render_lesson_docx.py:512`），同一块两种格式刻度数不同。
- **影响**：模型只能退回"表格里塞 `█`"，即 P-10 的成因。
- **建议**：新增 `chart` 块，**几何只算一次**（`lesson_common.py` 一处算出每根条的起点、长度、标签位置），HTML 与 DOCX 各自按同一套坐标画。HTML 侧用原生 SVG；DOCX 侧用 Pillow 画进 PNG 后 `add_picture` 嵌入（实测可行，见 §9）。教师选哪种产物，看到的是同一张图。

### P-21 打印不保留背景色（L3）

- **现象**：`theme.css` 中 `print-color-adjust` 命中 0。浏览器打印默认不印背景色，现有 `th{background:#F6F8F9}` 与卡片底色均不会打出。
- **影响**：若图表用 CSS 底色画条，屏幕上可见、打印后为空白。这一条决定了图表应走 SVG（`fill` 属内容）而非 CSS 色块。
- **P-28 后重算**：HTML 成为并列成品后，打印不再是"教师自己想办法"，而是 HTML 产物的正式使用场景之一（投屏、打印学案都用它）。补 `print-color-adjust:exact` 与 `@media print` 里按描边区分，属产物达标项，不是可选优化。
- **建议**：补 `print-color-adjust:exact`，并在 `@media print` 中把依赖底色的区分改为描边或图案。

### P-22 机械复核能力与规范承诺不符（L3）

- **现象**：`verify_rendered_outputs.py` 只做四件事——文件存在、字节非 0、HTML 能解析且可见文本非空、DOCX 包结构与 `<w:t>` 有字。它自述"不判内容"，但 [delivery-checklist.md:60](../.agent-presets/geo-teacher/skills/cn-high-school-geography-lesson-planning/references/delivery-checklist.md)（第 27 条）承诺能查"没有空块或只有标题的文档"。
- **实测**：`{"title":"只有标题","sections":[]}` 退出码 0；块类型拼错为 `tabel` 时正文只剩标题，退出码 0。
- **未覆盖项**：空块、只有标题、三件套齐全、`phase_header.minutes` 求和、课标原文出现次数、占位指令（"此处插图""播放相关视频"）、学生面泄漏关键词、表格列数与行格数不符（P-12）、悬空 `from_shared` 键（P-11）。
- **建议**：把第 27 条承诺与脚本能力对齐——或补检，或把承诺收窄到脚本实际范围。
- **P-28 后重算**：HTML 成为并列成品后，"只有标题""空块"这类检查不再是可省项——HTML 若单独发给教师，它就是唯一依据。至少要能查：块类型是否被识别（未知类型当前静默丢弃）、表格列数与行格数是否一致、`from_shared` 是否悬空。

### P-23 手工条块无复算机制（L3）

- **现象**：数值到条块长度这一步全靠模型心算并键入字符，无脚本、无校验。
- **建议**：随 P-20 一并解决；在 `chart` 落地前，至少提供一个"数值→格数"的辅助函数与自检（数值列与条列可互相复算，不一致即报错）。

### P-24 `lesson.json` 无结构校验（L3）

- **现象**：无 schema、无重复键检查、无未知块类型检查。`from_shared` 悬空键静默返回空（`lesson_common.py:352`）；块类型拼错静默渲染为空；`shared` 值若是无 `type` 又无 `text/items` 的 dict，会被字符串化为 Python dict repr 打进成品。
- **影响**：P-11、P-12 这类错误全部无法被发现；一次实测中整道高考真题因此从未进入成品。
- **建议**：新增结构校验脚本，作为阶段 5 的强制门：悬空与未引用共享键、重复 JSON 键、未知块类型、`type:"faceted"`、表格列数与行格数不符、`phase_header.minutes` 求和。

### P-25 学生面泄漏检查只在规范里，脚本中为零（L3）

- **建议**：复用该词表扫描学生面；`audience` 在入口处统一归一化（小写、去空格、非法值报错）。

- **现象**：`test/` 下 7 个文件、124 项测试**没有任何一项**引用 `render_lesson_html`、`render_lesson_docx`、`render_documents`、`lesson_common`、`verify_rendered_outputs`；`scripts/geo-verify.mjs` 从不调用 Python，只把本技能登记为 `reference` 分级。HTML 与 DOCX 两份产物的等价性仅靠源码注释里的口头约定。

- **现象**：`lesson_common.py:26` 把 `■`（U+25A0）定义为"未知数符号"，正文出现且未含定义词时自动追加"符号 ■ 表示未知数"。地理图表用 `■` 作图例色块会命中。

### P-29 HTML 产物缺网页基础结构（L3，2026-11-15 新增）

- **现象**：实测三份产物（教学设计 26.9 KB / 78 个 `<div>`，学生学习材料 22.1 KB / 90 个 `<div>`），网页该有的基础结构全部缺失：

| 项 | 实测 | 后果 |
| :-- | :-- | :-- |
| `<h1>/<h2>/<h3>` | **0 个**；标题全是 `<div class="h1/h2/h3">` | 无文档大纲，无法生成目录，屏幕阅读器跳不出标题，浏览器"查找"定位困难 |
| `lang="zh-CN"` | **0 处** | 浏览器可能按西文规则断行与选字体；屏幕阅读器用错误语音规则 |
| `<meta name="viewport">` | **0 处** | 手机、平板上版式失控 |
| `@page` | **0 处**（CSS 无任何 `@page`） | 打印页边距不可控，只能靠浏览器默认 |
| `print-color-adjust` | **0 处** | 表头底色、卡片底纹打印后消失（P-21） |
| `<img>` / `<svg>` | **0 处** | 无图（P-19、P-20） |
| 语义标签 `<main>/<section>/<nav>` | **0 个** | 全 `<div>` 堆叠；`<table>` 有 20 个但无 `<caption>`、无 `scope` |
| CSS 单位 | `pt` 47 处 | `pt` 是打印单位；屏幕上不随用户字号缩放，无障碍设置失效 |

- **证据**：`render_lesson_html.py:99-101` 输出 `<div class="h2">`、`:324` 的文档外壳只有 `charset` 与 `<title>`；`theme.css` 93 行内 `@page`、`print-color-adjust` 均 0 命中。
- **判断**：这不是"没做优化"，是**产物的语义层完全没建立**——它长得像网页，实际是一张用 div 定位的纸。定位改为并列成品后，这一条从"可选"变成"产物不达标"。
- **建议**：见 §9.3 第一步。改动集中在 `render_lesson_html.py` 的 `render_block` 与文档外壳，不触及 DOCX。

## 9. HTML 并列为成品后的解法（2026-11-15）

### 9.1 定位改了，剩余问题的性质也变了

P-28 之前，HTML 的问题按"预览够不够用"衡量，所以 P-19、P-20、P-21、P-22 都被判为可选。定位改为并列成品后，同一批问题要按"这份产物教师能不能直接用"重新判：

| 问题 | 旧判断 | 新判断 |
| :-- | :-- | :-- |
| P-19 无图片通道 | 预览不必有图 | HTML 与 DOCX 都要有，否则含图题无法交付 |
| P-20 无图表块 | 表格打印够用 | 两处都要能画，且必须是同一张图 |
| P-21 打印无底色 | 打印交给 DOCX | HTML 的正式用法之一就是打印学案 |
| P-22 校验只查非空 | 预览不值得查 | HTML 可能是唯一依据，空块等于交付失败 |
| P-29 无语义结构 | 未列入 | 产物不达标（新增） |

一句话：**以前是"给预览补功能"，现在是"两份产物各自要达到可用标准"。**

### 9.2 四层解法与依赖

```
第一层 语义层（P-29）        最便宜，先做；只动 HTML 渲染器
      ↓
第二层 打印形态（P-21）      只动 theme.css
      ↓
第三层 图形能力（P-19/P-20/P-10/P-23）  最贵，动两个渲染器 + 共用几何函数
      ↓
第四层 校验（P-22/P-24/P-25/P-26）      贯穿全程，第三层落地前必须先补测试
```

**为什么第四层要提到第三层前面**：HTML 与 DOCX 是两条独立 if 链（`render_lesson_html.py:89` 起 21 个分支 vs `render_lesson_docx.py:590` 的 `_EMITTERS`），`test/` 下 124 项测试**没有任何一项**引用它们（P-26）。第三层要新增块类型、改两个渲染器，没有测试守着，两边必然分叉——而分叉的后果正是这次 P-10 的形态：HTML 与 DOCX 各画各的，数值对不上。

### 9.3 第一层：语义层（P-29）

**目标**：让产物真的是一个网页，不是用 div 定位的纸。

| 改什么 | 现在 | 改成 | 成本 |
| :-- | :-- | :-- | :-- |
| 标题 | `<div class="h2">…</div>`（`render_lesson_html.py:99-101`） | `<h2>…</h2>`，保留 class | 3 行 |
| 文档语言 | 无 | `<html lang="zh-CN">` | 1 行 |
| 视口 | 无 | `<meta name="viewport" content="width=device-width, initial-scale=1">` | 1 行 |
| 主体 | `<div class="page">` | `<main class="page">`，每节 `<section>` | 少量 |
| 表格 | `<table>` 20 个，无 `caption`、无 `scope` | 表头加 `scope="col"`；图表类表格加 `<caption>` | 中 |
| CSS 选择器 | `.h1/.h2/.h3` | 同时匹配标签，`.h2, h2 { … }` | 3 条 |

**为什么值得做**：现在教学设计 12 个板块、26.9 KB，全靠 div 堆叠，浏览器无法生成大纲、无法用"查找"跳转、屏幕阅读器读不出一级结构。教师拿到一份 12 节的教案，**没有目录也没有标题层级**，只能从头滚。

**附带能拿到的**（成本很低，可选）：
- 自动生成目录锚点，屏幕顶部固定导航（12 节的教学设计尤其需要）；
- `@media screen` 下把 `.page` 宽度放开到 `min(100%, 7.1in)`，平板上不再横向滚动。

**风险**：`theme.css` 自称"designer-editable"，改选择器属于对外可见的改动。做法是**保留 class 名同时匹配标签**，旧样式仍生效，不破坏任何既有自定义。

### 9.4 第二层：打印与屏幕双形态（P-21）

现状：`theme.css` 93 行，`@page` 0 处、`print-color-adjust` 0 处，`pt` 47 处。

| 改动 | 内容 |
| :-- | :-- |
| `@page` | `@page { size: A4; margin: 18mm 18mm 16mm; }` ——与 DOCX 的 A4 + 0.7in 边距对齐，两种产物页边距一致 |
| `print-color-adjust` | `* { -webkit-print-color-adjust: exact; print-color-adjust: exact; }`——否则表头底色、标注框底纹打印后全白 |
| 黑白可辨 | 依赖底色的区分（表头、`.co.special` 等）补一条左侧 2pt 描边或图案，不只是颜色差 |
| `@media screen` | `.page { padding: 32pt 24pt }` 保持不变；宽屏下允许 `max-width: 9in`，避免大屏两侧大片留白 |

**单位问题要单独说**：`pt` 是打印单位，屏幕上不随浏览器字号设置缩放，无障碍上有损失。但我**不建议**改成 `rem` 或 `px`——DOCX 侧全部用 `Pt()`，一旦 HTML 改相对单位，两边字号就对不上，"同一份材料源两种呈现一致"这个前提就破了。**保留 `pt`，用 `@media screen` 做缩放适配**，是两边一致与屏幕可读之间更稳的取舍。

### 9.5 第三层：图形能力（P-19 / P-20 / P-10 / P-23）

**核心原则：几何只算一次，两处只负责画。**

```
lesson.json（数值）
      ↓
lesson_common.py  一个函数：每根条的起点、长度、标签位置、刻度值
      ↓                          ↓
HTML: 拼 <svg> 矩形        DOCX: Pillow 按同一坐标画进 PNG → add_picture
```

**为什么必须共用**：如果两边各算各的，就会出现 HTML 里 42.6 与 36.5 差得明显、DOCX 里看着差不多——这正是 P-10 已经发生过的错误形态。

#### 图块 `chart` 的字段

```json
{"type": "chart",
 "title": "图1  三次产业结构（2024年，单位：%）",
 "series": [{"name": "焦作", "values": [6.1, 42.6, 51.3]},
            {"name": "全国", "values": [6.8, 36.5, 56.7]}],
 "categories": ["第一产业", "第二产业", "第三产业"],
 "max": 60, "unit": "%",
 "note": "同一年、同一口径直接比较；数据见材料10、材料11"}
```

- `note` 承载来源注，解决 P-10 的"四图无来源行"。
- `max` 显式给定，避免自动缩放造成"两组图纵轴不同"的误读。
- 数值由 `lesson_common` 换算成坐标，**模型不再键入 `█`**（P-23 消失）。

#### HTML 侧：原生 SVG

- 零依赖、矢量、任意缩放清晰、文字可选中；
- `fill` 属内容不属背景，**不依赖 `print-color-adjust` 也能打印**（这是选 SVG 不选 CSS 色块的直接原因）；
- 焦作与全国用"实心/空心 + 灰阶"区分，黑白打印仍可辨。

#### DOCX 侧：Pillow 画 PNG 后 `add_picture`

已实测（2026-11-15）：

| 检查项 | 结果 |
| :-- | :-- |
| `matplotlib` | **未安装**（`ModuleNotFoundError`） |
| `cairosvg` / `svglib` | **未安装**（无法把 SVG 转位图） |
| `Pillow` | **12.3.0 已安装** |
| 中文字体 | `simhei.ttf`、`simsun.ttc`、`msyh.ttc` 齐全 |
| `add_picture` 接受流 | 签名 `(image_path_or_stream, width, height)`，`BytesIO` 直接可用，**不必写临时文件** |
| 300 DPI 实测体积 | 图1 1920×501 px / 14.6 KB；图4 12.5 KB；四图合计约 55 KB |
| 中文标题与数值渲染 | 正常（已生成样图目视确认） |

**三条被排除的方案**：

| 方案 | 排除理由 |
| :-- | :-- |
| SVG 直接嵌 DOCX | python-docx 无 API，需手拼 OOXML 并附 PNG 回退；**WPS 对 DOCX 内 SVG 渲染不可靠**，教师机上一半会空白 |
| EMF/WMF 矢量图 | Windows 专有，Python 侧无可靠生成器，换 Mac 即失效 |
| 表格铺底色格当条形 | 列宽只能等分，`42.6%` 与 `51.3%` 只能靠"占几格"近似，**等于把 P-10 换个形式复现** |

**必须处理的坑**：

1. **字体缺失要显式报错**。`C:\Windows\Fonts\simhei.ttf` 是硬编码；字体加载失败时 PIL 会静默回退到位图字体，中文变方块——无提示的失败。必须 `CJK_FONT_NOT_FOUND` 直接失败。
2. **DPI 与物理尺寸钉死**。A4 左右边距 0.7in → 可用 6.87in；图片固定 `width=Inches(6.4)`，300 DPI，PNG 带 dpi 元数据。
3. **禁用 `■`**（P-27）。`lesson_common.py:26` 把它定义为"未知数符号"，图表用它作图例会给学生材料注入一句数学说明。图例用 `█` 或 SVG 矩形，不用 `■`。

#### 图片块 `image`

```json
{"type": "image", "src": "…", "alt": "沙哇伦多城市发展生命周期图",
 "caption": "图5  沙哇伦多城市发展生命周期（2024湖南卷第17题配图）",
 "width_in": 5.6}
```

- **HTML**：`src` 转 base64 内联。产物是单文件，可直接发给教师、可直接打印，不依赖任何外部目录。
- **DOCX**：解码回 `BytesIO` 交给 `add_picture`。**同一张源图，两种封装**。
- **`alt` 必填**，既是无障碍要求，也是图缺失时能看出缺了什么。

这条直接解决 P-14：湖南卷第 17 题配图在本地题库（`data/obsidian_vault/90_附件/题目图片/湖南/2024/…G17__shared__01.png`，34 KB），接上即可。

#### 图表块与图片块的边界

| | `chart` | `image` |
| :-- | :-- | :-- |
| 数据来源 | `lesson.json` 里的数值 | 外部已有位图 |
| HTML | 生成 SVG | base64 `<img>` |
| DOCX | 用 Pillow 画 | `add_picture` |
| 是否可复算 | **是**（数值→长度由脚本算） | 否（原图） |

### 9.6 第四层：校验（P-22 / P-24 / P-25 / P-26）

顺序上**要在第三层之前或同时**做，否则改两个渲染器无回归保护。

| 项 | 做什么 | 优先级 |
| :-- | :-- | :-- |
| **P-26** | 给渲染侧建最小测试：同一份 `lesson.json` 渲染出的 HTML 与 DOCX，**提取纯文本后应逐段一致**；`chart` 落地后加一条"两种画法的比例一致" | **最高**，第三层的前置 |
| **P-24** | `lesson.json` 结构校验：未知块类型、悬空 `from_shared`、未引用共享键、表格列数与行格数不符、`phase_header.minutes` 求和、`type:"faceted"` | 高，一次能拦掉这次 P-11、P-12 两类错 |
| **P-25** | 学生面泄漏：复用命题侧 `plugins/question/package.js:44-54` 的 `STUDENT_LEAK_PATTERNS`；`audience` 入口归一化 | 高 |
| **P-22** | 扩展 `verify_rendered_outputs.py`：空块、只有标题、占位指令、三件套齐全 | 中 |

**关于"硬门还是提示"**：我建议**结构校验（P-24）作硬门**，因为它查的都是"内容会不会丢"一类不可接受的问题；**verify 的内容项作提示**，因为它查的是质量，误判时不该阻塞交付。这个区分要在规范里写清楚，否则模型遇到硬门会想办法绕过。

### 9.7 不建议做的

1. **不迁移 CSS 单位**（`pt` → `rem`）。会让 HTML 与 DOCX 字号失去对应关系，得不偿失。
2. **不在 HTML 里加 JS 交互**（折叠、答题输入、自动评分）。产物要被教师直接分发和打印，加了 JS 的打印与存档风险大于收益；目录锚点这类纯 CSS/HTML 能解决的除外。
3. **不改 `--format` 语义，不强制同时出 DOCX**。教师选 HTML 就只出 HTML；选了 DOCX 才同时出 HTML 孪生件。
4. **不为追赶"网页感"重写渲染器**。现在的字符串拼接虽然朴素，但它零依赖、可预测、产出稳定；问题在词汇表与语义层，不在实现方式。

### 9.8 验证方式

| 层 | 怎么验 |
| :-- | :-- |
| 第一层 | 渲染后查 `<h1>/<h2>/<h3>`、`lang`、`viewport` 计数非 0；浏览器大纲视图能看到层级；`theme.css` 旧选择器仍生效 |
| 第二层 | 浏览器打印预览：底色保留、页边距为设定的 A4 值、黑白模式下表头与正文可区分 |
| 第三层 | 同一份 `lesson.json` 出的 HTML 与 DOCX，**量同一根条的长度比**是否一致；四幅图数值逐条复算；字体缺失时能报 `CJK_FONT_NOT_FOUND` |
| 第四层 | 造错样本：拼错块类型、留一行 3 格、删掉一个 `from_shared` 引用、把 `audience` 写成 `Student`，四个样本都应被拦下 |

| 步 | 内容 | 为什么排这里 |
| :-- | :-- | :-- |
