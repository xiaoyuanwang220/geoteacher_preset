# 课程方案生成流程优化方案

状态：**已实施（源码，2026-11-10）**，桌面端运行时待验收。§3.3（28 条自查分析）本期只分析、不改清单，A/B 对比待做；实施记录与验证见 §7。

## 1. 要解决的问题

1. **构思确认被跳过**：教师首轮提出需求后，模型在部分会话里直接生成，没有先给构思让教师确认。
2. **思考时间偏长**：同一份课要读多份原文、多次联网核验、跑两轮自查，重复劳动占比高。
3. **引用靠记忆**：阶段 1 核到的课标与教材原文没有落盘，阶段 5 引用时重新打开或凭上下文复述。
4. **references 全量读取**：技能文件被整份读取，而不是按阶段取需要的小节。

目标：不牺牲质量底线，把重复劳动去掉，并让"先构思、后展开"稳定发生。

## 2. 不变量

课标原文可核验、教材边界、来源与地图合规、目标—活动—评价对应、三件套与渲染契约、交付前自查、教师确认门。这些不因提速而删减。

## 3. 优化项

### 3.1 阶段 1 依据落盘

**做法**：阶段 1 核到的依据写成 Markdown 文件，后续引用只对照该文件。

- **位置**：`<输出目录>/<课题>/依据-<课标编号>.md`；教师未指定输出目录时默认 `outputs/教学设计/<课题>/依据-<课标编号>.md`，与 `lesson.json` 同目录。
- **必须内容**：

  | 块 | 字段 |
  | :-- | :-- |
  | 课标 | 模块、条目编号、**原文逐字**、来源文件名与章节/页码、读取日期 |
  | 教材 | 版本印次、章节、页码、本课用到的图号表号、与边界相关的原文摘录 |
  | 素材 | 主情境每份材料：来源机构、标题、发布日期、访问日期、口径与单位、原文摘录、直接链接 |
  | 边界 | 本节范围、明确不展开项、前置已学项 |

- **规则**：
  1. 阶段 1 未写完 `依据-<课标编号>.md` 不得进入阶段 2；
  2. 阶段 4 写引用、阶段 5 自查与交付核对，一律以该文件为准，不凭记忆或会话上下文复述；
  3. 文件缺失或内容与本课不符：停止并说明，不用记忆补；
  4. 同一课题修改沿用同一文件，追加"修订日期"一行，不改写已核原文；
  5. 该文件是教师可核对的依据附录，可选随交付附上；不并入 `lesson.json`。

- **收益**：防记忆漂移、引用可审计；阶段 2、5 不再重复打开课标与教材原文件。

### 3.2 references 按需、渐进加载

**做法**：只读当前阶段需要的文件和小节，不预读、不整篇通读。

| 阶段 | 只读 | 不读 |
| :-- | :-- | :-- |
| 1 取依据 | `subject-notes.md`「一、课标定位与解读」 | 认知深度、灵感索引、借角度 |
| 2 选材料 | `source-and-map-policy.md`「来源优先级」「联网核验」「案例使用规则」 | 地图教学中完整的图件规则（无地图时） |
| 3 构思 | `subject-notes.md`「选择认知视角」或「认知深度」（按需取一） | 课标解读成文规则 |
| 4 写材料源 | `lesson-format.md`「一、材料源」「二、教学设计」「三、学生学习材料」 | 静态文件不重读，缺字段时只查块类型表 |
| 5 自查与渲染 | `delivery-checklist.md`「适用范围」「使用方式」＋适用条目 | 不适用的条件条目 |

- **需要写进 `SKILL.md` 的两条**：① 不预读后续阶段的 references；② 同一文件只读需要的章节（大文件按标题定位读取，不整篇拉取）。
- **注意**：`lesson-format.md` 与 `subject-notes.md` 篇幅中等，先按节读取即可，暂不拆文件；若实测仍偏长再评估拆分。

### 3.3 28 条自查的有效性分析

**结论：单条大体有效，但"不分任务、全量逐条"执行的方式低效。** 保留条目，改变执行方式，并补 3 项机械核对。

**支持有效的证据**：

- 2026-11-09 的复习课会话做了两轮自查，抓出 6 类实质错误（教材原文冲突、过度断言、意义条数与教材不符、数量级算错、题干泄露判断结论、教案缺结构卡与数据），修复后才渲染。
- 本轮实测五份产物：渲染复核全部退出码 0、学生材料无教师话术泄漏、课标完整引用各 1 次、无占位指令——分别对应第 21、22、27 条与引用规则，说明条目在产物上确实可判别。

**执行方式的问题**：

| 问题 | 说明 |
| :-- | :-- |
| 适用集不清 | 28 条里，讲授/复习课实际适用通常不超过 10 条；模型容易逐条过一遍，多数空转 |
| 条件化后仍全过 | 第 6—9、11—19 条已改为条件式，但执行时仍被逐条登记 |
| 条目重叠 | 第 11/12/14 条都在查"提问是否装得下"；第 16/19 条都在查"成果是否成立"；第 5 与第 22 条在"材料/答案是否干净"上相邻 |
| 可机械判定的仍人工过 | 三件套齐否、教案与学案一致、占位指令、渲染成功——多数可由脚本或结构核对完成 |
| 两轮自查无收益 | 第二轮通常只重复第一轮的判别动作；除修复后复查受影响条目外，没有额外检出 |

**覆盖盲区**（现有 28 条查不出的）：

1. **模型自述与产物不一致**：实测中复习课最终汇报写"四个环节 4+12+8+8=36"，产物实际是 5 环节共 40 分钟——产物对、自述错，清单不覆盖汇报层。
2. **数字自洽**：环节时长求和、数量级、单位与口径换算，清单只在第 4 条擦边。
3. **引用唯一性**：课标原文"教学设计中只完整出现一次"，第 1 条不查次数。

**建议**：

- 阶段 6 先勾出**适用集（≤10 条）**，只对适用集做判别动作；跳过的条目不登记、不计入问题数（现有"使用方式"已允许，需强调）。
- **默认只跑一轮**；只有发现缺陷并修复后，才对受影响条目复查。
- 把可机械判定的五项（三件套/占位/引用次数/时长求和/教案与学案一致）移入交付前机械核对（脚本或最后一遍结构化检查），不再靠人眼。
- 第 11/12/14 合并为一条"问题链容量够吗"，第 16/19 合并为一条"成果立得住吗"；28 条可压到 24 条左右，语义不变。

**本期执行范围**：只保留以上分析，**不改条目、不合并、不删**；按 §5 先做 A/B 对比（同一课题：适用集＋一轮 vs 全量两轮）再定稿。

### 3.4 构思确认门（硬停）

- **触发**：教师首轮提出需求后，先出构思卡，结束本轮等回复；除非教师明说"直接生成/不用确认"。
- **构思卡（≤5 行）**：教学核心、学生最可能卡住的地方、主线怎么走、主要取舍、已知风险。
- **授权边界写死**：给输出路径、命名、格式要求，**都不等于**允许直接生成。
- **固定开头**："先给你五句话的构思，确认或改完我再展开。"
- **工作台按钮**：`packages/dsh-geo-teacher-ui` 的"生成课程方案"建议改为"开始构思"（跨包，单独实施）；**本期不改**，靠技能正文的硬停与授权边界约束。
- **验收**：首轮停下的比例；未确认就进入展开的次数为 0。

### 3.5 流程由 8 段压到 5 段

| 新流程 | 对应原阶段 | 变化 |
| :-- | :-- | :-- |
| ① 取依据并落盘 | 0、1 | 只读本课条目与章节；写 `依据-<课标编号>.md` |
| ② 选材料 | 2 | 只核主情境 1—2 份；示意图按图号登记 |
| ③ 出构思并停 | 3、4 | 构思卡 ≤5 行；硬停等确认 |
| ④ 写材料源 | 5 | 按块模板一次写完 |
| ⑤ 一轮自查＋渲染＋机械复核 | 6、7 | 自查一轮；机械项交脚本；首次只渲染 HTML，DOCX 待教师确认 |

## 4. 验收指标

| 指标 | 目标 |
| :-- | :-- |
| 首轮确认率 | 3/3 任务首轮停下；未确认即展开 = 0 |
| 依据落盘 | 每份交付存在 `依据-<课标编号>.md`；抽查 3 处引用与原文逐字一致 |
| references 读取 | 单任务 ≤4 次读取；总读取字符数明显下降 |
| 自查 | 一轮；适用集 ≤10；真错捕获数不低于本次基线（复习课 6 类） |
| 机械核对 | 渲染复核 0 失败；三件套/引用次数/时长求和/占位全过 |
| 耗时 | 会话读取类工具调用减少 ≥1/3；总时长下降（以同任务复跑对比） |

## 5. 风险与对冲

- **依据文件成为新事实源**：若更新不及时会误导后续引用。对冲：引用前核对文件日期与内容，改动原文后追加修订行。
- **按需加载可能漏读必要小节**：对冲：加载表兜底；漏读会在自查或引用核对时暴露。
- **自查精简可能漏检**：建议先做 A/B——同一课题分别用"适用集＋一轮"和"全量两轮"各跑一次，比较缺陷捕获数，再定稿。
- **硬停多一次教师回复**：换来的是减少"生成完才发现方向不对"的返工，总时长通常更短。
