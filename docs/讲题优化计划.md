## 目标与范围

教师直接使用现有带答案的 Markdown 题库，系统自动完成“独立解题 → 核验 → 讲稿”，无需教师分别提供题面和答案。

本期只处理自身题库的 MD 格式。考点库继续提供知识分类；答案隔离发生在题库读取和解题执行环节。Word、PDF 后续接入同一流程。

## 一、插件负责答案隔离

复用现有 core 的题库解析和 analysis 的工具入口，增加独立解题执行能力，不另建重复题库。

1. **分离题答。** 后台读取完整 MD，分别整理题面与答案解析。解题输入只含材料、题干、选项、小问和题面图片；解析图、答案标记和解析派生的考点提示不进入解题输入。无法判断边界时指出具体题目，请教师确认。
2. **独立执行。** 先核实 DSH 创建全新上下文及限制工具权限的接口。解题会话不继承主会话历史，只能获取题面、提交作答；不开放原文件读取、Shell、联网、命题分析及任意代理调用。原卷和完整索引由后台持有，不能放入解题侧可访问的目录或接口。界面中的提醒不代替权限限制。
3. **提交后核验。** 服务端保存独立答案和关键依据，绑定运行、题目及题面版本，再把参考答案交给核验阶段。原始作答保持不变，修正答案另存；题面变化后重新解题。存在相互提示的小题按题组提交后统一核验。

流程只保留必要状态：题面就绪 → 作答已提交 → 核验完成。调用答案接口不能绕过作答提交；核验完成表示已完成对照，不等于内容自动正确。

## 二、接通讲题流程

- **只问怎么做：** 返回独立答案与关键依据。
- **要求讲题：** 连续完成解题、核验和讲稿，中途不重复询问是否继续；缺少关键题面或图片时才暂停。
- **核验：** 比较独立答案与参考答案，记录一致、遗漏、错误和争议，形成修正结论。取得参考答案只是开始核验，不能直接当成核验完成；参考解析有疑点时保留分歧。
- **成稿：** 使用同题的作答与核验结果。切换讲解对象复用结果，不重新解题；模型自己的错误不写成真实学生学情。
- **命题研究：** “分析命题设计”走 geo_analyze；需要把已核验结果整理成命题人讲稿时才走讲题流程。

保留 geo_solve、geo_judge、geo_explain 的入口名称，调整其执行与交接契约：解题由隔离环境完成，核验读取服务端保存的作答，讲稿读取对应核验结果，不依赖主模型自称已完成前序步骤。

## 三、收拢 Skill 与插件职责

| 位置 | 唯一职责 |
| :-- | :-- |
| persona | 需求路由、讲题流程入口和答案隔离底线 |
| 解题 Skill | 独立读题、读图、推导与作答方法 |
| 讲题 Skill | 流程编排、对象选择和交付要求 |
| 讲题 references | 学生、教师、命题人的具体写法与质量标准 |
| core / analysis | 数据分离、隔离执行、作答保存、核验交接和状态 |

将 core 中的大段语言指南、教学话术移入技能规范，检查消费者后清理相关字段与渲染。四段式和对象细则只维护一份，其他位置引用；工具描述只说明用途、参数与前置条件。

## 四、改善讲稿

- **学生版帮助学生理解并学会解决这类问题。** 讲清本题考查的知识点及其在解题中的作用，按清晰的顺序展示如何理解设问、发现材料线索、选择知识、逐步推理和检查答案。每个关键步骤说明“为什么这样想、依据是什么、怎样得到下一步”，不能只列步骤或给出答案。最后结合题库相关题目的比较，告诉学生遇到同类问题如何识别、从哪里入手、怎样解决，以及条件变化时如何调整。
- 命题人版评价考查目标与题目设计。
- **教师版以培养学生解决问题的能力为核心。** 围绕本题设计启发性问题，让学生自己识别问题、提取证据、选择知识、提出解释并检验结论。讲稿交代关键追问的目的、学生需要完成的思考、遇到困难时的提示，以及何时撤去提示让学生独立解决，避免教师直接宣布步骤或用连续诱导问答代替学生思考。
- **两版的同类问题解法都以题库比较为依据。** 先按设问任务、推理关系和材料特征检索相关题目，不能只因考点相同就归为同类。比较本题与相关题目的共同解题步骤、条件差异和方法适用边界。学生版将结论转成易懂、可执行的解题方法；教师版进一步说明如何引导学生通过比较自己归纳方法。总结须列出所依据的题目及具体对应关系，不能凭单题经验编造通用套路；相关题目不足时明确缺口，只保留本题可支持的结论。
- 同类题比较安排在本题独立作答提交之后；若相关题目用于学生独立迁移练习，教师版说明要观察哪些表现来判断学生能否迁移，学生练习材料不提前给出答案。
- 学生、教师版保留四段式，按题目复杂度分配篇幅，不为填满模板重复解释。
- 额外变式与跨学科内容按需加入，不替代两版必需的题库比较与方法总结。自拟变式明确标注，真实题库变式经检索取得。
- 教学判断由模型完成；插件不把固定话术当成教学质量保证。

两版共享知识依据、正确解题过程和同类题比较，不做互斥切分，也不要求机械套用同样的篇幅。输出侧重如下：

| 内容 | 学生版侧重 | 教师版侧重 |
| :-- | :-- | :-- |
| 考查知识 | 考什么知识点、为什么用它、它怎样帮助解题 | 学生需要建立哪些知识联系，如何引导其选择并运用知识 |
| 解题过程 | 清楚展示怎么想、怎么做、每步依据和关键辨析 | 在关键处怎样提问、提供提示和检验学生理解，逐步让学生独立完成 |
| 同类问题 | 用易懂的方法说明如何识别、入手、推理及调整 | 怎样用题库相关题目的比较，引导学生自己归纳方法与适用条件 |
| 迁移运用 | 知道换一道相关题时如何使用方法 | 怎样安排独立尝试，观察学生是否真正具备解决问题的能力 |

学生版可以有启发性提问，教师版也必须讲清正确解法；区别在于前者主要回答“我怎样学会做”，后者主要回答“我怎样教会学生做”。

## 五、实施顺序与完成标准

| 顺序 | 工作 | 完成标准 |
| :-- | :-- | :-- |
| 1 | 核实 DSH 隔离接口，接通 MD 题面与独立解题 | 新上下文只收到题面，无法通过其他工具或接口读取原卷与答案 |
| 2 | 保存作答，接通核验与讲稿 | 未提交不能取答案；同题作答、核验和讲稿连续衔接；原始作答可查看 |
| 3 | 精简规则，调整三对象讲稿 | 教学规则归属明确，完整讲题无多余确认；学生版讲清考查知识与思考过程，教师版突出启发与能力培养；两版的同类问题解法均有题库比较依据和适用条件 |
| 4 | 用现有题库走通实际会话 | 选取覆盖选择题、综合题和读图场景的四道题，检查答案隔离与讲稿质量 |

沿用现有源码检查；只补答案提前访问、题答图片分离、作答绑定等关键行为检查，不另建测试平台。部署后跑一次真实讲题流程，核对解题输入、作答保存时间和答案开放顺序。

文档直接更新现有讲题设计、技能与评测说明，本计划随实施勾清进度，不再增加修订版或阶段记录。

## 后续：Word 与 PDF

MD 链路稳定后增加文件导入与题答分离，复用上述隔离、提交、核验和讲题能力。先支持题目与答案分区明确的文件，再处理扫描卷和题答混排；教师始终只需导入一次带答案原卷。
