# 解决方案：组件粒度（点得到单个箭头）+ 接入流程（agent 不用猜）

> 日期：2026-10-25 ｜ 状态：**方案（未实施）** ｜ 依据：`docs/modelcheck/标注粒度问题分析.md`、会话 `session-5d6d640e…` 原始日志、当前插件代码
> 范围：网页路线（Three.js / SVG / DOM / 图像叠加）；Blender 仍在一期之外。
> 目标：**点得到具体组件/实例、标注能落到代码；接入时 agent 不需要读插件源码，也不需要反复试错。**

---

## 0. 一页摘要

| 问题 | 根因 | 方案 | 效果 |
|---|---|---|---|
| 标注点不到“某一个箭头” | 箭头被 `InstancedMesh` 打包、流管被合并；bridge 丢弃 `instanceId`；注册表只有组件级 | **只对“文字说不清”的几何做分层身份**：结构 / 区域 / 环流圈 / 气压带风带 / 箭头 / 几何部件 / 图像区域；保留实例化，给每个子单元稳定 key；bridge 回报 `instanceId`+命中链；注册表 `component.parts/instances`；规则/证据支持 `组件#子单元` | 地球、气压带、风带、环流圈、边界线、单支箭头都能点到正确层级；文字标签和命名控件不做点选；不拆模型、不撑爆注册表 |
| 初始化后 agent 仍要摸索很久 | 初始化只给 config/components，没给“模型现状/接线要求/校验入口”；候选名字与场景对象名不一致；交付版和校验版入口混用 | **接入就绪清单（readiness）**：init 返回“哪几件事没做、怎么做”；新增 `preview.verifyEntry`/`deliveryEntry`；verify 先预检再取证；给 agent 一页接入指南 | 47.5 分钟接入 + 34.5 分钟失败尾巴 → 目标 **10–15 分钟、少于 20 步** |

一句话：**身份要“生成时就有”，接入要“一次讲清”；不靠 agent 读源码猜，也不靠把模型拆散。**

**核心边界（本方案的总原则）**：**点选只聚焦模型本身**——预览里真实渲染的三维几何与图像叠加区域（地球、环流圈、气压带/风带、边界线、箭头、区域）。
文字标签、二维控件、文档与页面框架都不进入点选；它们由对话文字指代，必要时用 `text` 规则对数据/源码判定。

## 1. 问题回顾（实测）

### 1.1 颗粒度（来自代码与现场）

- 箭头：`模型源码/src/geo.js:285-287` 用 `THREE.InstancedMesh` 一次画一组箭头 → 场景里没有“第 3 个箭头”这个对象，只有 `instanceId`。
- 流管：`模型源码/src/main.js:150-165` 用 `mergeGeometries` 把同类流管合并成一个 Mesh → 合并后不存在子对象身份。
- bridge：`packages/dsh-modelcheck/assets/bridge.js:1245-1272` 射线命中后只取 `hits[i].object`，**丢弃 `hit.instanceId`**；`matchComponentForObject`（1138-1160）只按 `name`/`userData.mcId` 匹配**已登记**组件，未命中返回 `null`。
- 初始化候选来自 `data.js` 的 `name:`（中文标签），场景名却是 `mccell-*`/`mcbelt-*`/`mcearth` → `pick` 对不上，点中也不匹配。

### 1.2 接入耗时（`session-5d6d640e…` 日志统计）

| 时段 | 墙钟 | 工具调用 | 工具耗时 | 发生了什么 |
|---|---|---|---|---|
| 20:27–20:45 | 18 min | 18 | 5 s | 工作区根没有 `.modelcheck`，未绑定，白跑 |
| 22:13–23:00 | **47.5 min** | 48 | 115 s | 读插件源码 17 次、改模型/构建 16 次、手写组件与契约 |

**工具只占 3–4%，95% 是模型往返与试错**；关键浪费是“接线规则靠 agent 自己发现”和“校验版入口没概念”。

## 2. 总体思路

三样东西一次给 agent，而不是只给目标：

1. **身份（Identity）**：每个可标注单元（组件或实例）有稳定、可复现的 id，并能映射到代码位置。
2. **地图（Readiness）**：初始化直接告诉 agent 当前缺哪几根线、每根怎么接（钩子、pick、入口、产物）。
3. **规矩（Division of labor）**：agent 起草/修改，用户确认契约与人工验收，面板负责运行时取证；工具在“做不了”时给诊断而不是让 agent 重试。

## 3. 方案 A：组件粒度（任意可标注单元，不止箭头）

### A0. 可标注单元谱系（先定“要标什么”）

**总原则：点选只聚焦模型本身。** 下面这些“模型内几何/区域”才是可点选单元；页面上的文字标签、二维控件、文档与框架一律不点。

“颗粒度”不是只讨论箭头。一个地理网页模型里至少有下面这些类别；每一类都要能回答“它是什么、怎么被唯一指认、改哪段代码”：

| 类别 `kind` | 例子（三圈环流） | 推荐标注层级 | 身份来源 |
|---|---|---|---|
| `structure` 结构体 | 地球本体、地轴、经纬网 | 整体即可 | `Object3D.name` + `userData.mcId`（已有 `mcearth`/`mclatgrid`/`mcaxis`） |
| `region` 区域 | 低/中/高纬环流区、极地 | 区域或整组 | Group name + `userData.mcId` |
| `cell` 环流单元 | 低纬环流圈、中纬环流圈、高纬环流圈、单圈环流 | 单元级；其回路/箭头可再细分 | 已有 `mccell-<id>` + `userData.mcId`；内部回路/箭头按需加 `parts`/`instances` |
| `belt` 气压带/风带 | 赤道低压带、副热带高压、东北信风带、盛行西风带 | **整带**为默认；边界线、单个箭头为可选子单元 | 已有 `mcbelt-<id>`；边界环/锚点作为 `parts` |
| `arrow` 箭头 | 风带箭头、环流回路箭头、偏转过程箭头 | 单支箭头（实例级） | `InstancedMesh` 的 `instanceId` + 实例目录（A2-B） |
| `image-region` 图像区域 | 水循环底图上的叠加区域 | 单个区域 | 注册的多边形/矩形区域 id |

**哪些不做点选（明确排除）**：

- **文字标签**（气压带/风带名称、步骤说明）：文字本身就是最好的指代，用户直接说“把‘东北信风带’改成……”，agent 按文案定位即可，不需要点；
- **有明确名称的二维控件**（右侧步骤按钮、显示/隐藏开关、图例）：用户说“某个环流圈的控制按钮”就能指代，点选没有增量价值；
- **文档里已有唯一名称、且不需要精确指几何位置的整带/整圈**：可以用文字指代；点选只在“整带/整圈本身难以描述或容易歧义”时作为便利。

> **点选只留给“说不清、容易指代错”的对象**：某一条边界线、某一支箭头、某处几何错位、某个区域的位置。能用一个名字/一句文字唯一说清的东西，不建点位。

**粒度由项目决定，不是越细越好**：默认标到 `cell`/`belt`/`structure`；只有确实“难以文字指代、且需要精确几何”的部件（如代表性箭头、边界线）才下探到 `parts`/`instances`。

### A1. 身份规范（对以上所有类别统一）

- **对象级（已有）**：`Object3D.name` + `userData.mcId`，如 `mccell-<cellId>`、`mcbelt-<beltId>`、`mcearth`。
- **子单元级（新增，`parts`）**：一个组件内部**有名字的不同部件**（如气压带的“色带 / 上边界 / 下边界”），每个 `partKey` 稳定，如 `band`、`ring-north`、`ring-south`。
- **实例级（新增，`instances`）**：同一类重复出现的部件（箭头、纬线圈），每个 `instanceKey` 稳定：
  - 由**数据生成**，不是数组下标裸用：`instanceKey = seriesId + ':' + index`（如 `belt:nh-trade/flow:top/3`）；
  - 生成器保证“同一数据 → 同一 key”，增删其它组件的实例不影响本组件 key；
  - 推荐选择写法：`组件 id#key`（如 `nh-trade-winds#belt:nh-trade/flow:top/3`）。
- 每个 `part`/`instance` 可选带：中文 `label`、`locator {file,symbol,line}`、自身 `observables`（位置/方向/可见性）。
- 组件的 `kind` 必须声明（A0 表），用于扫描分类、界面分组与自检。

### A2. 模型侧（按类别接线，两种做法，推荐 B）

| 类别 | 推荐做法 | 说明 |
|---|---|---|
| `structure`/`region`/`cell`/`belt` | 保持现有 Group + `name` + `userData.mcId`，再补 `userData.mcKind` | 已具备，只需补 kind；组件级点选已可用 |
| `belt` 子部件 | 把色带/边界环分别命名（`userData.mcPart='band'/'ring-north'/...`） | 想标“边界线”时才需要；否则整带即可 |
| `arrow` | A. 每支箭头独立 `Object3D`；**B. 保留 `InstancedMesh` + 实例目录（推荐）** | B：生成箭头时同步生成 `instanceCatalog=[{k,index,label?,locator?}]` 挂到 `mesh.userData.mcInstances`，并标 `userData.mcAnnotatable=true` |

> 文字标签、命名控件不进入点选清单，因此模型侧**不需要**为它们加 `data-mc-id` 或可点属性；它们继续用文字/配置定位。

- 不可标注的合并几何（如整片流管）保持合并；**不要为了标注把几何拆散**。
- 合并几何若要可点，用**不可见拾取代理**（每个可标注单元一个极小 `Object3D`，只参与射线，不渲染），或接受“只能标到组”。

### A3. 桥接协议（`assets/bridge.js`）

1. **pick 回报完整信息**（不再只回已登记组件），覆盖 three / svg / dom / image：
   ```json
   { "type":"mc:pick", "componentId":"nh-trade-winds", "partKey":null,
     "instanceKey":"belt:nh-trade/flow:top/3", "instanceId":3,
     "objectName":"mccell-...", "worldPoint":{...},
     "chain":[{"name":"...","mcId":"...","kind":"cell"}], "unknown":false }
   ```
   - **three**：读 `hit.instanceId`，按 `userData.mcInstances` 映射到 `instanceKey`；
   - **svg**：按 `data-mc-id` / 元素 id 映射；路径端点仍可导出；
   - **dom**（仅 svg/dom 路线里的**几何元素**）：按 `data-mc-id`/稳定 id 映射；**不为文字标签与二维控件提供点选**；
   - **image**：命中已登记区域 id；
   - 未登记命中：`unknown:true` + `chain`，面板据此提供“登记为组件/部件/实例”。
2. **子单元与实例取证**：`mc:collect` 增加 `includeParts/includeInstances`；响应
   `components[id].parts{key: {worldPosition, visible, text?}}`、`.instances[] = {instanceKey, instanceId, worldPosition, worldDirection, visible}`。
3. **命中循环与 hover**：`mc:pick-mode {hover:true}` 返回 `mc:hover`；点击后多命中时面板可请求 `mc:pick-options`（前 N 个唯一 `组件/部件/实例` + kind）供选择。
4. **THREE 注入**：`window.__MC_PREVIEW__ = { scene, camera, renderer, THREE }`（或 `raycasterFactory`）；没有 `THREE` 时射线不可用，必须如实降级。
5. **遮挡**：HTML 标签层设置 `pointer-events:none`，避免点画布时被标签吞掉；标签/控件本身不参与点选。

### A4. 注册表 v2（`components.json`，向后兼容）

```jsonc
{
  "id": "nh-trade-winds",
  "label": "北半球东北信风箭头",
  "kind": "belt",                         // structure/region/cell/belt/arrow/image-region
  "route": "three",
  "pick": "mcbelt-nh-trade",              // 对象名 / CSS 选择器 / SVG id / 区域 id
  "locator": { "file": "模型源码/src/main.js", "symbol": "beltBand", "line": 190 },
  "observables": [ ... ],
  "annotatable": true,
  "parts": [                              // 可选：组件内“有名字的不同部件”
    { "key": "ring-north", "label": "北边界线",
      "selector": { "type": "part", "value": "ring-north" },
      "locator": { "file": "模型源码/src/main.js", "symbol": "beltBand", "line": 197 } }
  ],
  "instances": [                          // 可选：同类重复部件（箭头/纬线圈）
    { "key": "belt:nh-trade/flow:top/3", "label": "东北信风箭头 #3",
      "instanceSelector": { "type": "instanceId", "value": 3 },
      "locator": { "file": "模型源码/src/data.js", "symbol": "WINDS", "line": 38 },
      "fingerprint": "sha256:..." }
  ]
}
```
- 旧条目（无 `kind`/`parts`/`instances`）继续有效，`kind` 缺省按 `other`；新条目按需增加。
- **不允许**把每个实例写成顶层组件（会撑爆注册表与界面）；同一带/单元的部件与实例都挂在它下面。


### A5. 证据与规则

- 判据的 `component` 可写 `id`、`id#partKey` 或 `id#instanceKey`：
  - `id`：组件级（现状，保持兼容；带/环流圈/结构体默认走这级）；
  - `id#key`：子单元级（如 `belt-eq-low#ring-north`、`nh-trade-winds#.../3`）；
  - 组件带 `parts`/`instances` 且规则含 `quantifier:"each"`：每个子单元都需满足（汇总进一条判据）；`quantifier:"any"` 用于“至少一个”。
- 证据记录增加 `parts{}`/`instances[]`，每个子单元带自身 measured/assertion/visible；版本键仍按“构建/源码/规则/上下文”，子单元指纹只用于定位“哪个单元变了”。
- 失败报告要能说清：`组件 › 部件/实例` 的实测位置/方向/文案与容差。
- 不同 `kind` 的常用判据：结构体/区域→存在与位置；带→纬度范围/边界位置/可见性；环流圈→闭合与方向；箭头→方向；图像区域→像素坐标。文字标签与二维控件不建立点选单元；若确需验证文案，用 `text` 规则对源码/数据文件判定。

### A6. 界面（`client.js`）

- 点选后显示面包屑与层级：`北半球信风带 › 北边界线`、`低纬环流圈 › 东北信风箭头 #3`、`右侧控制区 › 显示气压带开关`；重叠时列表选择；hover 预高亮。
- 提供**单元树**（按 `kind` 分组：结构 / 环流圈 / 气压带风带 / 箭头 / 图像区域），可折叠到部件/实例；支持“只看可标注单元”。
- 不提供“标签/控件”分组；文字标签与二维控件继续由对话文字指代。
- 未登记命中 → “登记为组件/部件/实例”按钮（写入待整理，agent 补 locator/label）。
- 标注消息包含：组件 id、kind、部件/实例 key 与中文标签、代码位置、截图；批次可混合不同 kind。

### A7. 自检与诚实降级

- 新增**可标注性自检**（按 kind）：
  - 每个声明 `annotatable` 的组件/部件/实例必须能被唯一命中；
  - 指针命中的 `id#key` 与登记一致；
  - 带/环流圈若只登记到组，自检报告“只支持组级”，不得声称支持部件/实例。
- 自检失败时报告具体原因与建议（补名字、补 kind、补实例目录）。
- 文字标签与二维控件不在自检范围内（它们不是点选单元）。
- 合并几何且无实例目录 → 明确 `instanceSupport:false`；仍可标到组或最近的命名祖先。

### A8. 如何避免代码臃肿

1. 身份由生成器产出（一个函数 + 一份目录），不手写；
2. 注册表是“组件 → parts/instances”两级，任何子单元不占顶层；
3. 科学参数仍只写在 `data.js` 一处，子单元只引用；
4. UI 用“按 kind 折叠的树”，虚拟列表；
5. **按需细化**：默认 `structure`/`region`/`cell`/`belt` 级；只有确实“难以文字指代、且需要精确几何”的箭头、边界线才下探到 `parts`/`instances`；装饰元素保持组级。

### A9. 验收

- `structure`/`region`：点地球、点经纬网 → 返回对应组件，不误命中子对象。
- `cell`/`belt`：点气压带 → 默认整带；点边界线 → 可在“整带 / 北边界线”之间选择。
- `arrow`：夹具 `InstancedMesh` 中点击第 3 个 → `instanceKey` 正确；登记后标注消息含 `#3`；`direction` 判据只对 #3 判定；改动 #3 证据失效、其它实例不受影响。
- **明确不点**：文字标签（如“东北信风带”四个字）与右侧“显示/隐藏气压带”按钮不进入点选；用户用文字指代，agent 按文案/选择器定位，工具不得把它们报成可点组件。
- 合并几何夹具：命中返回 `unknown + chain`，面板只能标组，自检如实报告。
- 真实模型（三圈环流尝试）：依次验证 地球 / 气压带（整带+边界线）/ 风带 / 环流圈 / 单支箭头 五类都能得到正确层级；文字标签与控件不出现点选入口；不拆几何、绘制调用不增加。

## 4. 方案 B：接入流程（agent 不用猜）

### B1. `modelcheck_init` 返回“接入就绪清单”

`scan/apply` 返回（默认精简，`verbose:true` 才返回明细）：

```jsonc
{
  "readiness": [
    { "id": "project",        "ok": true,  "detail": "three / dist/index.html" },
    { "id": "hook",           "ok": false, "remedy": "在 模型源码/src/main.js:37 后加 window.__MC_PREVIEW__={scene,camera,renderer,THREE}，并重建" },
    { "id": "verifyEntry",    "ok": false, "remedy": "检测到 tools/verify-build.html；把 config.preview.verifyEntry 指向它" },
    { "id": "deliveryEntry",  "ok": true,  "detail": "三圈环流模型.html" },
    { "id": "pickWiring",     "ok": false, "remedy": "16 个候选中 0 个与场景对象名匹配；建议 pick 用 mccell-*/mcbelt-*（明细见 wiring，按 kind 分类）" },
    { "id": "buildOutputs",   "ok": false, "remedy": "build.outputs 为空；把成品 HTML 列为产物" },
    { "id": "panelEvidence",  "ok": null,  "detail": "运行时判据需在面板「标注」页签取证" },
    { "id": "contract",       "ok": false, "detail": "未建立契约；用 modelcheck_contract action=scaffold" }
  ],
  "nextActions": ["补 hook", "设置 verifyEntry", "修 pick", "起草契约"],
  "wiring": [{ "label": "东北信风带", "suggestedPick": "mcbelt-...", "matched": false }]
}
```

- **原则**：每条“不 ok”都必须带**具体文件/行/命令**，agent 不用读插件源码。
- 候选分 `wired:true/false`：`wired` 表示源码/构建里能找到对应 `name`/`userData.mcId`。

### B2. 校验版入口与交付版入口分开

- 配置新增：
  - `preview.verifyEntry`：取证用（含 `__MC_PREVIEW__` 的校验版，如 `模型源码/tools/verify-build.html`）；
  - `preview.deliveryEntry`：教师交付用成品（剥离验证代码）。
- 预览路由在 `?__VERIFY__=1`（面板取证）时使用 `verifyEntry`；交付检查使用 `deliveryEntry`；两者都缺时回退 `preview.entry`。
- 初始化自动探测常见校验版（`tools/verify-build.html`、`*.verify.html`）并填入 `verifyEntry`，探测不到时在 readiness 里提示。

### B3. `modelcheck_verify` 先预检、再取证

- 预检项：项目/契约存在、`verifyEntry` 可服务、钩子存在（扫描构建产物）、pick 可解析、面板在线（evidence poll 有面板）。
- 任一失败 → 返回 `status:"blocked"` + **一条**最优先补救指令，**不进入 20 秒超时**。
- 新增 `dryRun:true`：只返回每条判据需要的证据类型与来源，不等待。
- 面板不在线时，提示“打开「建模判定」→「标注」页签后重试”，而不是让 agent 反复 loop。

### B4. 给 agent 的一页接入指南

- 新增 `docs/modelcheck/接入指南-给agent.md`（中文、≤150 行）：三条路线怎么接线、`pick` 规则、`verifyEntry`、面板取证、契约编写规则清单、常见错误。
- `modelcheck_init` 与 `modelcheck_verify` 的工具描述直接引用它；**避免 agent 去读 `lib/*.js`**.

### B5. 契约起草建议（减少读文档与手写）

- `modelcheck_contract action=scaffold` 在返回中附带**项目内候选**（不是通用模板）：
  - 从 `mcanchor-*`、`data.js` 常量、构建产物推导：锚点位置 vs 教材口径位置、数据/源码里的文案、成品哈希；
  - agent 只需审核/改写，不需要从零设计规则结构；
- 仍遵守：来源条款、用户确认、不得削弱标准。

### B6. 完成门禁提醒带诊断

- `agent/turn-stopping` 的 steer 文案增加：当前阻塞原因分类（未取证/面板未开/钩子缺失/契约未确认）与**下一步唯一动作**；
- 同一 agent+turn 仍最多 2 次，避免变成刷屏。

### B7. 指标（验收时看）

| 指标 | 现状（实测） | 目标 |
|---|---|---|
| 首次接入到第一条判据通过 | 47.5 min（且最终未通过） | ≤ 15 min |
| 接入阶段工具调用步数 | 48 + 27 | ≤ 20 |
| 读插件源码次数 | 17 | 0–2（只看接入指南） |
| verify 空转（inconclusive 重试） | 3 次 + 2 次门禁提醒（34.5 min） | ≤ 1 次，且首轮给诊断 |
| 点选到实例 | 不支持 | 支持 `组件#实例` |

## 5. 分阶段实施（建议）

| 阶段 | 内容 | 依赖 | 工作量 |
|---|---|---|---|
| **P0（立即，先止血）** | readiness 清单（B1）、`verifyEntry/deliveryEntry`（B2）、verify 预检 + dryRun（B3）、agent 接入指南（B4）、门禁诊断（B6） | 现有 init/verify 代码 | M |
| **P1（实例级最小闭环）** | 身份规范 + 实例目录（A1/A2）、bridge 读 `instanceId` + hit chain + 未登记回报（A3）、注册表 v2（A4）、UI 面包屑/登记（A6） | P0 完成 | M–L |
| **P2（规则与证据）** | `组件#实例` 判据、每实例证据、可标注性自检（A5/A7）、验收夹具 | P1 | M |
| **P3（可选）** | hover、命中列表、拾取代理、批量标注与回归摘要 | P2 | S–M |

先做 P0，因为它在**不改注册表、不拆模型**的前提下就能把接入时间从 47 分钟压到目标区间；P1 只对确实需要“点单个箭头”的项目启用。

---

## 6. 边界与不承诺

- 不改 Blender 一期范围；合并几何且模型不提供实例目录时，**只能标到组**，不猜身份。
- 实例 key 必须由模型**确定性生成**；不能用“点击位置就近匹配”冒充稳定身份（会漂移）。
- 人工验收仍只能由用户点击；agent 不能代替确认。
- P0 不改变现有判据语义与认证规则；P1/P2 的注册表扩展保持向后兼容。
- 性能：保留 `InstancedMesh`，不强制拆分对象；实例目录是元数据，内存/绘制调用基本不变。
