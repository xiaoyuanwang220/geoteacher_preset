# 为什么现在点不到“某一个箭头”——通俗版 + 精确版

> 日期：2026-10-25 ｜ 状态：**分析记录，未改任何代码** ｜ 对象：`16测试/三圈环流尝试`（`mc-00112d88`）
> 用途：把“标注颗粒度不够”讲清楚，避免以后又归结为“网页就是不如 Blender”。

## 一句话

**网页（Three.js）完全能点到单个箭头；现在点不到，是因为模型为了性能把箭头打包成了“一整盒”，而插件只认“有胸牌的对象”。** 再叠加当前构建没把场景交给插件，所以连“盒子上贴的标签”都还没接上。

## 通俗版：用“老师点名”打比方

1. **模型里的箭头是一盒贴纸，不是一排学生。**
   你的模型用 `InstancedMesh` 一次性画很多箭头：一盒里有几十张，每张都知道自己是第几张（`instanceId`），
   但场景里只有“这一盒”这个对象，没有“第 3 张”这个对象。老师只能指着盒子，不能指着第 3 张。
   流管更彻底：很多根被熔成一块塑料（`mergeGeometries`），连“第几根”都不存在了。

2. **插件的点名册只认胸牌。**
   插件按“对象名 / `userData.mcId`”去找已登记的组件；名字对不上就“查无此人”，
   而且**没有“先把人点出来、再补登记”的流程**——于是点了像没反应。

3. **摄像头还没接上。**
   Three.js 路线要求页面把 `window.__MC_PREVIEW__ = { scene, camera, renderer }` 交给插件；
   当前构建产物里没有这个钩子，而且射线检测还需要 `THREE`（或射线工具），
   所以插件“看不见场景”，只能退化成猜位置——几乎必然点不中。

## 为什么这不是“网页不如 Blender”

- Blender 的“精细”来自：建模时**每个箭头就是一个独立对象**。
  一旦把这些箭头合并（Join）成一个 mesh，Blender 的 Object 模式同样点不到单个箭头，只能进编辑模式按面选。
- Three.js 也能“每个箭头一个对象 + 稳定名字”，这是常规做法；
  你现在用的是“实例化 + 合并几何”，本意是省性能，代价是**丢掉了单个箭头的身份**。
- 所以差别在**建模时怎么设计身份**、**插件协议认不认实例身份**，不在网页平台本身。

## 要做到“点某个具体箭头”，需要三件事

| 层面 | 要做什么 | 代价/取舍 |
|---|---|---|
| 模型 | 要么每个可标注箭头独立建对象（名字如 `mc:arrow:<带>:<流>:<序号>`）；要么保留实例化但维护“第几张 → 逻辑 id”的映射 | 独立建对象更直观，但对象/绘制调用变多；保留实例化省性能，但要多写映射 |
| 插件桥接 | 点中时把“命中的是哪一张（instanceId）、世界坐标、父级链”报给面板；未登记也能报，允许“点了再登记” | 需要改 bridge 协议；还要把 `THREE`/射线工具和场景钩子暴露好 |
| 注册表/界面 | 两级：组件（带/环流单元）下面挂实例（箭头 #3）；规则可写 `组件#实例`；界面显示“北半球信风带 › 箭头 #12” | 注册表结构升级；否则几百个箭头会变成几百个顶层组件 |

这三件里，**只有第一件必须改模型；第二、三件是插件侧能力**。可以分阶段：先让“组级点选 + 取证”可用，再做“单个箭头”。

## 你现在这个模型的好基础

- 环流单元组 `mccell-*`、气压带组 `mcbelt-*` 都有稳定名字和 `userData.mcId`；
- 还专门放了不可见锚点 `mcanchor-*` 用于取证；
- 也就是说：**“组级”身份已经做好了**，缺的是“箭头实例级”身份。

## 最小可行路径（建议顺序）

1. 构建产物暴露 `window.__MC_PREVIEW__ = { scene, camera, renderer, THREE }`（或提供射线工具）；
2. 注册表先把组件改成场景名（`mccell-*`/`mcbelt-*`），验证“点一下能选中组、能取证”；
3. 再决定是否为箭头加 `instanceId → 逻辑 id` 映射，实现“点单个箭头”；
4. 界面加“未登记就登记”和“组/实例钻取”，否则仍会点得中但标不准。

## 技术附录（精确版，供实现时对照）

- `模型源码/src/geo.js:285-287`：`makeArrowMesh()` 用 `THREE.InstancedMesh(geo, mat, specs.length)` 画箭头；
  单个箭头的身份只存在于 `instanceId`，不是独立 `Object3D`。
- `模型源码/src/main.js:150-165`：每种流场的所有流管 `mergeGeometries(geos, false)` 合成一个 `Mesh`；
  合并后不存在子对象身份，射线只能命中整块。
- `packages/dsh-modelcheck/assets/bridge.js:1245-1272`：`intersectObjects` 后只取 `hits[i].object`，
  **丢弃 `hit.instanceId`**；`matchComponentForObject`（同文件 1138-1160）只沿父链比对
  `name` / `userData.mcId`，匹配失败返回 `null`，不回报“命中了但未登记”。
- 组件候选来自 `data.js` 的 `name:` 中文标签，而场景对象名是 `mccell-*`/`mcbelt-*`，`pick` 不匹配。
- 取证要求 `window.__MC_PREVIEW__`（bridge 的 `detectThree()`）与 `THREE` 命名空间
  （`getThreeNamespace()`，bridge 173 行）；当前 `三圈环流模型.html` 无该钩子。
- 3D 标签是 HTML 覆盖层（`labelHost`），点在标签文字上时 `isClickInsideCanvas()` 为 false，也会表现为“无反应”。

**结论**：这是“身份粒度 + 取证接线 + 注册/交互协议”的工程问题，不是网页路线的能力上限。

## 补充（2026-10-25）：颗粒度不止箭头

本文件用“箭头”做例子，是因为它是最难的一类；实际需要分层标注的单元至少包括：
结构体（地球/地轴/经纬网）、区域（低中高纬）、环流圈、气压带、风带、单支箭头、几何部件（边界线）、图像叠加区域。
它们的身份来源不同（Object3D 名字 / `parts` / `instances` / 区域 id），不能用同一招硬套。
**文字标签与有名称的二维控件不做点选单元**（文字本身就能指代，点选没有增量价值）；
点选只留给“说不清、容易指代错”的几何。
完整的分类、身份规范、pick 协议与验收见 [解决方案-组件粒度与接入流程.md](解决方案-组件粒度与接入流程.md) §3（A0–A9）。
