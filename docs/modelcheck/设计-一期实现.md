## 0. 一期交付边界

| 阶段 | 本实现 | 说明 |
|---|---|---|
| M0 | ✅ | 能力矩阵 + 实测记录（另见 M0-能力矩阵.md） |
| M1 | ✅ | 契约、运行时取证、闭合/方向/数值/文案/哈希判据、判据自检、完成认证、依赖变化证据失效 |
| M2 | ✅ | 组件注册表、标注点选→请求→投递会话→改后核对→验收闭环 |

### 2.6 rules.js（判据执行核心，不执行任意表达式）

规则是**受限结构化操作**。每条 `execute(rule, ctx)` 返回：

```js
{ status: 'pass'|'fail'|'inconclusive', measured, assertion, detail, coverage, errors? }
```

`ctx` 形：

```js
{
  projectRoot, route,                 // three|svg|dom|image
  files: { read(relPath): Promise<string>, hash(relPath): Promise<string>, exists(relPath): Promise<boolean> },  // 只允许项目内相对路径
  components: Registry,
  evidence: {                         // 运行时证据快照（可能为 null）
    buildHash, sourceHash, adapterVersion, context, components: { [id]: { worldPosition?, worldDirection?, visible?, attributes? } }, errors[], coverage[]
  } | null,
  now: string
}
```

支持的 `rule.kind`（一期）：

| kind | 参数 | 判据含义 |
|---|---|---|
| `numeric` | `observed`（`component:<id>:<prop>` 或 `file:<rel>` 经 `parse` 数值）、`op`（`<= < >= > == !=`）、`value`、`tolerance` | 数值比较；容差内视为相等（对 `==`/`!=`） |
| `closure` | `from`,`to`（组件 id）或 `path`（SVG `pick`）、`tolerance`、`unit`、`inclusive` | **端点距离**：运行时证据给出组件 `endpoints` 时用 `from.end → to.start` 的实际路径端点；没有 `endpoints` 时退回 `worldPosition` 距离；SVG 路径端点偏差同此。≤ 容差（`inclusive` 决定等号）。 |
| `direction` | `component`、`expected`（`{x,y,z}` 或 `azimuthDeg`）、`toleranceDeg`、`source`（默认 world） | 世界方向与该组件方向夹角余弦换算角度 ≤ 容差；组件方向取运行时 `worldDirection`（不能只复述配置） |
| `text` | `file`、`mode`（`equals`/`matches`/`not-matches`）、`value` 或 `pattern` | 文案一致性；正则只允许字面量、长度 ≤ 512、禁回溯构造（仅 `i`/`m` 标志） |
| `hash` | `file`、`sha256` | 文件内容哈希 |
| `svgEndpoint` | `pick`、`from`（`start`/`end`）、`to`（`start`/`end`）、`tolerance` | 同元素/跨元素端点偏差 |
| `bboxOverlap` | `components` [a,b]、`candidateOnly` | **只标记候选相交，不判穿模**：输出 `inconclusive`，附候选信息 |
| `manual` | — | 永远 `inconclusive`，等待用户确认（见 completion） |

**fail-closed**：规则执行抛异常、缺证据、证据上下文与要求不符 → `inconclusive`，绝不 `pass`。

**证据充分性**：`rule.kind` 要求 runtime 而 `ctx.evidence == null` → `inconclusive`（detail 指明缺少运行时取证）；配置检查不得替代运行时几何检查。

### 2.13 依赖与断点续跑

- `depends` 中的文件在每次 `evaluate` 前算哈希；`full !== true` 时只复验「键变化或状态非 pass」的判据。
- 执行中断：`evidence.json` 逐条落盘（每判据一次），重跑时键未变且 pass 的跳过。

解决"已有模型项目里手写 `.modelcheck` 很麻烦"，尤其是**一个会话工作区下多个模型目录**的场景：

```js
discoverCandidates(startDir,{maxDepth}) → { candidates:[{root,relativeRoot,name,title,route,previewEntry,sourcesCount,buildOutputs,componentsCount,modelcheck,hasModelcheck,needsInit,warnings,score}] }
inspectModelcheck(dir) → { dirExists, state:'none'|'empty'|'partial'|'ready', empty, files[], missing[], configValid, componentsValid, componentsCount, contractStatus, issues[] }
scanProject(dir) → { root, projectId, title, route, previewEntry, sources[], buildOutputs[], docs[], components[], modelcheck, warnings[], notes[] }
applyScaffold(root,{force,overrides}) → 写 config.json + components.json（store 原子写；有效文件不覆盖；空目录/坏 JSON 补齐；不写契约）
buildContractDraft(spec,scan) → 轻量 criteria → 合法契约草稿（status='proposed'，source 文档带真实 sha256）
writeContractDraft(store,draft) → 写 contract.proposed.json
```

- **初始化状态按文件内容判断**：只存在 `.modelcheck` 目录不算已初始化。`empty`=目录里没有任何文件；
  `partial`=config.json 或 components.json 缺失/为空/坏 JSON/结构无效（`missing` 列出）；`ready`=两者都有效
  （components 数组可以为空，contract 尚未建立不算 partial）。`applyScaffold` 只写缺失或无效的文件，
  并在 `before/after/notes` 里如实报告（例如“检测到空 .modelcheck 目录，已按初始化处理”）。
- 探测规则：预览入口 `dist/index.html → index.html → src/index.html`，都找不到时回退到根目录唯一的 HTML
  （如 `三圈环流模型.html`）或一级子目录 index.html；路线按入口 HTML 的 `WebGLRenderer/THREE/<svg>/<canvas>/<img>` 判定；
  sources 只收 `src/**` 与根目录网页/JS/CSS；buildOutputs 收 `dist/` 的 html/js/mjs/css；
  components 候选来自 `data-mc-id`、`data-role`、three 对象 `.name=` / `name:`（含中文），并过滤 scene/camera 等通用名。
- 只有 `.blend` 的目录明确提示 Blender 路线一期不支持，不生成可预览项目。
- **不生成判据**：判据只能来自项目科学性/开发文档与用户标注；`buildContractDraft` 只是把 agent 给的轻量列表补默认值并校验。
- 宿主按会话记住选中的项目根（内存 Map）：`setProjectForSession/selectedRootForSession`，
  工具与 API 都优先走该选择，再回退到 cwd 向上查找。

## 3. 宿主半边（index.js + server/）

### 3.1 插件形态

```js
export default {
  name: 'modelcheck',
  inject: ['webServer', 'tools', 'sessions', 'sessionController', 'workingDirectory', 'fs'],
  apply(ctx) { /* 注册路由、工具、事件；disposer 交给 ctx.effect（如可用），否则手动 disposer 收集 */ }
};
```

- 只 import `node:` 内置与包内相对路径；**不 import 宿主包**（用户根无 node_modules）。
- 所有路由/工具注册失败必须 `console.error` + 明确降级，不让整个 profile 挂载失败。

### 3.2 会话 → 项目根

```js
async function projectForSession(ctx, sessionId) {
  const session = ctx.sessions.get(sessionId);              // 不激活 Agent
  const cwd = session?.header?.cwd;
  const agent = sessionId ? (await ctx.sessionController.resolveAgent(sessionId)).agent : undefined;
  const dir = cwd || (agent ? await ctx.workingDirectory.ensure(agent) : undefined);
  return dir ? findProjectRoot(dir, { fs: ctx.fs }) : null;
}
```

工具侧：`exec.agent` 存在时先看**本会话显式选中的项目根**（`modelcheck_init` 初始化后写入的内存绑定），
再回退到 `workingDirectory.ensure(exec.agent)` 的 cwd 向上查找。这样"一个工作区多个模型目录"时，
初始化过的子项目不必把会话 cwd 切进去。
**没有 `.modelcheck/` 时**：工具返回 `{ status: 'inactive', reason: '未发现 .modelcheck 目录' }`（不报错、不干预）；HTTP API 返回 404 `no-project`。
`modelcheck_init` 例外：它的职责就是在已有模型项目里生成 `.modelcheck`。

### 3.3 HTTP API（面板与预览用）

前缀 `/modelcheck`，JSON 请求体上限 1 MiB，响应 `Cache-Control: no-store`。所有 action 需要 `sessionId`；服务端把 `sessionId` 解析成项目根，**不接受客户端传入任意路径**。

| method | path/action | 请求 | 响应 |
|---|---|---|---|
| GET | `/modelcheck/preview/<sessionId>/<relPath...>` | — | 项目内文件；入口 HTML 注入 bridge；`?__VERIFY__=0` 或 config `injectBridge:false` 不注入；路径穿越/非项目文件 → 403/404 |
| GET | `/modelcheck/assets/<name>` | — | bridge.js / icon.svg / 静态图 |
| POST | `/modelcheck/api` `{action:'status'}` | `{sessionId}` | `{status, project:{projectId,title,route,root,previewEntry,unitToPx,viewport}, selection:{root,selected}, contract:{version,confirmed,counts,proposed}, criteria:[…], annotations:{pending}, budget:{…}, certification:{…}, evidenceBuild:{buildHash,sourceHash,adapterVersion}}` |
| POST | `…/api` `{action:'init/scan'}` | `{sessionId, path?}` | `{mode:'project'\|'workspace', target, scan?, candidates?, selected}`（初始化前探测；多模型工作区列候选） |
| POST | `…/api` `{action:'init/apply'}` | `{sessionId, path?, force?, projectId?, title?, route?, previewEntry?, unitToPx?}` | `{ok,root,relativeRoot,selected,written,skipped,nextSteps,scan,config}`；多候选未指定 path → 409 `multiple-candidates`（`error.candidates`） |
| POST | `…/api` `{action:'project/select'}` | `{sessionId, path}` | `{ok,root,selected}`；目标须已有 `.modelcheck` |
| POST | `…/api` `{action:'readiness'}` | `{sessionId}` | `{ok, readiness}`：已初始化项目的接入就绪清单（面板提示条用） |
| POST | `…/api` `{action:'criteria/list'}` | `{sessionId}` | 判据 + 当前证据 + 状态 |
| POST | `…/api` `{action:'components/list'}` | `{sessionId}` | 组件表 + 指纹 |
| POST | `…/api` `{action:'annotations/list'}` | `{sessionId}` | 批次/请求 |
| POST | `…/api` `{action:'annotations/create'}` | `{sessionId, items:[{componentId,userText,screenshot?}]}` | `{batch}` |
| POST | `…/api` `{action:'annotations/send'}` | `{sessionId, batchId}` | `{ok, delivered, idempotent, message}` ← 调 `sessionController.prompt` |
| POST | `…/api` `{action:'annotations/withdraw'}` | `{sessionId, requestId, reason}` | `{ok}` |
| POST | `…/api` `{action:'annotations/accept'}` | `{sessionId, requestId, accepted, reason?}` | 人工验收：写用户确认（`confirmedBy:'user'`，绑定证据版本） |
| POST | `…/api` `{action:'contract/confirm'}` | `{sessionId, contractHash}` | 用户确认 proposed 契约；哈希不符拒绝 |
| POST | `…/api` `{action:'report/latest'}` | `{sessionId}` | 最近报告 |
| POST | `…/api` `{action:'evidence/poll'}` | `{sessionId, waitMs?}` | 待处理取证请求（长轮询） |
| POST | `…/api` `{action:'evidence/submit'}` | `{sessionId, response}` | `{ok, accepted}`；校验 requestId/项目/构建哈希/结构 |

**投递**：`sessionController.prompt({ requestId, sessionId, mode:'queue', content:[{type:'text', text}] })`；成功后批次置 sent；失败返回 `{ok:false, error}` 并保留 draft（可重试，不重复生成请求）。
**用户确认边界**：`contract/confirm`、`annotations/accept` 只由面板（真实用户点击）调用；host 记录 `confirmedBy:'user'` + 时间 + 契约/证据哈希。agent 工具**没有**写这些字段的能力（工具参数不接受确认字段）。

### 3.4 运行时取证队列（M1）

- 判据执行需要 runtime 证据时，`evaluate` 调 `ctxFactory(criteria, requiredContext)`：
  - 找当前项目在线面板（`server/evidence-queue.js` 记录面板在 `evidence/poll` 的会话）；
  - 创建 `requestId`，把 `{requestId, projectId, sessionId, expected:{buildHash, sourceHash}, components, context, props}` 入队；
  - 等待面板 `evidence/submit` 或超时（默认 8000 ms，可由 config.preview.timeoutMs 配置）；
  - 超时 → `null`（判据 `inconclusive`，detail: '未取得运行时取证（面板未打开/超时）'）。
- 面板收到请求 → 通过 `postMessage` 发给预览 iframe → `bridge.js` 采集 → 回传 → 面板 POST `evidence/submit`。
- 证据必须含 `requestId/buildHash/sourceHash/adapterVersion/context/components/coverage/errors/capturedAt`；与请求不符（构建哈希、上下文）即丢弃并记 `inconclusive`。

### 3.5 桥接协议（面板 ↔ bridge.js）

panel → iframe：`{ channel:'modelcheck', type:'mc:hello' | 'mc:collect' | 'mc:pick-mode' | 'mc:reload', request }`
iframe → panel：`{ channel:'modelcheck', type:'mc:ready' | 'mc:evidence' | 'mc:pick' | 'mc:error' }`
校验：`event.source === iframe.contentWindow`、`event.origin === location.origin`（不透明源时接受 `'null'`）、`channel`、字段白名单、单条消息 ≤ 1 MiB、`requestId` 匹配。

**点选只聚焦模型几何**：文字标签、二维控件、页面框架不提供点选（不依赖 DOM pick）。

`mc:pick` 关键字段：`{componentId|null, unknown, kind, partKey, instanceKey, instanceId, objectName, worldPoint, chain:[{name,mcId?,kind?}]}`；未登记也要回报 chain 与世界坐标。

`bridge.js`（注入模型页，普通脚本）职责：
- 等 `window.__MC_PREVIEW__`（含 `THREE`/raycaster）或 DOM ready + 2 帧稳定；
- `three`：遍历命中（含 `InstancedMesh`），读 `hit.instanceId`；按对象/祖先的 `name`、`userData.mcId` 匹配组件，按 `userData.mcInstances` 匹配实例，按 `userData.mcParts`/parts key 匹配部件；导出 `worldPosition`、`worldDirection`（实例矩阵 × `mcAxis`/`axis`，缺省 +Z 并记录 error）、`visible`；
- `svg`/`dom`（仅几何元素）/`image`：按 `data-mc-id`/区域 id 命中，导出端点/bbox/像素坐标；
- 取证 `mc:collect` 支持 `includeParts/includeInstances`，输出 `components[id].parts{key:{worldPosition,visible}}`、`.instances[]`；
- 未登记命中仍高亮并可还原；绝不修改模型数据、不伪造用户确认；截图能力差异如实声明。

### 3.6 工具（模型可见）

统一输出：`output.schema = { type:'object', additionalProperties:true }`，`render(args, value)` 返回 `[{type:'text', text: JSON.stringify(value,null,2)}]`（与项目既有工具一致）。
所有工具：无 `.modelcheck/` → `{status:'inactive'}`；异常 → 结构化错误对象（不抛到模型）。

| 工具 | 参数 | 行为 |
|---|---|---|
| `modelcheck_init` | `{action:'scan'\|'apply', path?, projectId?, title?, route?, previewEntry?, unitToPx?, force?}` | 扫描候选并生成 `.modelcheck/config.json` + `components.json`，绑定到当前会话；返回 readiness（逐项补救）；不生成判据 |
| `modelcheck_status` | `{}` | 项目摘要：契约版本/确认、判据计数、待处理标注、预算剩余、认证状态、下一步建议 |
| `modelcheck_contract` | `{action:'read'\|'propose'\|'scaffold'\|'confirm-info', contract?, criteria?, sourceDocs?, contractVersion?}` | read 返回契约；propose 写完整草稿；scaffold 用轻量 criteria 列表生成草稿；均需用户在面板确认；agent 不能确认 |
| `modelcheck_components` | `{action:'list'\|'upsert', components?}` | 登记组件（id/label/kind/route/pick/locator/observables/parts/instances）；upsert 校验唯一性、pick 冲突、子单元 key |
| `modelcheck_verify` | `{ids?, full?, dryRun?, allowOffline?, timeoutMs?}` | 先接入预检：契约未确认/取证入口/钩子/面板不满足 → `status:"blocked"` + 一条补救；`dryRun` 只列证据要求；正常时增量执行并按 §3.4 取证 |
| `modelcheck_annotations` | `{action:'list'\|'get'\|'triage'\|'close', requestId?, claim?, criteriaIds?, acceptance?, level?, allowedChanges?}` | 读待处理标注；triage 生成判据草案并挂到请求（不改契约版本，需用户确认）；close 需关联判据全 pass 或用户撤回 |
| `modelcheck_complete` | `{}` | 完成门禁：不达标返回阻塞项与可执行补救指令；达标签发认证 + 一页式报告 |
| `modelcheck_round` | `{phase, target, metricBefore, metricAfter, strategy, progressNote?}` | 记录轮次并返回 `budget.verdict`（continue/remind/forbid-strategy/stop + 恢复梯子文案） |

工具描述要求：写清"何时调用、返回什么、失败怎么办"，并声明"modelcheck 验证结果不能由模型自证"。

### 3.7 完成门禁拦截（M0 已验证，按结论实现）

- `agent/turn-stopping`（serial）监听：项目活跃、契约已确认、且本回合结束时未认证 → 调用
  `sessionController.prompt({ requestId, sessionId, mode:'steer', content:[{type:'text',text:提醒}] })`
  把「未认证 + 阻塞项 + 下一步」插回 `next-step` 队列，让 agent 继续处理（依据 M0 能力矩阵 §1/§3.2：
  循环在 turn-stopping 后重新检查队列）。
- **自限**：同一 `agent.id + turn` 最多干预 2 次；`signal.aborted`（用户停止）时不续跑；监听器绝不抛异常。
- 无论是否续跑，都写 `reports/<ISO>-uncertified-turn.json` 记录 `steered`、阻塞项与说明。
- **不承诺**：阻止用户停止、阻止会话关闭、在空闲后的新回合强行续跑；认证只表示"当前产物满足契约"，不代表会话不能结束。

## 4. 客户端半边（client.js）

- `window.__ModuleLoader__.load({ id:'@geo-edu/dsh-modelcheck', factory })`；factory 返回 cordis 插件（与现有 geo-teacher-ui 同形）。
- 注入口：`conversation.view`，`{ id:'modelcheck-panel', order: 90, label: () => '建模判定' }`（label 用本地化函数，中文）。
- 仅在 `props.sessionId` 存在时渲染内容；面板顶部显示项目名/契约版本/认证状态；无项目时显示"当前项目未初始化 .modelcheck"并提供初始化入口。
- Tabs：**判定**（判据表：level/blocking/状态/实测/证据位置；状态色用主题令牌）、**标注**（预览 iframe + 标注模式 + 几何单元树 + 待发送列表 + 发送按钮）、**请求**（请求状态机、人工验收通过/不通过 + 原因）、**报告**（最近一页式报告）。
- 标注**只聚焦模型几何**：结构体/环流圈/气压带风带/边界线/箭头/图像区域；文字标签与二维控件不做点选。点选显示 `组件 › 部件/实例` 面包屑与 `组件id#key`；未登记命中给命中链与“让 agent 登记”提示，不自动写盘。
- 已初始化态显示**接入就绪**提示条（`readiness` block/warn + remedy）；verify 返回 `blocked` 时展示原因/补救，不重试。
- 预览：`<iframe src="/modelcheck/preview/<sessionId>/<config.preview.verifyEntry || config.preview.entry>?__VERIFY__=1&v=<Date.now()>">`；`postMessage` 严格校验来源/结构；只声明收到的数据。
- 发送：`annotations/create` 后 `annotations/send`；按钮在发送中禁用；失败显示原因并可重试（幂等）。
- 改后闭环：`status` 轮询（5 s，页面隐藏时暂停）→ 若 `model.buildHash` 变化则 iframe reload；对比组件指纹显示"已变/未变"。
- 样式：手写 `<style>`，类名 `mc-` 前缀，只用 `--dsw-alias-*` 主题令牌；不 require 其它 Harness 客户端包；不写全局。
- 面板不得出现在教师交付物中（规格 §8.6）：预览/标注只在面板内，模型页仅注入 bridge（`__VERIFY__` 关闭时不注入；见 §5）。

## 5. 交付版剥离

- `preview.deliveryEntry` 是交付成品，`preview.verifyEntry` 是含 `__MC_PREVIEW__` 的校验版；面板取证只加载 verifyEntry。
- `preview.entry` 兼容保留（缺省等于交付入口）；bridge 注入仍受 `?__VERIFY__=1` 与 `injectBridge` 控制。
- 文档与 README 写明：交付物中不得包含 `.modelcheck/`、标注层、验证入口；`modelcheck_status` 对 `route:'image'` 的底图未登记区域返回 `inconclusive`。

## 6. 测试与验收

单测（`node --test packages/dsh-modelcheck/test/*.test.mjs`）：
1. contract：默认值、非法契约、内容哈希稳定、变更检测（删判据/放宽阈值/降级 → weakened）。
2. rules：闭合边界（0.03 容差 in/out）、方向（world 与 expected 夹角；配置正确但运行时旋转 → fail）、文案、哈希、bbox 只返回候选、缺证据 → inconclusive。
3. evidence：键一致复用、依赖变 → stale、规则变 → stale、版本变 → stale。
4. selfcheck：正确样本 pass/缺陷 fail/边界；坏规则不启用。
5. completion：P1 阻塞失败 → 不认证；P0 全过 + P1 失败 → 不认证；非阻塞 fail → 可认证且进报告；空契约/缺证据/旧构建 → 不认证；认证后契约变 → 失效。
6. annotations：幂等发送、状态机、撤回、关联判据关闭。
7. budget：连续 3 轮无改善 + 同策略 → forbid/stop；指标改善 → continue；wait 不计。

固定夹具项目：`packages/dsh-modelcheck/fixtures/project/`（含 `.modelcheck/`、`index.html`、`src/config.js`、一个 0.03 闭合缝的 SVG/Three 场景），供单测与 M1/M2 验收复用。

端到端验收（安装后在真实桌面执行）：
- `/modelcheck/api` status 可用；工具出现在工具表；
- `conversation.view` 出现「建模判定」；
- 夹具项目：`modelcheck_verify` 复现 0.03 闭合缝 `fail`；修好后 `pass`；配置正确但运行时旋转 → 方向 `fail`；
- 标注：面板点选一个组件 → 输入要求 → 发送 → 会话收到含 id/标签/代码位置的批次文本；
- `modelcheck_complete`：阻塞项失败不认证；全过认证并落 `certification.json`；
- 改文件后旧证据 `stale`，重新验证。
