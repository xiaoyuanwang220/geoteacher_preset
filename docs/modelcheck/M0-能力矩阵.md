## 1. 结论摘要（先给能拍板的）

| # | 能力 | 结论 | 一句话 |
|---|---|---|---|
| 1 | 会话面板（`conversation.view`）+ 服务页面（`webServer`） | **可用** | 槽位与路由都在；安装即生效（P/L）；页签切换只能由用户点或视图内部 `openView`，宿主无"服务端切换当前视图"API |
| 2 | 向会话投递消息（`sessionController.prompt`） | **可用** | 宿主插件可直接调该方法；`requestId` 去重，天然幂等；`mode:'queue'` = 下一回合，`'steer'` = 下一步 |
| 3 | 构建与取证（iframe + postMessage） | **受限 / 未端到端验证** | 无 CSP 阻碍同源 iframe；宿主不提供构建服务，源码→新产物绑定须插件自算；预览桥接链路本机未跑过一次完整往返 |
| 4 | **完成拦截**（agent 不调 `complete` 就结束） | **可用（有条件）** | `agent/turn-stopping` 里把消息放进 `next-step` 队列，循环因此**继续走下一步**（源码 + 测试双重证据）；但监听器返回值不能否决，抛异常只会让回合以 error 结束；必须自带干预次数上限 |
| 5 | 写入拦截（`fs/write-intent`） | **受限：覆盖率不足** | 该事件只由 `write`/`edit`/`str-replace-editor` 三个工具派发；`pwsh`/`bash`/其它 MCP 工具写盘**不经过它**。可用的替代强制点是 `tools/pre-execute`（工具粒度 deny/ask），但看不到 bash 命令内部的目标文件 |
| 6 | 执行取消 | **可用（协作式）** | `sessionController.cancel` 取消活动回合且默认保留队列；插件自身应发 `agent.cancel({kind:'hook'})`；已派发工具是否真停取决于它是否转发 `exec.signal`（shell 执行器源码会杀进程，本机未实测） |
| 7 | 授权与确认存储（区分真实用户点击 / 模型页面写入） | **受限** | 传输层只能证明"这是持有浏览器会话凭据的页面"，不能证明"是人在点"；同源 iframe 能读父页面、能带 cookie；`sandbox="allow-scripts"`（opaque origin）才隔离，但那样它也拿不到凭据 |
| 8 | 恢复与隔离（多会话 / 多项目 / 重启） | **可用（插件需自律）** | 宿主按 `sessionId` 恢复 Agent、`workingDirectory` 给出项目根；`webServer` 路由是**全局无会话的**，必须由插件用 `sessions`/`workingDirectory` 校验，绝不能信任客户端传来的路径 |
| 9 |（横切）客户端半边调用自己的宿主半边 | **`host.call` 不可用（对手写 bundle）** | `host.call` 只属于"动态包浏览器半"（模型运行时写插件）；静态 bundle 的 factory 只拿到 `require`，且种子表只有 11 个模块 → 回退为同源 `fetch` 到本插件路由 |

### 3.2 源码事实（固定 tag，本条只摘关键结论）

1. **完成拦截的真实机制**是"往 `next-step` 队列里塞消息"，不是"监听器返回 false"。循环在 `turn-stopping` 之后**重新检查**队列长度（`agent-loop/src/agent.ts#L361-L366`），所以 steer 有效、返回值无效。
2. **`agent/pre-step` 的 `reject` 只会结束回合**（`turnEnds={kind:'blocked'}`），不要用它做"拦截结束"；它适合做"拒绝进入某个非法步骤"。要"注入提醒"应在 `turn-stopping` 里 steer，或在 `pre-step` 的 `enter.messages` 里追加。
3. **写入拦截是工具自派的**，`fs` 服务实现不派发 `fs/write-intent`；因此覆盖率 = 那几个工具，不等于"所有渠道"。
4. **`/api` 的鉴权不覆盖自定义路由**；自定义路由要鉴权必须自己调 `ctx.connection.admit`。
5. **同源 iframe 没有 CSP 阻碍**（主应用无 CSP 头），代价是它拥有同源权限。
