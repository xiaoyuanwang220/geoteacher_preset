# 硅基流动视觉接入方案（Qwen3-VL + UI 开关）

> 版本：v1.0　日期：2026-08-17　状态：方案稿，待评审
> 配套：`视觉与工作流修复方案.md`、`会话复盘-20260817.md`、`讲题图像转录方案.md`

## 一、目标

接入**硅基流动 SiliconFlow** 的 **Qwen3-VL-8B-Instruct** 模型（Apache-2.0），替换当前 opencode-go 路由（503 不可用），并支持 UI 运行时开关。

- **模型**：`Qwen/Qwen3-VL-8B-Instruct`（8B，视觉输入，中文 OCR/图表理解强）
- **API**：SiliconFlow OpenAI 兼容端点 `https://api.siliconflow.cn/v1`
- **接入路径**：复用 DSH harness 的 llm 服务（provider 路由方式），**零自建 HTTP**，现有视觉修复（规范 Message + attachment 引用 + 能力校验 + 降级）全部直接生效
- **UI 开关**：面板可运行时启用/禁用图像转录，不需重启

## 二、前置准备

### 用户操作

1. 注册 [SiliconFlow](https://siliconflow.cn) 账号（新用户送额度）
2. 获取 API Key（控制台 → API Keys）
3. 配置到 DSH 凭证服务（二选一）：
   - **方式 A（推荐）**：在 Web 设置页 Models 里添加，或通过环境变量 `set SILICONFLOW_API_KEY=sk-xxx`
   - **方式 B**：在 DSH credentials.yaml 里手写（需重启后生效）

### 定价参考（以 SiliconFlow 官网为准）

- Qwen3-VL-8B-Instruct：约几元/百万 token 量级（极便宜），具体以 [SiliconFlow 模型页](https://www.siliconflow.com/zh/models/qwen3-vl-8b-instruct) 为准
- 评测/对比可备选 `Qwen/Qwen2.5-VL-7B-Instruct`（更便宜）或 `Qwen/Qwen2.5-VL-32B-Instruct`（更强）

## 三、改动清单

### C1: settings.yaml — 新增 siliconflow provider 路由

在 `llm-pi-ai.providers` 下新增：

```yaml
# 硅基流动（视觉专用，供图像转录 geoVision 服务）
siliconflow:
  apiKeyEnv: SILICONFLOW_API_KEY
  baseURL: https://api.siliconflow.cn/v1
  api: openai-completions
  displayName: SiliconFlow
  models:
    - id: Qwen/Qwen3-VL-8B-Instruct
      name: Qwen3-VL-8B
      input: [text, image]
```

> 注：此路由仅供 vision 插件使用，不影响主 agent（主 agent 仍走 opencode-go/deepseek-v4-flash）。

### C2: agent.cordis.yml — geo-vision 指向新 provider

```yaml
    - id: geo-vision
      name: './plugins/vision/index.js'
      config:
        enabled: true            # 运行时可通过 UI 开关切换
        provider: siliconflow
        model: Qwen/Qwen3-VL-8B-Instruct
        cacheDir: 'E:/geo_edu_agent/outputs/visionCache'
        workspaceRoot: 'E:/geo_edu_agent'
```

### C3: vision plugin — 动态开关 + UI 路由

改动点：
1. `ENABLED` 改为**可变字段**（apply 时用配置初始化，运行时可由 UI 修改）
2. `api.enabled` 从常量改为 getter，始终返回当前值（`geo_solve` 的 `if (geoVision && geoVision.enabled)` 直接生效，analysis 无需改）
3. 新增两个 HTTP 路由（通过 `ctx.webServer.register`）：
   - `GET /geo/vision/status` → 返回 `{enabled, provider, model, visionOk}`
   - `POST /geo/vision/toggle?enabled=1|0` → 切换并返回新状态（内存；可选持久化到 `outputs/visionConfig.json`）
4. 注入增加 `webServer`（与 analysis/bank 一致，host 服务，无需 isolate）

### C4: page.html — 面板加开关控件

在 `/geo-teacher` 面板适当位置加"图像转录"toggle（checkbox + fetch 调 /geo/vision/status|toggle），约 15–20 行 JS。

## 四、与现有修复的关系

- 方案 A 的**全部修复保留**（模型选择逻辑、规范 Message + attachment 引用、chunk 消费、`visionOk` 降级）——换的只是 `provider/model` 配置指向，代码不改
- 适配器 `openai-completions` 已处理 `ImageBlock (attachment)` → base64 data URL 的格式转换，无需关心各家差异
- `resolveVisionModel` 的能力校验（`inputModalities` 含 image）会验证新模型是否图像支持——若 SiliconFlow 目录正确声明（应是），即通过

## 五、验证步骤

1. 用户配置好 `SILICONFLOW_API_KEY` 环境变量（或 credentials）
2. 改 `settings.yaml` + `agent.cordis.yml`（C1/C2）
3. 重启 DSH
4. 新会话调 `geo_extract_images` 或 `geo_solve`（皖 G17）→ 检查：
   - `vision-runs.jsonl` 出现 `provider:"siliconflow", model:"Qwen/Qwen3-VL-8B-Instruct"` + `status:"success"` + `schemaOk:true`
   - `vision.markdown` 非空，含 observed/uncertain 条目
   - 无 `503` / `UNSUPPORTED_CONTENT` / `json_parse`
5. 再次调用命中缓存（`cacheHit:true`）
6. UI 开关：面板 toggle 关闭 → 解题不再带图 → 打开 → 恢复带图

## 六、风险与对策

| 风险 | 对策 |
| :-- | :-- |
| SiliconFlow 对 Qwen3-VL-8B 上图的精度不够（密集中文图表） | 与阿里云百炼 qwen-vl-max 做基准对比；必要时升级到 `Qwen/Qwen2.5-VL-32B-Instruct`（更强、稍贵） |
| API 限流（新用户额度用完或并发限制） | DSH 已有重试机制（可重试码重试 1 次）；正式用建议充值或切 Qwen2.5-VL-7B（更便宜） |
| 模型 id 变更（SiliconFlow 更新） | 统一在 settings.yaml 管理，一处改全局生效 |
| UI 开关重启后丢失状态 | 可选持久化到 `outputs/visionConfig.json`（本方案暂不实现，优先内存） |
| OPENAI 适配器对 SiliconFlow 响应格式兼容性 | SiliconFlow 严格 OpenAI 兼容，已广泛验证；如有问题可在 settings 加 `compat` 字段调适 |

## 七、决策点

| # | 决策 | 选项 |
| :-- | :-- | :-- |
| D6 | 主力模型 | **`Qwen/Qwen3-VL-8B-Instruct`（推荐：最新、Apache-2.0）**；或 `Qwen/Qwen2.5-VL-7B-Instruct`（更便宜、质量稍低） |
| D7 | UI 开关持久化 | 本轮暂不实现（内存开关够用）；后续可加 `outputs/visionConfig.json` |
| D8 | 是否保留 opencode-go 回退 | **不保留（推荐，避免路由冲突）**；siliconflow 作为 vision 专用路由，主 agent 仍走 opencode-go |
