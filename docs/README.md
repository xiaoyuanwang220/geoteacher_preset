# 项目文档总索引

本文件是 `docs/` 的唯一导航入口。文档按**受众与生命周期**分为四层，所有进度与待办统一归口到单一事实源，不在多份文档顶部重复抄写开发日志。

| 状态标签 | 含义 |
| :-- | :-- |
| **现行** | 与当前代码和运行契约一致，修改实现时同步更新 |
| **已实施** | 改造已落入源码，契约持续有效；历史演进见 [决策记录](engineering/决策记录.md) 与 Git 历史 |
| **待处理 / 部分实施** | 问题单或试点方案，部分条目已落地、其余按批次推进 |
| **方案** | 尚未实施的设计草案，只代表演进方向与边界，不代表当前已具备该能力 |

## 五、文档维护铁律

1. **单一事实源**：验收状态只改 `engineering/验收待办.md`，历史取舍只追加 `engineering/决策记录.md`；使用指南与模块规范顶部禁止堆砌日期变更流水账。
2. **只删废话，不删契约**：合并或精简文档时严格遵守 `geo-doc-writing` 命题保留原则，所有地理与交付术语以 [术语表](术语表.md) 为准。
3. **不留僵尸归档**：已被现行实现完全取代的过渡文档在提取有效契约并更新全部入站引用后直接删除，历史过程通过 Git 追溯。
