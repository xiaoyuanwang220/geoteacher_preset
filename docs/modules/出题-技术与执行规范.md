## 1. 架构边界与三层渐进式披露

### 1.1 采用与不采用
- **采用**：目录包技能 `.agent-presets/geo-teacher/skills/geo-question-generator/` 作为编排入口；复用 `geo_taxonomy`、`geo_style_profile`、`geo_search_questions`、`geo_question_detail`、`geo_analyze` 工具；以任务目录 `package.json`（`schemaVersion: 2`）为唯一编辑源；由预设内置的单一 Node 模块完成 JSON Schema 校验、跨字段不变式检查、学生/教师双投影与六章节 Markdown 渲染。
- **不采用**：不自建外部数据库或独立工作流引擎；不把考点库 YAML 复制进技能目录；不自动写回考点库或真题库；不维护第二套 Python 命题包校验器（Python 仅留给后续经批准的科研制图）。

### 1.2 技能三层披露原则
| 层级 | 载体 | 职责与预算约束 |
| :-- | :-- | :-- |
| **发现层** | `SKILL.md` frontmatter | `description ≤ 500` 字符（防宿主静默截断），写清触发范围与边界 |
| **路由层** | `SKILL.md` 正文 | 保持精简（硬上限 `≤ 8192` 码点，工作流软上限 `5000`），只放模式、两阶段确认门、读写边界、校验工具调用与 `references/` 路由 |
| **执行层** | `references/{workflow,evidence-policy,item-writing,delivery-format}.md` | 按阶段按需读取（阶段 1 构思不预读交付格式；无地图任务不读地图细则） |

## 2. 数据源所有权与证据渠道实测边界

### 2.1 本地与外部数据源权限
| 数据源 | 渠道 / 位置 | 权限 | 关键约束 |
| :-- | :-- | :-- | :-- |
| 考点树（KPS） | `geo_taxonomy`（读取 `knowledgeBasePath` 或默认 `data/config/`） | 只读 | 当前源为 `v0.2-draft`，必须记录文件版本与指纹，不得宣称“官方正式定稿” |
| 真题与风格档案 | `geo_search_questions` / `geo_style_profile` | 只读 | 严禁主会话用 `read`/`glob` 直读题库 Markdown（防破坏讲题答案隔离纪律） |
| 课标与教材依据 | 本地可读课标/教材文本或教师提供资料 | 只读 | 不可读时标“待核验”，严禁凭记忆用引号伪造课标原文 |
| 命题任务输出 | `<出题输出根>/<taskId>/` | 可写 | 工作产物严禁写入技能源目录或 `node_modules` |

### 2.2 联网与文献渠道实测边界（源自实测契约，支撑 `evidence-policy.md`）
1. **`web_search` 仅达线索级（`lead_only`）**：返回 URL 列表，不含可直接引用的权威正文；搜索排名不代表权威性，不能直接充当 G2 证据通过依据。
2. **`web_fetch` 三条硬规则**（预设 `tool-web` 已设 `fetch: true`）：
   - **HTTP 2xx ≠ 已读到正文**：遇到 200/202 空响应体必须记为未读到（`pending`），严禁标 `full_text`；
   - **二进制 PDF 端点返回空文本**：随附环境未内置 PDF 文本抽取通道，在线 PDF 链接与本地未解析 PDF 均**不得**记为 `full_text`，亦不得据其声称已核对具体数值、方法或原图；
   - **跨域重定向（https → http）不自动跟随**：须改用目标 URL 重试，仍失败则按降级处理。
3. **学术文献检索边界**：Google Scholar 对自动化请求强拦截不可用；中文库（CNKI/万方/维普）无公开免登录全文通道；结构化元数据与摘要优先走 OpenAlex / Crossref（可达 `metadata` + `abstract`）。在专用文献工具接入前，**教师直接粘贴文本或上传论文配图（经 `read_image` 理解后教学化改绘）是正式支持的输入路径**；仅读到摘要时 `accessScope` 只能填 `abstract`。

## 3. 命题包数据契约与确认失效规则（对应原执行方案 §6）

### 3.1 唯一编辑源与最小目录结构（`schemaVersion: 2`）
任务目录位于 `<出题输出根>/<taskId>/`（注意：此处的 `package.json` 是命题任务数据包，不是 npm 包）：

```text
outputs/出题/<taskId>/
├── package.json          # 唯一编辑源（schemaVersion: 2，顶层声明 questionType）
├── draft.md              # 派生产物：六章节教师交付稿（带版本标识，禁止手写分叉）
├── student.json          # 派生产物：学生投影（白名单构造，绝对不含答案侧字段）
├── teacher.json          # 派生产物：教师投影（含答案/采分点、解析、错因与设计说明）
├── validation.json       # 派生产物：绑定 packageRevision 的结构校验与门禁状态报告
└── visuals/              # 已批准图表的本地附件目录（V1 不自动正式制图）
```

字段权威定义见 `.agent-presets/geo-teacher/plugins/question/package.schema.json`，双题型正例与 `schemaVersion: 1 → 2` 迁移规则见 [命题包样例说明](../examples/README.md)。

### 3.2 确认记录与版本失效不变式（§6.2）
- **`taskId` 贯穿全程**：阶段 0 建立后在同一任务内保持不变；只有更换 `questionType` 或教师明确要求重开新题时才新建 `taskId`。
- **确认绑定 `revision`**：教师对构思（`selectedConcept`）或图表提案（`visuals[]`）的批准必须记录原话与目标 `revision`，仅存布尔值无效。
- **变更自动失效**：
  - 测量目标、核心情境或关键证据变更 → 构思确认失效；
  - 题面、答案、关键来源变更 → 关联的 `reviews[]` 评审记录失效；
  - 综合题小问分值或采分点变更 → 该小问评分标准、答案边界评审及引用该 `pointId` 的学生模拟结论同步失效。

### 3.3 与讲题模块的衔接边界
学生投影（`student.json`）在综合题下必须显式剔除 `answerKey`、`rubric`、`answerBoundary`、`misconceptionPatterns`，且题面、文件名与图注不得夹带答案暗示。两类投影共享题组与设问 ID 并绑定同一 `sourceRevision`，为后续只读接入讲题流水线预留干净接口（当前版本不把题包 ID 直接混充题库 `qid`）。

## 4. 质量门（G0–G6）与单一 Node 校验实现（对应原执行方案 §7）

### 4.1 七道质量门：结构检查 vs 语义核验分离

| 门禁 | 代码可确定性检查（`structural`） | 必须人工或独立核验项（`semantic`，校验器恒置 `pending`） |
| :-- | :-- | :-- |
| **G0 输入** | 必填字段、模式枚举、`taskId` 格式 | 学情转译与测量目标是否合理 |
| **G1 知识边界** | 考点 ID 存在、源版本记录、`needsReviewNodeIds` 一致性 | 答案前提是否属高中共同知识、近似考点映射是否恰当 |
| **G2 证据** | `sourceId` 引用可解析、日期与 `accessScope` 合法、本地附件存在 | 来源是否真实支撑题面事实、热点是否非装饰、论文转化是否无失真 |
| **G3 构思确认** | 3 个构思齐全、选定构思与 `confirmations` 版本匹配 | 三构思是否实质不同、是否未经教师确认提前成题 |
| **G4 题组质量** | **选择题**：ABCD 齐全、答案合法、`distractorMap` 完整且不含正确项、`misconceptionId` 可解析。<br>**综合题**：**分值三级求和**（小问采分点之和＝小问 `points`，各问 `points` 之和＝`totalPoints`）、`rubric ≥ 2` 档、`answerBoundary` 正反非空、`hitPointIds`/`missedPointIds` 可解析 | **选择题**：答案唯一、材料充分、无科学歧义。<br>**综合题**（标 `usable` 必审两条）：① 采分点覆盖参考答案全部推理且不重计；② 答案边界在常见答卷上可判定、未靠 `notes` 兜底 |
| **G5 图表** | 每张图状态、批准 `revision`、`linkedItems`（小题或小问 ID）可解析 | 图表必要性、图文一致、地图审图合规与印刷可读性 |
| **G6 交付说明** | 六章节字段齐备、三档模拟结构完整、难度第四维按题型匹配（选择 `distractorDiscrimination` / 综合 `scoringDiscrimination`）、无伪统计字样 | 四翼与难度依据是否成立、模拟路径是否贴合认知障碍 |

> **完成度硬约束**：只要语义项存在 `pending`，校验器输出的 `effectiveReadiness` 上限锁定为 `draft_complete`（构思阶段无 `questionSet` 时为 `concepts_pending`），绝不因结构零错误而反向激励模型把完成度升格为 `usable`。

### 4.2 单一实现模块归属（§7.2 / §8.2）
1. `.agent-presets/geo-teacher/plugins/question/package.js`：唯一核心实现（内置 JSON Schema 2020-12 子集求值 + 跨字段不变式 + 白名单学生投影/全量教师投影 + 六章节渲染 + `toLosslessJson` 无损输出规整）。
2. `.agent-presets/geo-teacher/plugins/question/index.js`：注册模型工具 `geo_question_validate({ taskId, target, render })`（默认只读校验，`render: true` 才写出四个派生产物；`target: "usable"` 时禁止同时 `render`；严格限制在配置的出题输出根内解析 `taskId`，拒绝路径穿越）。
3. `.agent-presets/geo-teacher/skills/geo-question-generator/scripts/check-package.mjs`：命令行薄包装，供开发与脚本批处理调用同一核心实现。
