## 一、功能定位与核心原则

**定位**：对真题库中任一道真题（或题组），一步步教学生读材料、拆设问、建立地理推理链，按不同读者视角产出讲题稿。

1. **题能真正做对是一切的前提**：独立解题（Solver）先行，讲题（Explainer）建立在服务端已归档的核验记录（Judge）之上。
2. **解题与讲题物理分离，杜绝“看答案编理由”**：解题只在零工具的**隔离解题会话**中完成，只输入题面与**题面图片**；**解析图**、标准答案、解析文本与考点角色提示在作答提交前一律不可见。
3. **设问先行，去机械模板**：先拆解对象、行为动词与限定词，带着问题定向读材料；按设问类型组织逻辑（见 §四），只在材料证据支撑的维度展开，禁止机械套“自然原因＋人文原因”。
4. **地理思维显性化（四问论证）**：每个关键推理均须回答知识选择依据、材料使用依据、因果推导依据与排除论证（见 §三）。
5. **分题型讲法与评分视角**：选择题讲排除链与干扰项错因；综合题讲要素维度排查、采分点组织与术语规范。
6. **以题库检索支撑迁移**：同类题比较与变式推荐必须基于本地题库检索结果（`similarQuestions` / `variants`），候选不足时如实说明缺口，禁止凭记忆编造题目或通用套路。

## 二、总体架构与服务端状态机

```text
题库 MD（题面 + 答案/解析 + 题面图片 + 解析图）
        │  prepareSolve：题答分离 + 题面指纹（questionFingerprint）
        ▼
┌─────────────────────────────────────────────────────────────────┐
│ 【1】geo_solve 隔离解题（状态：question_ready → submitted）      │
│   输入：材料 + 题干 + 选项/小问 + 题面图片（无答案、无解析图）    │
│   执行：内部预设 geo-solver-internal spawn 全新零工具子会话      │
│   存档：插件调用 recordIndependentAnswer 保存原文（模型不可改写）│
│   失败：SOLVER_ISOLATION_UNAVAILABLE / SOLVER_RUN_FAILED（不回落）│
└─────────────────────────────────────────────────────────────────┘
        │  独立作答提交后才允许开放参考答案
        ▼
┌─────────────────────────────────────────────────────────────────┐
│ 【2】geo_judge 两阶段核验（服务端门禁）                          │
│   阶段一（无 conclusion）：openReferenceAnswer 开放整组标准答案、 │
│          解析、采分点、覆盖网格与干扰项目标                       │
│   阶段二（带 conclusion）：按小问调用 recordVerification 写入     │
│          conclusions[qid]；题组全部小问归档后状态才升为 verified │
└─────────────────────────────────────────────────────────────────┘
        │  服务端 verified 记录
        ▼
┌─────────────────────────────────────────────────────────────────┐
│ 【3】geo_explain 按对象成稿（只读服务端 verified 记录）          │
│   输入：qid + audience（student 默认 ｜ teacher ｜ setter）      │
│   输出：纯净讲题稿正文（不含流程元话语与内部核验状态汇报）        │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1 状态机与门禁铁律

- **题组级绑定与失效**：每个题组维护一个 run（以题组首题 id 为键），绑定 `questionId + questionFingerprint`（指纹仅由材料、各小问题干/选项、题面图片引用计算，不含答案与解析）。题面一旦变化，旧 run 自动失效（返回 `QUESTION_VERSION_CHANGED`），必须重新独立解题。
- **作答复用与强制重解**：同指纹已有 `submitted`/`verified` 记录时，`geo_solve` 默认直接复用并返回 `reused: true`、`answerOrigin: 'reused'` 与 `answerSessionId`；渲染与回复必须如实声明复用来源，不得伪称“本次重新解题”。用户要求重做时传入 `fresh: true` 强制新建子会话重解。
- **两道硬门禁**：
  1. 作答提交前调用 `geo_judge` → 返回 `SOLVE_NOT_SUBMITTED`；未先开放答案直接归档结论 → 返回 `JUDGE_NOT_OPENED`。
  2. 题组存在任一小问未归档核验结论时调用 `geo_explain` → 返回 `EXPLAIN_NOT_VERIFIED` 并列出 `pendingQuestionIds`；跨题组传参返回 `QUESTION_NOT_IN_GROUP`。
- **持久化与兼容**：运行记录持久化在 `<outputPath>/solve-runs.json`（上限 200 条）。「核验完成（`verified`）」仅证明“先盲做提交 → 后开答案逐问归档”的流程顺序成立，**不担保学科内容绝对正确**。

### 2.2 需求路由与调用收敛

- **「只问怎么做 / 怎么解」**：只调用 `geo_solve`（1 次），返回独立答案与关键依据，不自动进入核验与讲稿。
- **「要求讲题 / 讲解这道题」**：连续执行 `geo_solve`（1 次）→ `geo_judge` 开放答案（1 次）→ `geo_judge` 按小问归档结论（N 次）→ `geo_explain` 成稿，**中途不询问是否继续**（仅在缺关键题面或图片交付不完整时停止说明）。
- **「分析命题设计」**：调用 `geo_analyze`；若需将已核验题组整理为命题人视角讲稿，则使用 `geo_explain(qid, "setter")`。
- **禁止旁路**：主会话严禁自行解题，严禁使用 `read`/`glob`/Shell 直接读取含答案的题库 Markdown 或图片文件。

## 三、教学推理模型：设问先行六步与四问论证

### 3.1 学生版段内序列（设问先行六步）

学生对象与教师对象外层统一采用**「题目定位—审题—破题—反思与迁移」四段式**；以下六步作为段内动作序列融入其中（审题＝①，破题＝②③④⑤，反思与迁移＝⑥），**不得替代四段式作为顶层标题**，涉图题的读图并入步骤②：

| 步骤 | 核心动作 | 地理思维锚点 |
| :--- | :--- | :--- |
| **① 拆设问（先行）** | 识别对象 + 行为动词 + 限定词，判定能力层次与设问类型 | 明确作答逻辑方向，不盲目通读背诵 |
| **② 带着问题读材料** | 按设问指向定向提取文字与图表要素证据，锁定区域与空间尺度 | 区域认知 + 目的性取证；识别无关背景与干扰信息 |
| **③ 知识选择** | 说明题目中哪条线索激活了哪项地理原理或概念 | 知识由材料线索与区域特征触发，而非死记硬背 |
| **④ 推理链** | 材料证据 × 地理原理 × 设问限定 → 逐环推导或逐项排除 | 显性化每一步“前提 → 结论”的因果联系 |
| **⑤ 作答与检查** | 综合题按要素维度排查组织采分点；选择题完成干扰项错因复核 | 地理术语规范、条件限定完整 |
| **⑥ 方法提炼** | 基于题库同类题对照，归纳该类问题的分析路径与适用边界 | 从“解一道题”升维到“解一类题的条件化思路” |

### 3.2 四问论证（推理质量底线）

每个关键推理步骤均须能回答四个问题：
1. **为什么调用这条知识**（触发线索与适用边界）；
2. **为什么依赖这句材料/这张图**（删去后结论是否仍成立）；
3. **上一步为什么能推出下一步**（消除逻辑跳跃）；
4. **为什么不是其他选项或备选要点**（选择题点明绝对化/因果倒置/偷换概念/无中生有等错因；综合题说明备选维度为何缺乏材料支撑）。

## 四、去机械化设问拆解与要素维度排查

### 4.1 八类设问组织框架

| 设问类型 | 答案组织逻辑（依材料证据取舍，不硬凑） | 讲解重点 |
| :--- | :--- | :--- |
| **原因 / 成因** | 直接原因 → 根本条件 → 触发因素 → 加剧因素 | 区分基础背景条件与诱发/放大机制 |
| **影响 / 意义 / 作用** | 分主体（自然/人文、受益/受损）+ 分尺度（直接/间接、短期/长期） | 讲清影响传递链，落到区域发展与人地协调 |
| **形成过程 / 演变** | 按时间阶段与先后环节推进（环节 → 驱动力 → 状态变化） | 动态演化链条，禁止写成静态要素罗列 |
| **比较 / 差异** | 同口径可比指标 + 区域特征限定 | 明确比较基准与差异成因 |
| **评价 / 利弊 / 可行性** | 分主体利弊 + 代价风险 + 成立前提条件 | 辩证分析，结论须带适用前提 |
| **措施 / 对策 / 治理** | 针对具体成因或病症 + 分实施主体 + 可操作性 | 说明每项措施如何解决对应问题 |
| **分布 / 特征描述** | 总体分布（均/不均）+ 极值与极区 + 延伸方向/空间变化 + 数值支撑 | 基于空间方位与数据描述，避免空洞形容词 |
| **变化 / 趋势** | 总体方向 + 阶段转折 + 幅度与速率变化 | 区分现状态势、历史过程与趋势外推 |

### 4.2 综合题采分点：要素维度排查法

- **自然维度池**：位置、地形、气候、水源/水文、土壤、生物/植被（及自然灾害）。
- **人文维度池**：人口/聚落、农业、工业、服务业、交通、市场、政策、技术。
- **执行纪律**：逐一用材料检验“有无证据支撑”——**有证据才纳入，无证据坚决排除**，再按因果逻辑排序形成「要素 + 材料证据 + 结论」采分点。内核 `dimensionScan` 仅标注整组材料的候选维度供参考，不得机械当成单个小问的必答清单。

## 五、讲题三对象规范（`audience`）

`geo_explain` 接收 `audience`：`student`（默认）｜`teacher`｜`setter`。**仅按用户实际诉求选择对象**（不得因为使用者是教师就自动切为 `teacher`）；切换对象而题面未变时直接复用服务端 `verified` 记录。详细文体规范见 `.agent-presets/geo-teacher/skills/references/explainer-audiences.md`。

| 维度 | 学生对象（`student`，四段式） | 教师对象（`teacher`，四段式） | 命题人对象（`setter`，独立七节评价结构） |
| :-- | :-- | :-- | :-- |
| **知识** | 学什么、何时想到、怎样使用与适用条件 | 重点难点成因、前后知识衔接与突破抓手 | 考点承载效度、是否暗中超纲 |
| **解题过程** | 起步切入点、证据连接与自检动作；推理自然引出答案 | **主体篇幅用于启发学生产生、检验与修正想法**（目标→追问→支架撤除） | 材料与设问如何引发认知操作、三层干扰辨析 |
| **方法总结** | 下一次遇到同类设问如何独立起步与调整 | 如何从个例引导学生归纳、防过度概括与独立迁移检测 | 是否真正测到迁移而非套路背诵 |
| **跨学科** | 按四问门槛判定（必要性/入推理链/非地理本位/已学可交代），不适用时不硬写 | 何时引入、如何搭桥及防范概念误读 | 跨学科素材是否服务考查目标、有无未交代门槛 |

- **命题人对象结构**：考查目标 → 情境/材料/设问 → **设问、材料与选项三层干扰辨析（必检）** → 预期认知路径 → 答案成立条件及错误路径 → 迁移与跨学科设计 → 题组和质量评价。无真实试测数据时严禁输出正确率、区分度数值。
- **交付纯净度**：讲题稿只输出成稿正文，不输出“已完成核验/下面是讲稿”等流程套话、内部状态码或推销式追问。无答案练习支架作为学生对象的可选附加物，仅在按需请求时生成。

## 六、技术边界、图片交付与常驻回归门

### 6.1 题答分离与原生图片交付
- **题面图片** = `## 相关图片` 节图片 + 各小问 `**答案**` 标记前的正文图片；**解析图** = `**答案**` / `**解析**` / `## 教学备注` 之后的图片（**永不交付给解题会话**）。
- 题答边界不明（缺 `**答案**` 标记或题面区混入答案痕迹）时，`prepareSolve` 直接返回 `QUESTION_BOUNDARY_UNCERTAIN` 并指出具体题组与小节，严禁猜测切分。
- 题面图片由 `geo_solve` 通过宿主 `attachments.saveImage()` 作为原生多模态块按序交付，不暴露本地磁盘路径；交付状态分 `none` / `complete` / `partial` / `degraded` 四态，凡 `partial` 或 `degraded` 一律返回 `IMAGE_DELIVERY_INCOMPLETE`，不补猜图意。
- 教师在对话中直接上传的图片题目前不走隔离解题状态机，按普通多模态答疑处理，不得冒充已核验讲题流水线产物（独立方案见 [上传试卷讲题方案](../proposals/上传试卷讲题方案.md)）。

### 6.2 内部隔离预设工具锁
- `cordis.patch.yml` 声明内部预设 `geo-solver-internal`（`order: 999`，提示日常勿手动选择），仅挂载 `plugins/solver-isolation`。
- `solver-isolation` 读取 `skills/geo-solver.md` 正文作为 persona，并在 preset 作用域同时启用 `tools.restrict({ deny })`（隐藏全部继承来的宿主全局工具）与 `tools.guard`（执行期兜底拦截），确保子会话零工具可用。

### 6.3 工具契约与 `geo-verify.mjs` 常驻检查
- 三个模型工具（`geo_solve`、`geo_judge`、`geo_explain`）的 `description` 严格控制在 **≤ 350 字符**，只声明用途、参数与前置门禁。
- `scripts/geo-verify.mjs` 持续守护：题答分离与边界错误码、子会话 `startActivation` 隔离调用且无主会话自解回落、三态状态机门禁错误码、移除废弃的 `self_reported_material`/`toJudgeReportJson`、原生图片四态检查与工具描述长度预算。
