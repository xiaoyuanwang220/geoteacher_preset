# 地理教师 Agent 术语表

> **唯一权威来源**：教师技能（出题/解题/讲题/课程方案）、开发技能、面板文案、工具 description、文档一律引用本表，不各自定义。术语以本表为准；遇新术语由开发方在本表追加，不擅自引入。

## 一、考点与知识体系

| 术语 | 定义 | 禁用/易混 |
| :-- | :-- | :-- |
| **考点** | 课标要求的具体知识单元，存于 `knowledge_taxonomy_*.yaml`，格式为 `domain→theme→knowledge_unit` 三级，节点带 `id`（如 `KU-HUM-IND-002`） | 禁用"知识点"（太泛）；禁止与"考点"混用 |
| **考点树（taxonomy）** | 全部考点按领域→主题→知识单元组织的树状结构 | |
| **领域（domain）** | 考点一级分类（如"人文地理""区域发展"），节点 id 以 `DM-` 开头 | 禁用"板块""模块" |
| **主题（theme）** | 考点二级分类（如"产业区位""区际联系"），节点 id 以 `TH-` 开头 | |
| **知识单元（knowledge_unit）** | 考点三级，具体可考知识点，节点 id 以 `KU-` 开头（如 `KU-REG-INTERREGION-003`） | |
| **核心考点** | 一道题的主要考查对象（KM 角色 `core_exam_point`） | |
| **支撑知识** | 一道题的辅助知识点（KM 角色 `supporting_knowledge`） | |

## 二、素养与能力

| 术语 | 定义 | 禁用/易混 |
| :-- | :-- | :-- |
| **核心素养** | 高中地理四大素养：区域认知、综合思维、人地协调观、地理实践力 | 禁用"素养"单独使用（须指明哪一项） |
| **素养立意** | 命题/讲题时说明"这道题主要考查哪个核心素养" | 禁用"能力立意"（已过时） |
| **设问模式** | 题干的提问方式（如"分析原因""比较差异""评价利弊"），由动词+对象+限定词构成 | 禁用"题型"（题型=选择题/综合题，是结构；设问模式是内容） |
| **设问类型** | 按设问动词归类的逻辑框架（原因/影响/过程/比较/评价/措施/分布/趋势），决定答案组织方式 | |
| **能力层次** | 识记/理解/应用/分析/评价，用于评估题目认知难度 | |

## 三、题目结构

| 术语 | 定义 | 禁用/易混 |
| :-- | :-- | :-- |
| **题型** | 题组的结构取值，字段 `questionType`：`single_choice` 材料型选择题组／`comprehensive` 材料型综合题。**一个题包只用一种**，在题包顶层声明一次 | 禁用"题型"指设问方式（设问方式见"设问模式"）；禁用"模式"指题型（"模式"已用于 `mode`＝参赛/专项训练） |
| **题组** | 一道综合题或一组共用材料的选择题，含共用材料 + 若干小问（综合题）或小题（选择题）。题型由 `questionType` 声明 | 禁用"题"笼统指代（须区分题组/小问/小题）；不得在一个题包里混排两种题型 |
| **小问** | **综合题**题组内的一个独立设问，字段 `items[0].subQuestions[]`，id 形如 `Q1-1` | 禁用"第N题"指综合题小问（应说"第N题第1问"或"Q1-1"）；**不用于选择题题组** |
| **小题** | **选择题**题组内的一道独立设问，字段 `questionSet.items[]`（`itemType=single_choice`），id 形如 `Q1` | 禁用"小问"指选择题题组内的题（小问属综合题）；禁用"第N题"笼统指代 |
| **题干** | 一道小问/小题的提问文字（"分析……"） | 禁用"题目"（题目=材料+题干+选项/小问） |
| **材料** | 题组共用的背景文字/图表 | |
| **选项** | 选择题的 A/B/C/D 候选答案 | 禁用"答案选项"（选项≠答案） |
| **干扰项** | 选择题中错误的选项，须有明确错因 | 禁用"错误选项"（太笼统，须说明错因类型） |
| **采分点** | 综合题评分时的要点单元，字段 `subQuestions[].answerKey[]`，id 形如 `KP-1`；每个采分点写要素（`statement`）＋证据链（`evidenceChain`）＋分值（`points`） | 禁用"得分点"（采分点更规范）；只写结论不写证据的采分点不合格；分值须三级自洽（同一小问的采分点分值之和＝该问 `points`，各问 `points` 之和＝`totalPoints`） |
| **评分标准** | 综合题的答案分档描述，字段 `subQuestions[].rubric[]`，至少 2 档；每档写等级、分值区间与达到该档的答案特征 | 禁用"认真分析、条理清晰即可给分"式不可判定的措辞；不得把评分标准写成采分点的同义复述 |
| **开放答案边界** | 综合题说清"什么算对、什么不算对"的字段 `subQuestions[].answerBoundary`：`acceptable`／`unacceptable`／`notes` | 禁用"言之有理即可"；`notes` 只能记待教师裁定的灰区，**不得用 notes 代替边界**；边界不可判定的小问不得随题包标为可使用 |
| **典型错答模式** | 综合题的错因单元，字段 `subQuestions[].misconceptionPatterns[]`：错答样子（`pattern`）＋落在哪个采分点或哪条边界上失分（`howItLosesPoints`） | 综合题**没有干扰项**，不得把干扰项分析套到综合题上；也不得用"粗心""审题失误"当错因 |

## 四、命题与出题

| 术语 | 定义 | 禁用/易混 |
| :-- | :-- | :-- |
| **旧五段式** | 题目／解析／答案／评分标准／考察知识点——**旧出题技能的输出格式** | **不得作为 V1 验收标准**；不得用"五段式"描述 V1 交付（用"六大章节"） |
| **六大章节** | V1 命题稿的固定结构：学生用试题／答案与解析／命题设计说明／典型学生模拟作答／来源与证据／风险与待确认事项 | PRD §6.3 的十二项是**内容要求**，不是十二个顶级章节 |
| **认知障碍** | 由教师模糊学情转译出的、**待验证**的命题假设（题包 `learningHypotheses[]`），表述须含"可能/待验证" | 禁用"诊断结论""学生确实……"（命题假设≠真实诊断） |
| **四翼** | 高考评价体系的考查要求：基础性、综合性、应用性、创新性；回答"怎么考" | 禁用"四个难度等级"；禁止把四翼相加当难度分数；无题面承载的不标 |
| **命题包（题包）** | 出题任务的唯一编辑源 `outputs/出题/<taskId>/package.json`（任务数据，不是 npm 包）；格式版本字段 `schemaVersion` 当前为 **2**——v2 起支持选择题组与综合题两种题型 | 禁用"草稿包"；工作产物不写入技能源目录；`schemaVersion: 1` 的旧题包须按 `docs/examples/README.md` 的迁移说明升级，迁移会递增 `revision` 并使受影响评审失效 |
| **待复核节点** | 本次实际使用、且源中 `needs_review=true` 的考点，记入 `knowledge.needsReviewNodeIds` | 非空时**不得无提示地交付为最终作品**，须在交付稿与 `risks` 中明示；不得把草稿状态的 taxonomy 表述为"正式定稿" |
| **学生投影 / 教师投影** | 由题包生成的两种可读取视图：`student.json` 只含题面，`teacher.json` 含答案、解析、错因映射与设计说明 | 禁用"学生版/教师版"（易与旧技能双视图混淆）；两类投影共享 ID 并绑定同一 revision；**综合题的学生投影须排除 `answerKey`（采分要素、证据链与分值）、`rubric`、`answerBoundary`、`misconceptionPatterns`**，小问分值分布也不得暗示采分点数量 |
| **readiness（完成度）** | 题包完成状态四态：构思待选择 `concepts_pending`／初稿完成 `draft_complete`／可使用 `usable`／待补充 `pending` | 禁用笼统的"已完成"（须指明四态中的哪一态）；**综合题另加两条语义条件**（采分点与分值自洽且覆盖参考答案、答案边界可判定），未评审前不得标 `usable` |
| **命题蓝图** | 对一道真题分析后给出的"下一道题怎么设计"的指导（考点锁定/情境换新/设问设计/选项设计） | |
| **风格档案** | 从真题库现场抽取的七维度风格特征（题组结构/材料/图表/设问/选项/解析/综合题），用于按某省卷风格出题 | |
| **原创性** | 情境、材料、题干、选项、答案全部原创；风格模仿≠抄袭 | |

## 五、讲题流程（solve → judge → explain）

| 术语 | 定义 | 禁用/易混 |
| :-- | :-- | :-- |
| **解题轨迹** | solver（独立解题）产出的"证据-知识-结论"三元组，不含答案/解析 | 禁用"解题过程"（太泛） |
| **核验报告** | judge（核验）产出的得分点覆盖/推理错误/遗漏/干扰项解释分析 | |
| **讲题稿** | explainer（讲题）产出的教学化文档：讲解对象为学生或教师时为「题目定位—审题—破题—反思与迁移」四段式；讲解对象为命题人时为命题分析结构 | 禁用"讲解稿"（讲题稿是基于已验证解题，不是照抄解析） |
| **讲解对象（audience）** | 讲稿服务的读者对象：`student` 学生（默认）／`teacher` 教师／`setter` 命题人；中文写作"学生对象／教师对象／命题人对象" | 禁用"学生版/教师版"指代讲解对象（该说法属题包视图，见"学生投影/教师投影"）；禁用"模式"指代对象 |
| **四维内容** | 讲题的分析维度：知识、解题过程、方法总结、跨学科；融入四段式的段内，不另设顶层目录 | 禁用"四个章节"；与"四问论证"（推理质量检查）不是同一套划分 |
| **学生版教学流程（设问先行六步）** | 学生对象四段式的**段内**动作序列：① 拆设问（先行）→ ② 带着问题读材料 → ③ 知识选择 → ④ 推理链 → ⑤ 作答与检查 → ⑥ 方法提炼；落位为审题＝①、破题＝②③④⑤、反思与迁移＝⑥（外层仍为四段式） | 禁用把六步写成替代四段式的顶层目录；禁用"读图"单列为一步（涉图题并入②）；不得输出"本步自检"第三要素 |
| **跨学科判定（四问）** | 讲题阶段判断是否生成跨学科内容的四问门槛：必要性（删去该学科原理后结论是否仍成立）、参与环节（是否进入推理链，而非只影响读图与表达）、学科归属（是否本属地理课程自身的图表解读能力）、可交代性（是否为学生已学且题面有交代）；任一不通过即记 `not_applicable`，不得生成 | 禁用把跨学科当必填段；禁用把地理自身能力或情境中的跨领域词语包装成跨学科 |
| **三层干扰辨析** | 命题人对象的必检项：设问层、材料（含图表）层、选项层逐层检查干扰 | 禁用"错误选项分析"指代该检查；设问、材料中的相关内容称"干扰信息／干扰机制"，不称"干扰项" |
| **提供材料待核验** | geo_explain 的核验状态：已收到独立答案与核验材料，但会话无解题/核验记录机制可确认核验实际发生 | 禁用"已核验""核验通过"表述该状态 |
| **过程性元话语与作者痕迹** | 讲题稿中需删除的内容：模型自述（"我这样想"）、版本痕迹（"v2 修订"）、评审痕迹、对解析的机械复述 | 禁用"CoT 泄漏"（旧称，易误伤可教学推理） |
| **可教学推理** | 讲题稿中必须保留的推理：审题（设问拆解）、证据（材料引用）、原理（知识选择）、因果链、干扰项排除 | |

## 七、项目术语

| 术语 | 定义 | 禁用/易混 |
| :-- | :-- | :-- |
| **预设包** | 以 `link:` 或包安装形式挂进 profile 的预设 bundle；本机为 `link:E:\geo_edu_agent\.agent-presets\geo-teacher` | 禁用“权威源/运行时副本”（rc.2 已无双副本） |
| **组合文件** | 预设的实际装配来源：`cordis.patch.yml` 的 `@deepseek-ai/dsh-agent-preset` 声明行（`config.id` / `config.plugins`） | 禁用 `agent.cordis.yml`（已退役形态） |
| **技能根** | 预设包内的 `skills\` 目录，由 `createRequire(baseUrl).resolve('<包>/package.json')` 定位 | |
| **包子路径导出** | 本地插件在 `cordis.patch.yml` 中一律写 `@geo-edu/dsh-geo-teacher-preset/plugins/<name>`；相对路径会因 baseUrl 是 profile 目录而 `ERR_MODULE_NOT_FOUND` | 禁用相对插件名 |
| **原生图片交付** | `geo_solve` 将题库图片保存为 DSH 附件并以图片内容块交给当前多模态模型 | 禁用“图像转录”（当前链不做二次文字转录） |
| **isolate 白名单** | geo group 的服务隔离机制：每个 `ctx.provide()` 的服务名必须在 `cordis.patch.yml` 的 isolate 中声明 | 禁用"isolate"（须完整说"isolate 白名单"） |
| **preset generation** | 预设注册器挂载的一代实例；rc.2 会把旧代标为 retired，并在使用者归零后回收 | 禁用“旧代永不 dispose”（0.1.1 时代结论，rc.2 已不成立） |
