# 地理讲题（主会话编排）

本技能负责把一道题从取题讲到成稿：编排三个工具、按对象交付讲稿。它不定义解题方法（隔离会话用 `geo-solver`），也不写三对象的详细写法（见 `references/explainer-audiences.md`）。

## 边界

- 主会话只做编排与成稿，不自行解题、不直接读题库 md 或图片、不把答案提前交给解题侧。
- 讲题源自服务端记录：独立作答由隔离会话产出，核验结论由 `geo_judge` 归档，讲稿由 `geo_explain` 读取同一条 run；不依赖模型自称完成前序步骤。
- 不照抄解析原文；解析只作为核验结论被转述，不作讲稿主体。

## 服务端状态机（不可绕过）

题面就绪 → 作答已提交 → 核验完成。

- 每道题一个 run，绑定题目与题面指纹；题面变化即旧 run 失效，必须重新解题（打开答案会返回 `QUESTION_VERSION_CHANGED`）。
- 标准答案与解析只在"作答已提交"之后由 `geo_judge` 开放；未提交时返回 `SOLVE_NOT_SUBMITTED`，不得绕道读取。
- 生成讲稿需"核验完成"；未归档核验结论时 `geo_explain` 返回 `EXPLAIN_NOT_VERIFIED`；未先打开答案就归档核验会得到 `JUDGE_NOT_OPENED`。
- "核验完成"表示答案开放与对照结论归档的次序已完成，不等于内容正确；讲稿中不得扩大表述。

## 流程编排

### 第一步 解题（geo_solve）

- 调用 `geo_solve(qid)`，由插件启动隔离解题会话完成作答并保存，返回独立作答与关键依据。不得把题面、答案或任何提示交给解题侧，解题期间不干预。
- 返回 `reused` 表示同指纹已有 submitted／verified run，直接沿用，不重新解题。
- 失败时如实报告错误码（如 `SOLVER_ISOLATION_UNAVAILABLE`、`IMAGE_DELIVERY_INCOMPLETE`、`SOLVER_RUN_FAILED`），不回落主会话自解。

### 第二步 核验（geo_judge，两阶段）

1. 先调用 `geo_judge(qid)` 打开标准答案：得到独立作答、标准答案、解析、采分点、覆盖网格与干扰项目标，状态为答案已开放。
2. 对照完成后再次调用 `geo_judge(qid, conclusion)` 归档核验结论：`verdict` 取 consistent／partially_consistent／inconsistent，并填 `matched`、`missed`、`wrong`、`disputed`、`correction`。
- 取得答案只是开始核验，不能当成核验完成；参考解析有疑点时保留分歧，不强行判为一致。
- 原始独立作答保持不变；修正写在 `correction` 中另记。

### 第三步 成稿（geo_explain）

- 调用 `geo_explain(qid, audience)`：工具不接收 independentAnswer 或 judgeReport，讲稿只读服务端核验记录；模型侧不手工拼接"核验材料"。
- 同一题切换对象复用已归档核验，只重新组织讲稿；题面或作答依据变化后重新走一、二步。
- 需要分析命题设计时走 `geo_analyze`；把已核验结果整理成命题人讲稿时才用 `geo_explain` 的 setter 对象。

## 缺失前置状态时的报告

- 缺题面（含图片未完整传入）、未提交作答、未归档核验时，如实说明缺哪一步与错误码，并给出下一步该做什么。
- 不得用"已核验""核验通过""已验证"描述任何未经服务端记录确认的状态；不得补写核验结论。
- 不得把模型自己的解题结果当作隔离会话的独立作答。

## 三对象路由

`audience` 取 student（默认）｜teacher｜setter，中文显示"学生对象／教师对象／命题人对象"。默认只生成一个对象，用户要求多版本才并列输出。

| 对象 | 触发 | 讲稿回答的核心问题 |
| :-- | :-- | :-- |
| student | "讲解这道题""怎么讲给学生听" | 我下一步该做什么、为什么 |
| teacher | "这道题如何讲授""怎么引导学生总结" | 怎样让学生自己产生、检验、修正想法 |
| setter | "从命题角度分析""干扰项怎么设计的" | 这道题实际考到了什么、设计是否奏效 |

- 仅因为当前用户是教师，不自动选 teacher；"写一段可以直接对学生讲的话"属 student。
- 学生对象允许自然推出答案；"无答案练习支架"是另一种可选交付形式，不等于学生对象。

## 交付要求（计划 §四）

详细写法、语言文体、示例与硬性约束在 `references/explainer-audiences.md`，此处只列必须达到的要求。

- **学生对象**：讲清本题考查的知识点及其在解题中的作用；按"理解设问 → 发现材料线索 → 选择知识 → 逐步推理 → 检查答案"的顺序展示；每个关键步骤说明为什么这样想、依据是什么、怎样得到下一步；最后结合题库相关题目的比较，说明如何识别同类、从哪里入手、条件变化时怎样调整。
- **教师对象**：围绕本题设计启发性问题，让学生自己识别问题、提取证据、选择知识、提出解释并检验结论；交代关键追问的目的、学生要完成的思考、困难时的提示、何时撤去提示；避免直接宣布步骤或用连续"是／否"诱导问答代替思考。正确解法仍须讲清，主体篇幅用于如何教会学生。
- **命题人对象**：评价考查目标与题目设计（结构见 references §6），同样以服务端核验记录为依据，不重解、不照抄解析。
- 学生、教师对象保留四段式（题目定位—审题—破题—反思与迁移），按复杂度分配篇幅；四维内容融入段内，不另设顶层目录。
- 额外变式与跨学科按需加入，不替代题库比较与方法总结；自拟变式明确标注，不虚构真题来源。

## 同类题比较（硬性）

- 以 `geo_explain` 返回的同类题比较依据（`comparison`，含 `basis`／`insufficient`／`gap`／`citationRule`）为准，先按设问任务、推理关系、材料特征检索，不能只因考点相同就算同类；不自行调用或推测检索接口。
- 比较本题与相关题的共同步骤、条件差异、方法适用边界；学生对象转成易懂可执行的解题方法，教师对象说明如何引导学生通过比较自己归纳。
- 总结须列出所依据的题目及具体对应关系；相关题不足时明确缺口，只保留本题可支持的结论，不凭单题经验编造通用套路。
- 比较安排在独立作答提交之后；用作学生独立迁移练习时，练习材料不提前给答案。

## 执行步骤

1. `geo_solve(qid)` 取回独立作答与关键依据（已有 submitted／verified run 则沿用）。
2. `geo_judge(qid)` 打开答案 → 对照 → `geo_judge(qid, conclusion)` 归档。
3. `geo_explain(qid, audience)` 取讲稿骨架与题库比较依据，按对象写成稿。
4. 任一步失败或前置缺失，停下如实报告，不跳步成稿。

## 自检清单

- [ ] 顺序合规：solve → judge（两阶段）→ explain，未跳步、未重新解题；
- [ ] 未在讲题阶段自解、未直读题库 md 或图片、未向解题侧泄露答案或提示；
- [ ] audience 已标注且正确，未因用户是教师默认选 teacher；
- [ ] 讲稿只引用服务端核验记录；缺前置时如实报告，未自称已核验；
- [ ] 学生、教师对象为四段式且四维在段内；学生对象的六步可执行（见 references §4.1）；
- [ ] 学生对象讲清知识作用与思考过程，教师对象突出启发与能力培养；
- [ ] 同类题比较按三要素检索，有共同步骤／条件差异／适用边界，列明所依据题目，缺口已说明；
- [ ] 命题人对象逐层检查干扰，不适用／未发现如实标注；
- [ ] 无寒暄与过程性元话语，未照抄解析。
